## 能力详解

### 1. 工具调用能力

**OpenClaw**：
- 50+ 内置工具，覆盖 Shell/浏览器/文件/Web/Docker/多媒体
- ClawHub 5700+ 社区技能，生态丰富但质量参差不齐
- 懒加载机制节省 ~92% token 消耗
- 安全护栏：White-list + 参数扫描 + HITL

**Hermes**：
- 50+ 内置工具，覆盖类似的领域
- 自进化技能：Agent 完成新任务后自动总结为技能（这是 OpenClaw 不具备的）
- 27 分类内置技能库，质量可控但数量远不如 ClawHub
- 安全护栏：tool_guardrails.py + error_classifier.py

### 2. 记忆系统

**OpenClaw 四层记忆栈**：
```
Session Context → Daily Logs → MEMORY.md → Vector Search
(进程内存)       (Markdown)    (结构化记忆)  (语义检索)
```
- 需要 Redis + Qdrant/PGVector + Graph DB
- 支持语义向量检索，可发现非关键词匹配但语义相关的记忆
- 架构较重，适合对记忆质量有高要求的场景

**Hermes SQLite + FTS5**：
```
Session State → SQLite DB → FTS5 全文搜索 → LLM 摘要
```
- 只需 SQLite，零外部依赖
- FTS5 全文搜索 + LLM 摘要满足大多数记忆回溯需求
- 轻量实用，适合个人或小团队部署

### 3. 多 Agent 协作

**OpenClaw Hub-Spoke**：
- Orchestrator + 专项子 Agent
- sessions_spawn 工具创建 Docker 隔离的子 Agent
- 无依赖任务并行，有依赖串行
- 适合：中等复杂的任务分解

**Hermes Kanban + delegate_task**：
- SQLite 持久化的 Kanban 看板
- Dispatcher + Worker 模式
- 支持 fan-out/fan-in、优先级队列、状态机
- 适合：长时间运行的复杂任务流

### 4. 安全防护

**OpenClaw**：
- 多层护栏（白名单→参数扫描→HITL→沙箱）
- Docker 沙箱默认开启且配置严格（--cap-drop=ALL, --net=none）
- 风险：ClawHub 12% 技能含恶意代码，供应链风险高
- 512+ 已知漏洞（截至 2026.01），CVE-2026-25253 (CVSS 8.8)

**Hermes**：
- 工具护栏 + 多沙箱后端（Docker/Modal/Daytona/SSH/Singularity）
- 内置技能无供应链风险
- 攻击面更小（代码规模更大但暴露面可控）

### 5. 自进化能力

这是 Hermes 最独特的优势。OpenClaw 不具备等价机制。

**Hermes 自进化循环**：
```
Agent 完成任务 → 总结经验 → 自动创建/更新技能文件
                              ↓
                   curator.py 定期审查 → 改进建议 → 自动修补
                              ↓
                   下次遇到类似任务 → 直接复用技能
```

**OpenClaw** 的技能进化依赖：
- 社区在 ClawHub 上发布新版本
- 用户手动编写或修改技能
- 没有自动化的经验总结和技能改进机制

### 6. 生态规模

| 指标 | OpenClaw | Hermes |
|------|----------|--------|
| GitHub Stars | ~250K | 较小 |
| 贡献者 | 370+ | 较少 |
| 技能/插件 | 5700+ | 27 分类内置 |
| 企业采用 | 腾讯/阿里/华为/小米/Nvidia | Nous Research 主导 |
| 衍生项目 | Java 移植、C 移植、Managed Agents 等 | 暂无公开衍生 |
