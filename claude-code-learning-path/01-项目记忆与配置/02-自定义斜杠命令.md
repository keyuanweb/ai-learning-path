# 自定义斜杠命令

## 概述

自定义斜杠命令让你能创造可复用的工作流，团队共享或跨项目使用。命令文件是放在特定目录下的 Markdown 文件。

## 命令文件目录

| 位置 | 作用范围 | 使用场景 |
|------|---------|---------|
| `.claude/commands/` | 当前项目 | 团队共享的工作流 |
| `~/.claude/commands/` | 所有项目 | 个人常用的工作流 |

## 命令文件结构

### 基本格式

```markdown
---
description: 命令的简短描述（必填，用于 /help 显示）
argument-hint: [参数1] [参数2]
allowed-tools: Bash(git add:*), Bash(git commit:*)
---

<objective>
命令要达成的目标
</objective>

<context>
可选的动态上下文
</context>

<process>
执行步骤
</process>

<success_criteria>
成功标准
</success_criteria>
```

### XML 标签说明

| 标签 | 必须 | 说明 |
|------|------|------|
| `<objective>` | 是 | 命令要达成的目标 |
| `<process>` | 是 | 执行步骤，可包含子步骤 |
| `<success_criteria>` | 是 | 完成标准 |
| `<context>` | 否 | 动态上下文（常配合 `!` 使用） |

## 实战示例

### 示例 1：智能 Commit 命令

`.claude/commands/commit.md`：

```markdown
---
description: 创建符合 Conventional Commits 规范的提交
allowed-tools: Bash(git add:*), Bash(git status:*), Bash(git commit:*), Bash(git diff:*)
---

<objective>
为当前改动创建一个原子化的、符合规范的 git commit。
</objective>

<context>
- 工作区状态: !`git status --short`
- 改动详情: !`git diff HEAD`
- 最近 5 条提交: !`git log --oneline -5`
</context>

<process>
1. 分析当前所有改动（staged & unstaged）
2. 按逻辑分组，每次只提交一组相关的改动
3. 按 Conventional Commits 格式编写提交信息：
   - feat: 新功能
   - fix: 修复
   - refactor: 重构
   - docs: 文档
   - test: 测试
   - chore: 杂项
4. 依次暂存相关文件并提交
</process>

<success_criteria>
- 所有改动已分组提交
- 每个提交信息符合 Conventional Commits 格式
- 没有遗留未暂存的相关文件
- 提交创建成功
</success_criteria>
```

### 示例 2：PR Review 命令

`.claude/commands/review.md`：

```markdown
---
description: 全面的 PR 代码审查
argument-hint: [PR编号]
allowed-tools: Bash(gh pr view:*), Bash(gh pr diff:*), Read, Grep
---

<objective>
对 PR #$1 进行全面审查：正确性、安全性、性能和可维护性。
</objective>

<context>
- PR 信息: !`gh pr view $1 --json title,body,author`
- 改动文件: !`gh pr diff $1 --stat`
</context>

<process>
1. 获取 PR 详情和代码改动
2. 从以下维度审查：
   - 正确性：逻辑是否正确，边界情况是否处理
   - 安全性：是否有注入、泄露等风险
   - 性能：是否有不必要的计算或 I/O
   - 可维护性：代码是否清晰、是否有重复
3. 给出具体建议（带行号和代码示例）
</process>

<success_criteria>
- 审查覆盖全部 4 个维度
- 每个问题附带具体位置和改进建议
- 给出总体评估：approve / comment / request-changes
</success_criteria>
```

### 示例 3：TDD 工作流命令

`.claude/commands/tdd.md`：

```markdown
---
description: Red-Green-Refactor TDD 工作流
argument-hint: [功能描述]
allowed-tools: Read, Write, Edit, Bash(*test*), Bash(*lint*)
---

<objective>
按照 TDD 周期为"$ARGUMENTS"实现功能：先写失败测试 → 最小实现让测试通过 → 重构优化。
</objective>

<process>
1. RED: 编写失败的测试用例
2. 运行测试确认失败（不是语法错误）
3. GREEN: 编写最小量代码让测试通过
4. 运行测试确认通过
5. REFACTOR: 重构代码，消除重复，提升可读性
6. 再次运行测试确认仍然通过
</process>

<success_criteria>
- 测试覆盖了核心场景和边界情况
- 实现代码以最简方式通过测试
- 重构后代码遵循项目约定
- 所有测试通过
</success_criteria>
```

## 进阶技巧

### 动态上下文（!）

在 `<context>` 中使用 `!` 执行命令并注入输出：

```markdown
<context>
- 当前分支: !`git branch --show-current`
- 未提交文件: !`git status --short`
</context>
```

### 文件引用（@）

引用项目文件作为参考：

```markdown
<process>
1. 参考 @docs/api-conventions.md 中的 API 规范
2. 检查 @src/middleware/auth.ts 中的认证逻辑
</process>
```

### 模型覆盖

为特定命令指定模型：

```markdown
---
description: 深度性能分析
model: opus
---
```

### 禁止自动调用

```markdown
---
description: 手动触发的安全审查
disable-model-invocation: true
---
```

## 命令管理

```bash
# 列出所有可用命令
/help

# 创建命令模板
mkdir -p .claude/commands
```
