# 预训练数据工程

> 数据质量决定了模型能力的上限。模型架构和训练技巧只能逼近这个上限，无法超越。

---

## 1. 数据工程的五个阶段

### 解决什么问题

原始互联网数据是"脏"的——重复、低质、有害、格式混乱。直接用这些数据预训练会产生低质量、充满偏见、事实错误的模型。数据工程的目标是**从海量原始数据中提取出高质量、多样化、安全的训练语料**。

### 完整流水线

```
原始数据 → 过滤 → 去重 → 质量分类 → 配比 → 训练数据
```

## 2. 数据采集

| 来源 | 类型 | 量级 | 问题 |
|------|------|------|------|
| Common Crawl | 网页 | PB 级 | 极脏，90%+ 需过滤 |
| Wikipedia | 百科 | ~20GB | 质量高但量少 |
| Books | 书籍 | TB 级 | 版权问题 |
| GitHub | 代码 | TB 级 | 许可证问题 |
| 学术论文 | 科学文献 | TB 级 | 格式特殊 |
| 对话/论坛 | Reddit, StackExchange | TB 级 | 偏见 |
| 专有数据 | 内部文档 | 不定 | 私密性 |

### LLaMA 3 的数据配比

| 数据来源 | 比例 | 作用 |
|----------|------|------|
| 网页 (经过滤) | ~50% | 通用知识 |
| 代码 | ~20% | 推理、逻辑 |
| 书籍 | ~10% | 长文本连贯性 |
| 学术 | ~10% | 专业知识 |
| 多语言 | ~10% | 多语言能力 |

## 3. 过滤：去掉"垃圾"

### 解决的问题

- 低质量内容：拼写错误、不连贯、模板化文本
- 有害内容：仇恨言论、暴力、色情
- 非自然语言：HTML 标签残留、JavaScript 代码、重复字符
- 太短/太长：一个词的句子或百万 token 的超长文档

### 常用过滤方法

| 方法 | 去什么 | 原理 |
|------|--------|------|
| **困惑度过滤** | 低质量文本 | 用小语言模型计算 PPL，PPL 过高 = 不自然 |
| **语言检测** | 非目标语言 | fastText 分类器 |
| **规则过滤** | HTML、重复、太短/太长 | 正则 + 长度阈值 |
| **分类器过滤** | 有害内容 | toxicity classifier |
| **启发式过滤** | 垃圾文本 | 停用词比例、特殊字符比例、重复 n-gram 比例 |

---

## 4. 去重：消除冗余

### 解决的问题

互联网上同一篇文章被转载数百次。如果不做去重，模型会在相同数据上反复训练 → 过拟合 + 浪费算力 + 可能导致训练数据记忆（隐私问题）。

### 三层去重

| 层级 | 方法 | 粒度 |
|------|------|------|
| **文档级去重** | MinHash + LSH | 整篇文章 |
| **段落级去重** | 精确/近似匹配 | ~100 词 |
| **跨数据集去重** | 去掉训练集中与测试/验证集重合的样本 | 防止 benchmark 泄露 |

**MinHash 原理**：将文档表示为 n-gram 集合，通过多个哈希函数签名后比较 Jaccard 相似度。极快（$O(1)$ 每对），适合 PB 级去重。

## 5. 质量分类：选出"好"数据

### 问题

过滤是"去掉明显坏的"，但大部分数据处于"灰色地带"——不好不坏。需要给每条数据打分，选择高质量的部分。

### PPL-based 方法

用一个在高质量文本（如 Wikipedia）上训练的参考模型给每条数据打分，PPL 越低表示越接近高质量文本。

### Classifier-based 方法

训练一个分类器（如基于 Llama 2 的小模型），对每条数据的"教育价值"、"信息密度"、"格式正确性"打分。

### 模型辅助筛选（LLaMA 3 的做法）

用已有的高质量模型（如 Llama 2 70B）对候选数据进行质量评分，高于阈值的保留。这本质上是用一个"老师模型"筛选"学生模型"的训练数据。

---

## 6. 数据配比：平衡的艺术

### 问题

不同来源的数据教模型不同的能力，但比例不当会产生灾难后果：
- 代码太多 → 模型变得"过于逻辑化"，日常对话僵硬
- 书籍太多 → 模型变成"文学腔"，不会回答事实性问题
- 多语言不平衡 → 低资源语言能力差

### 配比策略

| 策略 | 做法 | 代表 |
|------|------|------|
| **启发式配比** | 根据经验设定比例 | 早期 LLaMA |
| **小模型实验** | 用不同配比训练小模型，选最好的 | Chinchilla |
| **动态配比** | 训练过程中调整配比（前期多常识，后期多推理） | LLaMA 3 |
| **学习型配比** | 用 DoReMi 等方法自动学习最优配比 | 前沿研究 |

---

## 7. 数据工程的投资回报

| 投入 | 效果 |
|------|------|
| 1x 数据量但高质量 | > 10x 数据量但低质量 |
| 精细过滤 (去重+质量筛选) | PPL 降低 5-10%，下游提升 ~5% |
| 多语言数据配比优化 | 低资源语言提升 10-20% |
| 代码数据 15-30% | 推理能力显著提升 |

数据工程是大模型训练中**ROI 最高的环节**——同样的 GPU 预算，更好的数据比更好的训练技巧带米的收益更大。
