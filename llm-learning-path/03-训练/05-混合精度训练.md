# 混合精度训练

混合精度训练几乎是大模型训练的免费午餐：**不改变模型结构，不改变超参数，训练速度提升 1.5-2×，显存降低 30-50%**。

---

## 1. 解决的问题

### FP32 (32-bit 浮点数) 为什么浪费

大模型的绝大多数运算不需要 FP32 的精度。FP32 提供 7-8 位有效数字，但对于 Attention 权重和 FFN 中间值，3-4 位有效数字就足够了。多余的精度只是"显存和计算时间的浪费"。

但**不能全部用低精度**——某些操作真的需要高精度：
- **权重更新**：如果学习率是 $10^{-5}$，乘以梯度后的增量可能只有 $10^{-7}$ 量级，在 FP16（最小可表示约 $6 \times 10^{-8}$）中会直接下溢到 0
- **Loss 累积**：大 batch 的 loss 和可能很大（量级问题）

### 混合精度的核心思想

> 大部分计算用低精度（FP16/BF16）省时间+省显存；关键部分保留高精度（FP32）确保正确性。

---

## 2. FP16 vs BF16

| | FP16 | BF16 | FP32 |
|---|---|---|---|
| **总位数** | 16 | 16 | 32 |
| **指数位** | 5 | 8 | 8 |
| **尾数位** | 10 | 7 | 23 |
| **表示范围** | $~10^{-8} \sim 65504$ | $~10^{-38} \sim 3.4\times 10^{38}$ | 更大 |
| **精度** | 中 | 略低于 FP16 | 高 |
| **溢出风险** | 高（范围小） | 无（范围=FP32） | 无 |

### 为什么 BF16 现在是主流

**BF16 是 FP32 的"砍半版"**——指数部分与 FP32 完全相同，只是尾数截断了。这意味着：
- BF16 → FP32 转换是"无损"的（直接补 0）
- 表示范围与 FP32 一样大，不存在溢出问题
- 不需要 Loss Scaling（这是 FP16 最大的工程麻烦）

```python
# 大模型训练的标准做法
with torch.autocast(device_type='cuda', dtype=torch.bfloat16):
    logits = model(inputs)
    loss = criterion(logits, labels)

loss.backward()  # 反向传播也是混合精度
optimizer.step() # 参数更新回到 FP32
```

## 3. AMP (Automatic Mixed Precision) 的工作机制

### 哪些用低精度，哪些保留高精度

| 操作 | 精度 | 原因 |
|------|------|------|
| **Linear 层** (QKV, FFN) | BF16 | 矩阵乘法计算量大，低精度加速最明显 |
| **Attention softmax** | BF16 | 注意力权重不需要高精度 |
| **LayerNorm/RMSNorm** | FP32 | 涉及平方和开方，精度敏感 |
| **Loss 计算** | FP32 | cross entropy 数值范围大 |
| **梯度累积** | FP32 | 多次累积后小梯度可能下溢 |
| **参数更新** | FP32 | 权重更新增量可能极小 |

PyTorch 的 `autocast` 会自动做这些决策——开发者不需要手动指定。

## 4. Loss Scaling（仅 FP16 需要）

### 问题

FP16 的最小正数约 $6 \times 10^{-8}$。如果某个梯度值小于这个阈值，在 FP16 下就变成了 0 → 参数不更新 → 模型学不到这个信号。

### 解决方案

在前向传播完成后，将 loss 乘以一个大系数（如 $2^{16} = 65536$）→ 梯度也成比例放大 → 小梯度被"推"入 FP16 的表示范围 → 在反向传播结束后 / 更新之前，将梯度除以同样的系数恢复。

```python
# FP16 AMP 的完整流程 (PyTorch自动处理)
loss = loss * scale            # 放大
loss.backward()                # 梯度也被放大了
optimizer.step()
```

**但如果用 BF16，不需要这一切**——这也是 BF16 更受欢迎的原因。

## 5. FP8：更进一步的精度压缩 (Hopper H100)

### 解决的问题

FP16/BF16 已经不错了，但 H100 GPU 的 FP8 Tensor Core 可以提供 2× 于 FP16 的算力。能否用 8 位精度做部分计算？

### FP8 的两种格式

- **E4M3**：4 位指数 + 3 位尾数 → 表示范围小但精度更高 → 适合前向传播
- **E5M2**：5 位指数 + 2 位尾数 → 表示范围大但精度较低 → 适合梯度

### 混合 FP8 训练

前向传播用 E4M3（精度重要），梯度用 E5M2（范围重要），参数更新仍保留 FP32。配合精细的 scaling 策略（按张量统计动态调整缩放因子）。

**现状**：FP8 训练已在 H100 上可用（通过 TransformerEngine），但工程复杂度远高于 BF16。对于大多数微调任务，BF16 足够。

## 6. 最佳实践

| 场景 | 推荐 |
|------|------|
| 预训练（大模型） | BF16 + AMP |
| 微调（LoRA/全量） | BF16 + AMP |
| H100 训练优化 | FP8 (TransformerEngine) |
| 老旧 GPU (V100) | FP16 + Loss Scaling |
| 推理 | 看 06-优化/量化章节 |
| 绝对不推荐 | 纯 FP32（浪费 2× 显存 + 2× 时间） |
