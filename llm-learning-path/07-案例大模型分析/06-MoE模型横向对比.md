# MoE 模型横向对比

2025 年，MoE 从 DeepMind 的研究实验变成了大模型的标配。不同模型对 MoE 的设计选择反映了不同的工程哲学。

---

## 1. 对比矩阵

| | DeepSeek-V3 | LLaMA 4 Maverick | Qwen3-MoE | Mixtral 8×7B |
|---|---|---|---|---|
| **总参数** | 671B | 400B | 235B | 47B |
| **活跃参数** | 37B (5.5%) | 17B (4.3%) | 22B (9.4%) | 13B (27.7%) |
| **专家总数** | 256 (+1 共享) | 128 (+1 共享) | 128 | 8 |
| **每 token 激活** | 9 (1共享+8路由) | 2 (1共享+1路由) | 8 | 2 |
| **专家粒度** | 细 (2048 hidden) | 粗 (8192 hidden) | 中 | 粗 |
| **共享专家** | 是 | 是 | 否 | 否 |
| **MoE 层密度** | 除前3层外每层 | 交替 MoE/密集 | 每层 | 每层 |
| **注意力** | MLA | GQA | GQA | GQA (Mistral) |

---

## 2. 设计哲学的分歧

### 专家粒度：细 vs 粗

**DeepSeek (细)**：每个专家是一个小 FFN（hidden dim = 2048 vs 密集的 8192 的 1/4）。256 个这样的小专家提供极细粒度的知识分离。路由有极大的选择空间。

**LLaMA 4 (粗)**：每个专家就是完整的 FFN（hidden dim = 8192）。专家数量少（128），但每个专家能力强。

**权衡**：
- 细粒度 → 更好的知识分离，但路由压力大（从 256 个中选对 8 个）
- 粗粒度 → 每个专家更"全能"，但知识分离不够精细

### 共享专家：要还是不要

**DeepSeek / LLaMA 4 (要)**：共享专家捕获通用语言能力（语法、基础常识），路由专家专注领域特化。相当于有一个"通识教育"的基底，在此之上叠加"专业训练"。

**Qwen3 (不要)**：所有知识都通过路由。避免了共享/路由专家之间的知识冗余和冲突。纯粹的 MoE 理念。

**实际差异**：
- 有共享专家的模型在通用任务上更稳定（共享专家兜底）
- 无共享专家的模型在领域任务上可能更精准（没有"通用"专家干扰路由）

### 激活率：极稀疏 vs 温和稀疏

| 模型 | 激活率 | 推理效率 | 微调难度 |
|------|--------|---------|---------|
| DeepSeek (5.5%) | 极高 | 微调数据量需求大 |
| LLaMA 4 (4.3%) | 最高 | 微调数据量需求最大 |
| Qwen3 (9.4%) | 中等 | 中等 |
| Mixtral (27.7%) | 一般 | 接近密集模型 |

**极稀疏 (DeepSeek/LLaMA 4) 的代价**：每个 token 只经过少数专家 → 这些专家必须"全能" → 需要更大的 total 参数量来补偿 → 需要更多的 GPU 来装下所有专家。

---

## 3. 路由策略

### DeepSeek: Top-8 + Aux-Loss-Free

- 从 256 个专家中选 8 个 → 丰富的选择空间
- **Aux-Loss-Free 负载均衡**：不是加一个辅助损失来惩罚不均衡，而是通过**动态调整每个专家的 bias**——过载的专家降低 bias（减少被选概率），空闲的专家增加 bias。避免了辅助损失与主任务损失冲突

### LLaMA 4: Top-1 + 共享专家

- 每个 token 只选 1 个路由专家 + 共享专家 → 极度稀疏
- 路由简单（就一个选择），但需要共享专家提供通用能力

### Qwen3: Top-8, 无共享

- 类似 DeepSeek 的选择，但无共享专家
- 8/128 = 6.25% 选择率，与 DeepSeek 接近

## 4. 推理效率的实际对比

以单 token 推理 FLOPs 为基准（密集 70B = 1×）：

| 模型 | 相对 FLOPs | 显存需求 | 推理速度 |
|------|-----------|---------|---------|
| 密集 70B | 1× | ~140 GB | 1× |
| Mixtral 8×7B | ~0.19× (13B活跃) | ~94 GB (47B总) | ~2× |
| Qwen3-MoE | ~0.31× (22B活跃) | ~470 GB (235B总) | ~1.5× |
| LLaMA 4 Maverick | ~0.24× (17B活跃) | ~800 GB (400B总) | ~2× |
| DeepSeek-V3 | ~0.53× (37B活跃) | ~1342 GB (671B总) | ~1× |

**FLOPs 不是唯一瓶颈**——显存才是。DeepSeek 虽然活跃 FLOPs 最高，但 671B 的总参数需要跨越大量 GPU 存储，跨卡通信是推理延迟的主要来源。

---

## 5. 选 MoE 还是密集

| 指标 | 密集模型 | MoE 模型 |
|------|---------|---------|
| 训练成本 | 中 | 高（需要更多数据） |
| 推理 FLOPs | 高（所有参数参与） | 低（只有活跃参数） |
| 推理显存 | 中 | 高（所有专家都要加载） |
| 微调难度 | 低 | 高（容易过拟合） |
| 单卡友好 | 好 | 差（总参数太大） |
| 高并发服务 | 一般 | 好（FLOPs 低） |
| 能力上限 | 中 | 高（更多总知识容量） |

**结论**：MoE 适合大公司的高并发 API 服务（多 GPU 集群，吞吐优先）；密集模型适合个人/小团队的微调和单卡部署（简单可控）。
