# Qwen 系列架构剖析

Qwen 是中文大模型的标杆，但其技术贡献远超"中文优化"。Qwen3 的密集和 MoE 双轨策略代表了对模型部署灵活性的思考。

---

## 1. Qwen 系列的定位

### 解决的核心问题

LLaMA 系列对中文不友好（tokenizer 32K，中文效率低）。需要一个**从 tokenizer 到训练数据到对齐全链路中文优化**的模型家族。

### Qwen 2.5 → Qwen3 的演化

```
Qwen 2.5: 密集模型 (0.5B → 72B)，标准 GQA + SwiGLU
Qwen3:    密集 + MoE 双轨，混合 Pre/Post-Norm，思考模式
```

---

## 2. Tokenizer：中文友好的基础

### Qwen 的词表设计

| | LLaMA 3 | Qwen 2.5 | DeepSeek-V3 |
|---|---|---|---|
| **Vocab Size** | 128K | 152K | 128K |
| **中文 1 token 覆盖率** | ~60% | ~85% | ~80% |
| **编码效率 (中文)** | 2-3 tokens/汉字 | 1-1.5 tokens/汉字 | 1-1.5 tokens/汉字 |

Qwen 的 tokenizer 在词表大小和中文效率之间取得了最好的平衡——152K 的词表比 LLaMA 大（更好的中文），但不像某些方案过度膨胀。

**解决的问题**：同等中文内容，Qwen 的 token 序列比 LLaMA 短 ~1.5-2× → Attention 计算量降为原来的 1/2-1/4 → 推理速度显著更快。

---

## 3. 规范化策略：不跟风的独立思考

### Qwen3 的混合 Pre/Post-Norm

大多数现代模型只用 Pre-Norm。Qwen3 在 Attention 部分使用 Pre-Norm（稳定），在 FFN 部分使用 Post-Norm：

```
Qwen3 Block:
    x = x + Attn(RMSNorm(x))       # Pre-Norm for Attention
    x = RMSNorm(x + FFN(x))        # Post-Norm for FFN  ← 不同于 LLaMA！
```

**为什么在 FFN 用 Post-Norm**：FFN 的输出可能出现量级偏大的情况（SwiGLU 的门控和 up project 相乘后的值域不稳定），Post-Norm 在输出后做归一化可以防止量级在残差路径上累积。

### MoE 变体放弃共享专家

DeepSeek 和 LLaMA 4 的 MoE 都有共享专家（用于捕获通用能力）。Qwen3-MoE 选择不设共享专家，所有 128 个专家都通过路由选择。

**设计哲学**：共享专家可能学到的"通用知识"与路由专家的"领域知识"会产生冗余。不如让所有知识都通过路由动态分配，更纯粹地发挥 MoE 的稀疏激活优势。代价是需要更好的负载均衡策略。

---

## 4. 思考模式 (Thinking Mode)

### 解决的问题

用户不是每次都需要深度推理（"今天几号？"vs "证明这个数学定理"）。但用一个模型覆盖两种场景——日常对话需要快，推理任务需要深——这两者矛盾。

### Qwen3 的方案

通过特殊的 token 控制模型的"思考深度"：

```
<|thinking|>  开启思维链模式 (CoT)
<|/thinking|> 关闭思维链模式

输入: "<|thinking|>证明根号2是无理数<|/thinking|>"
模型: 生成详细的逐步推理链 → 给出结论

输入: "今天几号？"
模型: 直接回答（不生成无意义的中间推理）
```

**这解决了什么**：不需要部署两个模型（一个快、一个深）。同一个模型可以根据 prompt 中的标记切换行为模式。这是用模型能力取代多模型部署的聪明做法。

---

## 5. Qwen3 密集 vs MoE 的选择

| 维度 | Qwen3 密集 (72B) | Qwen3-MoE (235B-A22B) |
|------|-----------------|----------------------|
| **单卡推理** | 较难（72B × 2 bytes = 144GB） | 容易（活跃 22B） |
| **推理吞吐** | 低 | 高（活跃参数少） |
| **微调难度** | 简单 | 较难（MoE 过拟合风险） |
| **能力上限** | 高 | 更高（总知识量大） |
| **适用场景** | 微调+单任务部署 | 多任务高并发 API |

**双轨策略的意义**：用户可以根据自己的硬件和需求选择密集或 MoE。这是"选择权"——把架构决策权交给用户。其他大模型系列（LLaMA、DeepSeek）更适合大规模 API 服务，Qwen 的设计更考虑"个人的单卡微调"。

---

## 6. Qwen3 的技术决策总结

| 决策 | 与主流不同的选择 | 原因 |
|------|----------------|------|
| 混合 Pre/Post-Norm | Post-Norm on FFN | 防止 FFN 输出量级漂移 |
| 无共享专家 MoE | 纯路由 | 避免冗余，更纯粹的稀疏 |
| 超大词表 152K | 比 LLaMA 大 | 中文效率优先 |
| 思考模式 | 模型内切换 | 替代多模型部署 |
| 双轨 (密集+MoE) | 两套架构 | 用户选择权 |
