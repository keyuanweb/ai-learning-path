# 机制可解释性

可解释性回答一个根本问题：**大模型内部到底在做什么？** 不是黑盒观察（给它输入看输出），而是"打开盒子"看每个神经元、每层激活在做什么。

---

## 1. 为什么要可解释性

### 三件事推动了这个领域

1. **安全**：如果不知道模型怎么"思考"，你怎么保证它不会偷偷学会有害模式？
2. **对齐**：模型是否有"欺骗"能力？它在 Surface 层面说"我不知道"的时候，内部是不是其实"知道"？
3. **控制**：能不能修改特定知识而不用重新训练？能不能删除危险能力？

---

## 2. Sparse Autoencoders (SAEs)

### 解决的问题

模型内部的激活是**稠密**的（4096 维向量，几乎每个维度都有值），人无法理解。SAE 将稠密激活分解为**稀疏的、可解释的特征**。

### 直觉

```
原始激活: [0.023, -0.41, 0.87, 0.15, ...] (4096 维，几乎全有值)
         ↓ SAE 编码
稀疏特征: [0, 0, 3.2, 0, 0, 0, 5.1, ...]  (65536 维，大部分是 0)
         ↑
    只有少数特征激活：
    特征 #42 (激活 3.2) = "提到金门大桥"
    特征 #1337 (激活 5.1) = "法律文本"
```

### 如何训练 SAE

```python
# SAE = Encoder + Decoder
# Encoder: d_model → 扩展维度（如 4096 → 65536），用 ReLU 强制稀疏
# Decoder: 扩展维度 → d_model，重建原始激活

class SparseAutoencoder(nn.Module):
    def __init__(self, d_model=4096, d_sparse=65536):
        self.encoder = nn.Linear(d_model, d_sparse)
        self.decoder = nn.Linear(d_sparse, d_model)
    
    def forward(self, x):
        # 编码：用 ReLU 强制大部分维度为 0（稀疏性）
        features = F.relu(self.encoder(x))
        # 解码：尝试重建原始激活
        reconstructed = self.decoder(features)
        
        # Loss = 重建误差 + 稀疏惩罚
        recon_loss = F.mse_loss(reconstructed, x)
        sparsity_loss = features.abs().sum()  # L1，鼓励更多 0
        return recon_loss + lambda_sparse * sparsity_loss
```

**训练后**：每个特征维度对应一个可解释的概念。激活特征 #42 → 看什么文本让它激活 → 发现它专门对"金门大桥"相关内容响应。

## 3. Activation Patching

### 解决的问题

模型做了一件事（输出了答案 A）。是哪一层、哪个位置的激活导致的？如果我把某一层的激活换成另一个输入的激活，输出会变吗？

### 操作

```python
# 正常前向：输入 X → 输出 A
# Patch 前向：输入 X → 但把第 15 层的激活换成输入 Y 的第 15 层激活 → 观察输出变成什么

def activation_patching(model, clean_input, corrupted_input, layer_idx):
    """在 corrupted_input 的前向过程中，将指定层的激活替换为 clean_input 的"""
    
    patched_activation = None
    
    def hook(module, input, output):
        # 用 clean 的激活替换 corrupted 的激活
        return patched_activation
    
    # 1. 先用 clean_input 跑一次，记录目标层的激活
    handle = model.layers[layer_idx].register_forward_hook(
        lambda m, i, o: setattr(sys.modules[__name__], 'patched_activation', o)
    )
    model(clean_input)
    patched_activation = ...  # 从 hook 获取
    
    # 2. 用 corrupted_input 跑，但替换指定层的激活
    handle = model.layers[layer_idx].register_forward_hook(hook)
    output = model(corrupted_input)
    
    # 3. 如果 output 变成了 clean_input 的输出 → 这一层是关键
    return output
```

### 一个经典发现

用 Activation Patching 发现：Transformer 的早期层负责"语法/词性"级别的处理，中间层负责"语义/事实"，最后几层负责"输出格式/措辞"。不同知识储存在不同深度。

## 4. Gemma Scope

Google DeepMind 为 Gemma 2 模型提供了开源的 SAE 工具集：

- **每层都有 SAE**：不是只在输出层，而是 40+ 层 Transformer，每一层都训练了 SAE
- **不同稀疏度**：16K、65K、262K、1M 特征维度，研究不同粒度
- **开放访问**：可以直接加载并分析 Gemma 2 的任意层

```python
# 使用 Gemma Scope
from gemma_scope import load_sae

sae = load_sae(model_name="gemma-2-9b", layer=20, width="65k")

# 获取第 20 层的稀疏特征
hidden = model.layers[20].output
features = sae.encode(hidden)  # [batch, 65536]

# 查看哪些特征激活了
active_features = features.nonzero()  # 通常只有几百个
```

## 5. 可解释性的现实局限

| 现状 | 挑战 |
|------|------|
| **SAE 特征不一定干净** | 一个 "特征" 可能混合多个概念（"纽约"和"金融"混在一起） |
| **因果不等于相关** | 某个特征激活了 ≠ 它导致的输出是这个特征 |
| **规模问题** | 分析 7B 模型需要训练数千个 SAE |
| **可解释 ≠ 可控制** | 知道哪个特征控制什么 ≠ 能精确修改它 |

**2025 年共识**：可解释性已经能"看到"模型的内部结构，但还不能"精准编辑"。这个领域在快速进步。
