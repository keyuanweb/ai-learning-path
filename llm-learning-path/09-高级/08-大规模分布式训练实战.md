# 大规模分布式训练实战

单个 GPU 放不下 70B 模型。你需要把模型和数据拆分到多个 GPU 上。这一章讲怎么做，以及常见问题如何排查。

---

## 1. 为什么需要分布式

### 显存计算

一个 7B 参数模型：
- 参数本身：7B × 2 bytes (BF16) = 14GB
- 优化器状态 (Adam)：7B × 8 bytes × 2 = 112GB  ← **大头！**
- 梯度：7B × 2 bytes = 14GB
- 激活值（与 batch size 和序列长度有关）：variable

**单张 H100 (80GB) 纯推理够，但训练远远不够。**

---

## 2. 三种并行方式

### 数据并行 (Data Parallelism, DP)

```
GPU 0: 完整模型 + 数据 Batch[0:16]
GPU 1: 完整模型 + 数据 Batch[16:32]
GPU 2: 完整模型 + 数据 Batch[32:48]
GPU 3: 完整模型 + 数据 Batch[48:64]

每张 GPU 独立前向+反向 → 梯度 AllReduce 平均 → 每张 GPU 用平均梯度更新参数
```

**优点**：实现简单，通信仅发生在梯度同步时
**局限**：每张 GPU 必须有完整的模型副本 → 模型放不进单卡就做不了纯 DP

### 模型并行 (Tensor Parallelism, TP)

把模型的**每一层**切成多份分布在多 GPU 上。

```
一个 [4096, 4096] 的权重矩阵:
GPU 0: [2048, 4096] 前一半行
GPU 1: [2048, 4096] 后一半行

每步前向时需要 GPU 间通信来拼接完整结果
```

**优点**：能让单个超大层的参数跨 GPU 存储
**局限**：每个 token 的每次 forward 都要通信 → 通信量大

### 流水线并行 (Pipeline Parallelism, PP)

把模型的**不同层**放在不同 GPU 上。

```
GPU 0: Layers 0-7
GPU 1: Layers 8-15
GPU 2: Layers 16-23
GPU 3: Layers 24-31

数据像流水线一样穿过各 GPU
```

**优点**：通信量比 TP 少（只在层边界通信）
**局限**：GPU 利用率不均（前面的 GPU 算完要等后面的）

---

## 3. 3D 并行：三者结合

生产级训练将 DP + TP + PP 结合：

```
[DP Group 0]                    [DP Group 1]
GPU 0: L0-7 上半矩阵    GPU 4: L0-7 上半矩阵
GPU 1: L0-7 下半矩阵    GPU 5: L0-7 下半矩阵
GPU 2: L8-15 上半矩阵   GPU 6: L8-15 上半矩阵
GPU 3: L8-15 下半矩阵   GPU 7: L8-15 下半矩阵

DP=2, PP=2, TP=2 (共 8 GPU)
```

## 4. DeepSpeed ZeRO 配置

DeepSpeed 的 ZeRO 从 DP 的"每张卡存完整副本"演进为"梯度/优化器/参数全部切分"：

| ZeRO 阶段 | 切分什么 | 显存节省 | 额外通信 |
|-----------|---------|---------|---------|
| ZeRO-1 | 优化器状态 | 4× | 无 |
| ZeRO-2 | 优化器 + 梯度 | 8× | 无 |
| ZeRO-3 | 优化器 + 梯度 + 参数 | N× (N=GPU 数) | 有 |

### ZeRO-3 配置示例

```json
{
    "train_batch_size": 512,
    "gradient_accumulation_steps": 8,
    "fp16": {
        "enabled": false
    },
    "bf16": {
        "enabled": true
    },
    "zero_optimization": {
        "stage": 3,
        "offload_optimizer": {
            "device": "cpu"          // 优化器状态 offload 到 CPU
        },
        "offload_param": {
            "device": "cpu"          // 参数也 offload 到 CPU（最省显存）
        },
        "overlap_comm": true,        // 通信与计算重叠
        "stage3_gather_16bit_weights_on_model_save": true
    },
    "optimizer": {
        "type": "AdamW",
        "params": {
            "lr": 3e-4,
            "weight_decay": 0.1
        }
    }
}
```

### 启动命令

```bash
# 8 GPU 训练 7B 模型
deepspeed --num_gpus=8 train.py \
    --deepspeed_config ds_config.json \
    --model_name_or_path meta-llama/Llama-2-7b
```

## 6. 故障恢复

### 关键原则

512 GPU 跑 30 天的训练，任何一张 GPU 都可能在任何时刻故障。你必须能自动恢复。

```python
# 一个鲁棒的训练循环
try:
    while step < total_steps:
        try:
            batch = next(dataloader)
            loss = train_step(batch)
            loss.backward()
            optimizer.step()
            
            if step % save_every == 0:
                # 保存 checkpoint（上传到对象存储，不在本地！）
                model.save_checkpoint(f"s3://my-bucket/ckpt-{step}")
        
        except (CUDABadAlloc, RuntimeError) as e:
            # 单步出问题：跳过，不中断整个训练
            log.warning(f"Step {step} failed: {e}, skipping batch")
            optimizer.zero_grad()
            continue

except KeyboardInterrupt:
    # 被手动暂停：保存 checkpoint
    model.save_checkpoint(f"s3://my-bucket/ckpt-interrupted-{step}")
```

### DeepSpeed 的自动恢复

DeepSpeed 支持从最后一个 checkpoint 自动恢复训练（保存 optimizer 状态比模型参数还重要——可以重算参数但不能重算 optimizer 的动量）。

## 7. 成本估算

训练一个 70B 模型的成本（2025 年参考）：

| 项目 | 数值 |
|------|------|
| GPU | 64 × H100 (80GB) |
| 训练时长 | ~30 天 |
| GPU 云成本 | ~$\$150K$ (按需) / ~$\$80K$ (预留) |

MoE 模型（如 DeepSeek-V3）因为活跃参数少，训练 FLOPs 更低但 GPU 数量需求更高（总参数大）。

## 本章速查

| 概念 | 核心 |
|------|------|
| **DP** | 每卡完整模型，梯度同步 |
| **TP** | 每层切片跨 GPU，通信量大 |
| **PP** | 不同层在不同 GPU，流水线 |
| **3D 并行** | DP + TP + PP 组合 |
| **ZeRO-3** | 切分所有状态（优化器+梯度+参数） |
| **故障恢复** | 定期 checkpoint + skip bad batch |
