# 自定义奖励模型训练

RLHF 和 DPO 都需要"知道什么是好回答"的评判标准。通用奖励模型有盲区——它不懂你的领域。你需要训练自己的奖励模型。

---

## 1. 奖励模型解决什么问题

### 场景

你在做一个法律合同审查助手。你需要模型判断"这个审查意见写得好不好"。通用奖励模型可能偏好"长而详细的回答"，但法律场景中"简洁精确"更重要。

你需要的不是"通用好"，而是"对你领域的好"。

---

## 2. Bradley-Terry 偏好模型

### 核心假设

对于两个回答 A 和 B，A 比 B 更好的概率由它们的"隐式质量分数"决定：

$$P(A \succ B) = \frac{e^{r_A}}{e^{r_A} + e^{r_B}}$$

其中 $r_A$ 和 $r_B$ 是 A 和 B 的"质量分数"（奖励模型要打的分）。

直觉：分数差距越大，判断越确定。A 评分 5、B 评分 2 → A 比 B 好的概率 ≈ 95%。A 评分 3、B 评分 2.9 → A 比 B 好的概率 ≈ 52%。

---

## 3. 训练数据构建

### 数据格式

```json
{
    "prompt": "请审查以下合同中的违约责任条款...",
    "chosen": "该条款的第二段存在歧义，'合理期限'未明确定义...",  // 人类偏好的回答
    "rejected": "这条款看起来没什么问题。"                         // 人类不偏好的回答
}
```

### 构建方法

| 方法 | 怎么做 | 成本 |
|------|--------|------|
| **人类标注** | 标注员比较两个回答 | 最高（$\$3-5/条$） |
| **LLM-as-Judge** | 用 GPT-4 判断哪个更好 | 中（$\$0.01/条$） |
| **合成数据** | 故意生成"坏回答"配对"好回答" | 低 |
| **用户行为** | A/B 测试中用户选了哪个 | 最低（但你得有产品） |

### 关键陷阱

标注数据中的**位置偏差**——标注员（和 LLM）倾向于偏好第一个出现的回答。对策：
- 随机打乱 A/B 的顺序
- 对每条数据存两份（顺序互换），两份都训练

## 4. 训练奖励模型

```python
class RewardModel(nn.Module):
    def __init__(self, base_model):
        super().__init__()
        self.transformer = base_model  # 复用预训练模型的主体
        self.reward_head = nn.Linear(hidden_size, 1)  # [hidden] → [1] 标量分数

    def forward(self, input_ids, attention_mask):
        hidden = self.transformer(input_ids, attention_mask).last_hidden_state
        # 取最后一个 token 的 hidden state（或取平均）
        pooled = hidden[:, -1, :]
        reward = self.reward_head(pooled)  # → [batch, 1]
        return reward.squeeze(-1)          # → [batch]

# Bradley-Terry Loss
def reward_loss(chosen_rewards, rejected_rewards):
    # chosen 比 rejected 好的概率
    prob = torch.sigmoid(chosen_rewards - rejected_rewards)
    # 最大化这个概率 = 最小化 -log(prob)
    return -torch.log(prob).mean()

model = RewardModel(base_llm)
for batch in preference_data:
    r_chosen = model(batch['chosen_input'])
    r_rejected = model(batch['rejected_input'])
    loss = reward_loss(r_chosen, r_rejected)
    loss.backward()
    optimizer.step()
```

## 5. 评估奖励模型

| 指标 | 含义 | 合格标准 |
|------|------|---------|
| **Accuracy** | 奖励模型同意人类判断的比例 | > 70% |
| **与 GPT-4 判断的相关性** | 你的 RM 打分 vs GPT-4 判断 | Spearman > 0.6 |
| **一致性** | 同一 prompt 的不同回答对，排序是否一致 | — |
| **校准** | 只有分数差距实时判断才确定 | — |

## 6. 后续：用奖励模型做 RLHF 或 Best-of-N

有了奖励模型，你可以：

1. **RLHF**：用 PPO/GRPO 优化策略模型，让奖励模型打分更高
2. **Best-of-N**：生成 N 个候选回答，用奖励模型选最好的（简单有效）
3. **Rejection Sampling**：生成候选，只保留奖励分数 > 阈值的作为训练数据

```python
# Best-of-N：简单但非常有效
def best_of_n(prompt, model, reward_model, n=16):
    candidates = [model.generate(prompt) for _ in range(n)]
    scores = [reward_model.score(prompt, c) for c in candidates]
    return candidates[argmax(scores)]
```
