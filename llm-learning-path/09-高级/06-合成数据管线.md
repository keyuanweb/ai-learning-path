# 合成数据管线

真实数据不够怎么办？用 LLM 生成。合成数据已经是现代大模型训练的标配——GPT-4、Claude、Qwen 的训练都大量使用了合成数据。

---

## 1. 合成数据解决什么问题

### 真实数据的局限

- **成本**：人工标注 $3-5/条，10 万条就是 $50 万
- **规模**：某些领域（法律判例、罕见病医疗记录）天然数据稀少
- **质量**：互联网文本充满了错误、偏见和废话
- **多样性**：用户实际问的问题和训练数据分布不匹配

### 合成数据的价值

用 LLM 生成高质量、多样化、针对性的训练数据，成本是人工标注的 1%。

## 2. Self-Instruct 及其演进

### 原始 Self-Instruct (2022)

```python
# 1. 用少量种子指令引导
seed_tasks = [
    "将以下句子翻译成英文",
    "总结以下段落",
]

# 2. LLM 基于种子生成更多变体
for seed in seed_tasks:
    new_tasks = llm.generate(
        f"基于以下任务生成 20 个类似但不同的任务:\n{seed}"
    )

# 3. LLM 为每个新任务生成输入和输出
for task in new_tasks:
    input_examples = llm.generate(f"为任务生成 5 个输入示例: {task}")
    for inp in input_examples:
        output = llm.generate(f"{task}\n{inp}")
        dataset.append((task, inp, output))
```

### 演进：Evol-Instruct (WizardLM)

不满足于简单变体，而是让 LLM **逐步增强问题的复杂度**：

```python
def evolve_instruction(base_instruction):
    """逐步加深问题的复杂度"""
    prompt = f"""
    将以下问题变得更深更难，可以：
    1. 增加约束条件
    2. 要求更详细的推理
    3. 增加步骤数
    4. 要求考虑边界情况

    原始: {base_instruction}
    进化后:
    """
    return llm.generate(prompt)

# "写一个排序函数" → "写一个排序函数，要求 O(n log n)、
#  稳定排序、支持自定义比较器、内存使用 O(1)、包含测试用例"
```

## 3. 数据质量验证

合成数据的最大问题是**垃圾进垃圾出**——LLM 生成的错误数据会毒害后续训练。

### 多层验证管线

```python
def validate_synthetic_data(dataset):
    # 层 1：格式检查
    dataset = [d for d in dataset if is_valid_format(d)]

    # 层 2：内容质量
    dataset = [d for d in dataset if not is_too_short(d)]
    dataset = [d for d in dataset if not has_repetition(d)]  # 去重复片段
    dataset = [d for d in dataset if not is_obviously_wrong(d)]

    # 层 3：LLM 验证（最贵，最可靠）
    validated = []
    for d in dataset:
        score = verifier_llm.judge(d)  # "这个答案是否正确、有用？"
        if score > 7:
            validated.append(d)

    # 层 4：去污（防止污染测试集）
    validated = deduplicate_against_benchmarks(validated)

    return validated
```

训练数据如果包含测试集的问题，评估结果就会虚高。去污 = 检查合成数据中是否有跟 benchmark 高度相似的内容。

## 4. 合成数据的配比

| 数据类型 | 合成生成 | 配比建议 |
|---------|---------|---------|
| **指令跟随** | Self-Instruct / Evol-Instruct | 30-40% |
| **代码** | LLM 生成代码 + 测试用例 | 20-25% |
| **数学推理** | 生成题 + 推理过程（验证答案正确性） | 10-15% |
| **多语言** | 翻译 + 回译验证 | 10-15% |
| **安全** | 故意生成边界案例 | 5% |

---

## 5. 合成数据的陷阱

| 陷阱 | 症状 | 对策 |
|------|------|------|
| **模型崩塌** | 用 LLM 生成的数据训练新 LLM → 新 LLM 同样有原 LLM 的偏见和盲区 | 混合真实数据（至少 30%） |
| **缺乏多样性** | 生成的指令千篇一律 | 提高 generation temperature + 多模型生成 |
| **幻觉扩散** | LLM 编造的"事实"被当作训练数据 | 事实性验证（用搜索引擎验证） |
| **评测污染** | 合成数据无意中包含了 benchmark 问题 | 系统性的 n-gram 去污 |
