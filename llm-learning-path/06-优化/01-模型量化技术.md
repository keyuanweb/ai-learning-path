# 模型量化技术

量化是大模型部署优化的第一手段。降低精度的代价很小（~1% 质量损失），收益极大（2-4× 显存节省 + 2-3× 加速）。

---

## 1. 量化的本质

### 解决的问题

大模型权重存储为 FP16/BF16（每个参数 2 bytes）。能否用更少的 bits 表示每个参数，同时保持模型质量？

### 量化 = 离散化

将连续的浮点数值映射到离散的整数区间：

```
FP16: [-3.27, -2.15, -0.03, 1.42, 2.89]   (每个 2 bytes)
 ↓ 量化到 INT8
INT8: [-127, -83, -1, 55, 112]              (每个 1 byte)
      × scale = 0.0258                       (共享的缩放因子)

恢复: -127 × 0.0258 ≈ -3.28 (误差 0.01，可忽略)
```

量化后的计算使用 INT8 Tensor Cores（A100 上比 FP16 快 2×），矩阵乘法速度翻倍。

---

## 2. 量化方案对比

### PTQ (Post-Training Quantization)：训练后量化

不重新训练，只是在已有模型上应用量化。所有主流方案都是 PTQ。

### QAT (Quantization-Aware Training)：训练感知量化

在训练/微调过程中模拟量化效果，让模型"适应"低精度。效果好但成本高——需要重新训练。

### 对比

| | PTQ | QAT |
|---|---|---|
| 需要训练 | 否 | 是 |
| 质量 | 好（损失 <2%） | 更好（损失 <1%） |
| 成本 | 零（几小时校正） | 高（重新训练） |
| 代表 | GPTQ, AWQ, GGUF | LLM-QAT |
| 推荐 | 先用 PTQ，不够再用 QAT | 追求极致 |

## 3. GPTQ：单样本最优量化

### 解决的问题

朴素的"直接截断"量化误差很大——某些权重通道的值域比其他通道大 10×，统一量化会严重扭曲小值通道。

### 原理

**逐层校正**——不是一次性量化所有权重，而是一列列地量化，每量化一列后，用剩余未量化的列"补偿"量化误差：

```python
for col in range(W.shape[1]):
    W_quant[:, col] = quantize(W[:, col])       # 量化这一列
    error = W_orig[:, col] - W[:, col]          # 量化误差
    # 将误差"分摊"到还未量化的列上
    for remaining_col in range(col+1, W.shape[1]):
        W[:, remaining_col] += error * H_inv[:, col, remaining_col]
```

- 只需要**一小撮校准数据**（通常是 128 条文本），计算 Hessian 矩阵来确定每列的"重要性"
- 逐列校正确保累积误差最小化
- 结果：INT4 量化后模型质量损失 <1-2%

## 4. AWQ (Activation-Aware Weight Quantization)

### GPTQ 忽略的问题

GPTQ 只考虑了**权重的量化误差**，但没考虑**激活值的影响**。某些权重通道可能值很小（容易被量化扭曲），但它们对应的激活通道很大——这些小权重的误差被大激活值放大了。

### AWQ 的解决方案

识别出最重要的权重通道（通过观察激活值的分布），对这些通道的权重**在量化前稍微放大一点**：

```python
# 找到与最大激活值对应的权重通道
salient_channels = topk(activation_magnitude.mean(dim=0), k=0.01 * d)

# 对这些通道的权重乘以一个小系数 (如 1.1)
W[salient_channels] *= 1.1

# 然后正常量化
W_quant = quantize(W)

# 推理时将系数"吸收"到 LayerNorm 中（无需额外计算）
```

**效果**：比 GPTQ 更好的质量保留（尤其是在小型模型上），同样 4-bit 量化，MMLU 分数高 1-2 分。

## 5. GGUF：本地推理的事实标准

### 解决的问题

GPTQ/AWQ 需要 GPU。如何在 CPU 上、在 MacBook 上、在手机上运行大模型？

### GGUF 的特点

- 文件格式统一：模型权重 + tokenizer + 配置全部打包在一个 .gguf 文件中
- 支持 1.5-bit 到 8-bit 的多种量化变体（Q4_0, Q4_K_M, Q5_K_M, ...）
- **mmap 加载**：不需要一次性将模型读入内存，按需从硬盘加载 → 16GB 内存可以跑 13B 模型
- CPU 推理优化：利用 SIMD (AVX2/NEON) 指令加速，Apple Silicon 上利用 Metal/MLX

```bash
# 一键本地推理
llama-cli -m llama-3-8b.Q4_K_M.gguf -p "Hello, how are you?"
```
