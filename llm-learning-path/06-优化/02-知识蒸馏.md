# 知识蒸馏

知识蒸馏解决的核心矛盾：**大模型效果最好但部署太贵，小模型能部署但能力不足。**

---

## 1. 核心思想

> 用一个"教师模型"（大，能力强）的输出作为训练信号，训练一个"学生模型"（小，能部署）。

教师模型不仅给出正确答案，还给出**概率分布**——即使是"错误"答案的概率也包含有价值的信息（这个错误答案比那个错误答案更合理）。

---

## 2. 三种蒸馏范式

### Logit 蒸馏

最基础的形式。让学生模型的输出概率分布模仿教师模型：

$$\mathcal{L}_{distill} = \text{KL}(P_{teacher} \| P_{student})$$

使用高温度 softmax 让教师分布"更柔软"——错误答案之间的差异也被放大，这些信息对学生很重要：

```python
# 高温度让教师分布更"软"
teacher_probs = softmax(teacher_logits / T)  # T=3-5
student_probs = softmax(student_logits / T)
distill_loss = KL(teacher_probs, student_probs)
```

**解决的问题**：one-hot 标签只告诉模型"巴黎是对的"，但没告诉"伦敦比北京更像正确答案"（在回答"法国首都是什么？"时）。软标签包含了这种"偏好排序"。

### 特征蒸馏

不仅模仿最终输出，还要模仿**中间层的隐藏表示**：

$$\mathcal{L}_{feat} = \| H_{teacher} - W_{proj} H_{student} \|_2^2$$

- 让学生模型的每一层（或特定层）的 hidden states 向教师模型对齐
- 需要投影矩阵 $W_{proj}$（因为教师和学生的隐藏维度可能不同）

### Black-box 蒸馏

只能调用教师模型的 API，无法访问内部 logits 或 hidden states。用 API 生成大量高质量回答，作为学生模型的 SFT 训练数据。

**这是 GPT-4 → GPT-4o-mini、Claude Opus → Claude Haiku 等闭源模型蒸馏小版本的通用方法。**

---

## 3. 蒸馏 + 微调 = 最强小模型

### 两阶段训练

```
阶段1: 知识蒸馏 (从教师模型获取软标签)
  训练数据: (输入, 教师模型输出的概率分布)
  目标: 让学生模型的输出分布接近教师

阶段2: 任务微调 (从标注数据学习)
  训练数据: (输入, ground truth 输出)
  目标: 在目标任务上优化
```

两阶段结合效果通常优于单独任一阶段——蒸馏提供"广博的知识"，微调提供"领域的精度"。

---

## 4. 蒸馏的极限

| 能蒸馏 | 不能蒸馏 (至少目前) |
|--------|-------------------|
| 知识：事实、常识、语言模式 | 涌现能力：小模型达到同样参数规模前不会自然出现 |
| 风格：写作风格、回答格调 | 推理链：复杂多步推理需要大模型的内部回路 |
| 对齐：偏好、安全性 | 上下文学习：ICL 在蒸馏到 <6B 时会退化 |

**结论**：蒸馏可以让 7B 模型接近 70B 模型在"知识"上的表现，但在"推理"上仍有差距。模型能力的上限取决于它自己的参数量。
