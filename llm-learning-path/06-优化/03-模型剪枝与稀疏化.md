# 模型剪枝与稀疏化

量化是用更少的 bits 表示每个参数；剪枝是直接**删除不重要的参数**。

---

## 1. 剪枝的两种类型

### 非结构化剪枝 (Unstructured Pruning)

将单个不重要的权重置为 0：

```
原始权重矩阵:
[0.3, 0.8, 0.01, 0.5]
[0.9, 0.02, 0.7, 0.1]

剪枝后 (50% 稀疏):
[0,   0.8, 0,   0.5]
[0.9, 0,   0.7, 0]
```

**问题**：虽然少了非零值，但矩阵还是稀疏的——GPU 对这种不规则稀疏模式的加速有限（需要专门的稀疏 Tensor Core 硬件支持）。

### 结构化剪枝 (Structured Pruning)

删除整行/整列/整头：

```
原始: [Attention Head 0, Head 1, ..., Head 31]
剪枝: [Head 0, Head 4, Head 7, ..., Head 28]  (去掉 25% 的头)
```

**优势**：删除后仍然是规则的密集矩阵，现有 GPU 可以零改动直接加速。这是实际更有用的剪枝方式。

---

## 2. 剪枝判定标准

### 怎么判断"不重要"

| 标准 | 方法 | 直觉 |
|------|------|------|
| **权重大小** | 绝对值小的权重 ≈ 不重要 | 简单有效，但忽略了激活值的影响 |
| **梯度** | 乘以梯度（weight × grad） | 考虑了对损失的影响 |
| **激活值** | Wanda：\|weight\| × \|activation\| | 权重小但激活大，实际上很重要 |
| **Hessian** | SparseGPT：二阶信息 | 精确但计算量大 |

### Wanda：简单有效的剪枝标准

$$\text{importance}_{ij} = |W_{ij}| \cdot \|x_j\|_2$$

其中 $\|x_j\|_2$ 是输入激活值第 j 个通道的 L2 范数。同时考虑了权重本身的大小和对应输入的大小——即使权重小的参数，如果对应的输入很大，它也很重要。

## 3. SparseGPT：大模型专用剪枝

### 解决的问题

GPTQ 用 Hessian 信息补偿量化误差，SparseGPT 用同样的思路处理剪枝误差：

1. 逐列剪枝权重矩阵
2. 每剪掉一列，用剩余列的权重补偿剪枝造成的输出误差
3. 只需要少量的校准数据
4. **可以在单个 GPU 上对 175B 模型进行剪枝**

```python
# SparseGPT 的核心伪代码
H = compute_hessian(W, calibration_data)  # 二阶信息
for col in range(W.shape[1]):
    # 选择这一列中最不重要的权重
    prune_mask[col] = select_topk(|W[:, col]|, sparsity_ratio)
    # 用剩余列补偿误差
    W[:, col+1:] += compensation(H, W[:, col], prune_mask[col])
```

**效果**：可以达到 50-60% 的稀疏度（参数减半）而 PPL 损失 <1-2 分。再高会显著退化。

---

## 4. 实际效果参考

以 LLaMA-7B 为例：

| 方法 | 稀疏度 | 模型大小 | PPL 上升 |
|------|--------|---------|---------|
| 不做剪枝 | 0% | 14 GB FP16 | 0 (基线) |
| Wanda | 50% 非结构化 | ~7 GB (2:4 稀疏) | +1.0 |
| SparseGPT | 50% 非结构化 | ~7 GB | +0.8 |
| SparseGPT | 60% | ~5.6 GB | +2.5 |
| 结构化剪枝 (去头) | 25% | ~10.5 GB | +3.0 |

**非结构化剪枝的实际加速取决于硬件**——只有 Hopper 架构 (H100) 的 2:4 稀疏 Tensor Core 才能利用 50% 的随机稀疏。结构化剪枝没有这个问题。
