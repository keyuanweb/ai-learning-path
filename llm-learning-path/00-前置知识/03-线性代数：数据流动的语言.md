# 线性代数：数据流动的语言

> 大模型中的"数据"就是向量和矩阵。矩阵乘法是数据流动的基本操作。这一章不堆公式，只讲直觉。

---

## 1. 向量：三种视角理解同一个东西

你可以把向量理解为三个概念的统一体：

**视角一：箭头**。一个从原点出发指向某处的箭头。在二维平面中，向量 `[3, 2]` 就是从 (0,0) 指向 (3,2) 的箭头。

**视角二：坐标**。一个点的位置。`[3, 2]` 就是平面上的一个点。

**视角三：列表**。一组数字。`[3, 2]` 就是一个长度为 2 的列表。

这三种理解在大模型中都有用：
- **箭头视角**：两个向量的夹角 → 语义相似度
- **坐标视角**：向量在空间中移动 → 矩阵变换
- **列表视角**：每个 token 用一串数字表示 → Embedding

---

## 2. 矩阵：一个"变换机器"

### 这玩意儿干嘛的

输入一个向量 → 输出另一个向量。矩阵就是一个"变换规则"——按照某种规则把输入空间的坐标映射到输出空间。

打个比方：矩阵像一个翻译器。输入一个中文句子（向量），输出一个英文句子（向量）。矩阵内部编码了"翻译规则"。

### 用数字感受一下

```python
# 一个 2×3 的矩阵
A = [[1, 0, 2],
     [0, 1, 1]]

# 一个 3 维输入向量
x = [2, 3, 1]

# A × x = 把 3 维空间中的 (2,3,1) 映射到 2 维空间
# 结果 = [1*2 + 0*3 + 2*1,  0*2 + 1*3 + 1*1] = [4, 4]
```

输入是 3 维的，输出是 2 维的。矩阵把空间"压扁"或"拉伸"了。

### 在大模型中的体现

```python
# Embedding 矩阵：把 token ID 映射到 768 维向量
embedding = nn.Embedding(vocab_size=32000, embedding_dim=768)
# 本质就是一个 [32000, 768] 的矩阵
# 输入 token ID 5 → 取矩阵第 5 行 → 得到一个 768 维向量
```

## 3. 矩阵乘法：批量加权求和

### 这玩意儿干嘛的

你买了 3 件商品：
- 2 斤苹果（每斤 5 元）
- 1 斤香蕉（每斤 3 元）
- 4 斤橘子（每斤 4 元）

总价 = 2×5 + 1×3 + 4×4 = 29 元

这就是**加权求和** —— 每个物品的"量"乘以它的"权重"，然后求和。

矩阵乘法就是**批量地做加权求和**。每一行输出 = 输入各分量的一次加权求和。

```
矩阵乘法 A × B = C:
- C[i][j] = 矩阵 A 的第 i 行（权重）× 矩阵 B 的第 j 列（数据）做内积
- 本质就是 "拿着第 i 行的权重，对第 j 列的数据做加权求和"
```

### 为什么这很重要

大模型的所有层本质上都在做矩阵乘法：
- Embedding: Token ID → 查矩阵取一行
- Attention: Q × K^T → 算相似度
- FFN: 输入 × W_up → 升维

**记住这个就够了**：矩阵乘法 = 批量加权求和。一个新向量的每个分量，是旧向量所有分量的加权组合。

## 4. 点积：衡量"方向一致程度"

### 直观理解

想象两个箭头从原点出发：
- 指向完全相同 → 点积 = 两个长度相乘（最大正值）
- 指向完全相反 → 点积 = 负的两个长度相乘（最大负值）
- 恰好垂直 → 点积 = 0（完全无关）

```
a·b = |a| × |b| × cos(θ)
            ↑
       夹角的余弦值

同方向: cos(0°)  = 1  → 点积最大
垂直:   cos(90°) = 0  → 点积为 0
反方向: cos(180°)= -1 → 点积最负
```

### 为什么 Attention 用点积

Attention 机制需要计算"Query 和 Key 有多匹配"——这恰好就是点积的行为！

```
Query (查询) · Key (键) = 一个数字，表示"Query 想要的内容"和"Key 提供的内容"的匹配程度
数值大 → 匹配好 → 这条信息值得关注
数值小 → 匹配差 → 这条信息可以忽略
```

这是整个 Transformer 的核心——**用点积来分配"注意力"**。

## 5. 维度思维：在大脑中画 3D 图

大模型代码中最需要的能力是**随时追踪 tensor 的形状变化**。读代码时，建议你拿着笔在旁边写 shape：

```python
# 大模型代码中常见的形状变化流水线

input_ids:   [batch, seq_len]            # 32 句话，每句 512 个 token
          ↓ Embedding
hidden:      [batch, seq_len, d_model]   # 每个 token 变成了 4096 维向量
          ↓ Attention 分头
Q,K,V:       [batch, num_heads, seq_len, d_head]  # 32 头 × 128 维 = 4096
          ↓ Q × K^T
scores:      [batch, num_heads, seq_len, seq_len] # 每个 token 对每个 token 的注意力
          ↓ scores × V
output:      [batch, num_heads, seq_len, d_head]  # 加权聚合后的特征
```

**有个小窍门**：把你想象成数据。你是 `[32, 512, 4096]` 这个形状的数据。你在每一层经过什么样的"工厂加工"？每个操作之后你的形状变成了什么？跟着"你"的旅程走，就能理解整个模型。

## 6. 转置：行列互换

### 这玩意儿干嘛的

把矩阵的行变成列，列变成行。就像把一张表格横过来看。

```python
# 转置前
[[1, 2, 3],
 [4, 5, 6]]   # shape: [2, 3]

# 转置后
[[1, 4],
 [2, 5],
 [3, 6]]      # shape: [3, 2]
```

### 为什么 Q × K^T 要做转置

```python
# Q: [batch, heads, seq_len, d_head]
# K: [batch, heads, seq_len, d_head]  ← 需要转置

# Q × K^T → [batch, heads, seq_len, seq_len]
#          每个 token 对每个 token 的匹配分数

# 为什么必须转置？
# 矩阵乘法要求 [m, n] × [n, p]
# Q 的最后一维是 d_head，乘以 K 的最后一维也必须是 d_head
# 但我们需要每个 seq 位置对每个 seq 位置算点积
# 所以把 K 转成 [batch, heads, d_head, seq_len]
# Q[batch, heads, seq_len, d_head] × K^T[batch, heads, d_head, seq_len]
#   → [batch, heads, seq_len, seq_len] ✓
```

`K.transpose(-2, -1)` —— 这就是你在每个 Attention 实现中都会看到的一行。

## 本章速查

| 概念 | 一句话解释 | 在大模型中 |
|------|----------|-----------|
| **向量** | 一串数字（箭头/坐标/列表） | token 的表示 |
| **矩阵** | 变换规则（把向量从旧空间映射到新空间） | 所有层的参数都是矩阵 |
| **矩阵乘法** | 批量加权求和 | Attention、FFN、Embedding 都是 |
| **点积** | 两个向量方向一致的程度 | Query-Key 匹配分数 |
| **转置** | 行列互换 | `K^T` 让矩阵乘法维度对上 |
| **shape 追踪** | 在脑中维护数据形状变化 | 读懂模型代码的核心能力 |

**记住这个就够了**：大模型的每一层都在做"矩阵乘法"——输入一个向量（或一批向量），用矩阵（层的参数）把它们变换到新空间。整个过程就是一个巨大的矩阵乘法流水线。
