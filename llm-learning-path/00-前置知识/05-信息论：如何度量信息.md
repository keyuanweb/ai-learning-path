# 信息论：如何度量"信息"

> 为什么 "明天地震" 比 "明天天晴" 信息量大？大模型用"交叉熵"作为损失函数——要理解为什么交叉熵能衡量预测质量，你需要先理解"信息量"这个概念。

---

## 1. 信息量：消息有多"意外"

### 哪条消息信息量大？

- **消息 A**："明天太阳从东边升起"
- **消息 B**："明天有 8 级地震"

直觉：消息 B 的信息量大得多。为什么？因为消息 A 几乎肯定发生（不意外），消息 B 极其罕见（很意外）。

**信息量 = 意外程度 = 概率的负对数**

$$
I(x) = -\log_2 P(x)
$$

用几个例子感受一下：

| 事件 | 概率 | 信息量 (bits) |
|------|------|-------------|
| 太阳从东边升起 | 0.9999 | ≈ 0.00014 |
| 掷骰子出 6 | 1/6 | ≈ 2.6 |
| 抛硬币正面 | 0.5 | 1.0 |
| 行人被陨石击中 | 0.00001 | ≈ 16.6 |

**核心直觉**：越不可能发生的事，一旦发生了，带给你的"信息量"越大。

这里有个重要的细节——如果你说"太阳从西边升起"，而我真的看到太阳从西边升起了，那这信息量就巨大了（因为这种事的概率几乎为 0）。

---

## 2. 熵：平均有多"意外"

### 这玩意儿干嘛的

一个消息源的混乱程度。熵高 → 消息不可预测，熵低 → 消息很单调。

### 用两个城市类比

| 城市 A（沙漠） | 城市 B（正常） |
|-------------|------------|
| 晴 90%、阴 5%、雨 3%、暴风雨 1%、雪 1% | 晴 30%、阴 25%、雨 20%、暴风雨 15%、雪 10% |
| 熵 ≈ 0.57 | 熵 ≈ 2.22 |

城市 A 的天气几乎总是"晴"，所以天气预报基本无价值，熵低。城市 B 的天气变化多端，天气预报有价值，熵高。

### 用骰子类比

- **公平骰子**（每个面概率 1/6）→ 熵最高 → 完全不可预测
- **灌铅骰子**（面 6 概率 99%，其他面合起来 1%）→ 熵很低 → 几乎总是出 6

**熵的公式**：

$$
H = -\sum_i P(x_i) \log P(x_i)
$$

翻译成人话：**把所有可能结果的"概率 × 意外程度"加起来**。结果越大，系统越不可预测。

---

## 3. 交叉熵：你以为的 vs 真实差距

### 这玩意儿干嘛的——大模型的损失函数

这是整个大模型训练中最核心的数学概念。

**你有两个概率分布**：
1. **真实分布 P**：正确答案是什么（比如，下一个词 100% 是 "光"）
2. **预测分布 Q**：模型认为下一个词可能是什么（它给了每个词一个概率）

**交叉熵 = 用预测分布 Q 来"描述"真实分布 P 的"成本"**

直觉：如果模型猜得很准（Q 在正确词的概率接近 1），这个成本就小。如果模型猜错了（Q 在正确词的概率接近 0），这个成本就很大。

### 用例子感受

真实答案：下一个词是 "光"（P("光") = 1, P(其他) = 0）

| 模型的预测 Q("光") | 交叉熵 Loss | 模型表现 |
|-------------------|------------|---------|
| 0.99 | -log(0.99) ≈ 0.01 | 几乎对了，loss 很小 |
| 0.5 | -log(0.5) ≈ 0.69 | 犹豫不决，loss 中等 |
| 0.1 | -log(0.1) ≈ 2.3 | 方向错了，loss 很大 |
| 0.001 | -log(0.001) ≈ 6.9 | 完全错了，loss 巨大 |

**关键洞察**：当模型在正确 token 上的预测概率从 0.1 提升到 0.5 时，loss 从 2.3 降到 0.69（大幅下降）。但当它从 0.9 提升到 0.99 时，loss 只从 0.1 降到 0.01（小幅下降）。

这很符合直觉：**从全错到半对是巨大进步，从半对到更好是逐步优化。**

---

## 4. KL 散度：两个分布有多不像

### 这玩意儿干嘛的

KL 散度衡量"你在用 Q 近似 P 时，损失了多少信息"。

$$
KL(P \parallel Q) = \text{交叉熵}(P, Q) - \text{熵}(P)
$$

翻译成人话：**交叉熵 = 真实分布的熵 + KL 散度**。因为真实分布的熵是固定的（数据决定了），最小化交叉熵等价于最小化 KL 散度。两者都在做同一件事——让 Q 尽量接近 P。

### 在大模型中

训练一个语言模型时：
- **P** = 真实的 token 分布（训练数据中这个位置就是某个词，概率 1）
- **Q** = 模型预测的 token 分布
- **目标** = 让 Q 在正确词上的概率尽量高 → 交叉熵尽量小

---

## 5. 困惑度 PPL：把熵翻译成人话

### 这玩意儿干嘛的

Loss = 2.3，这是好还是差？PPL 把 loss 映射到一个有直观含义的数：

$$
\text{PPL} = e^{\text{Loss}}
$$

| PPL | 含义 |
|-----|------|
| 1 | 完美模型（每一步都 100% 确定下一个词是什么） |
| 10 | 模型平均在 10 个词之间纠结 |
| 100 | 模型在 100 个词之间纠结——质量很差 |
| 32000 | 完全随机猜（等于词表大小） |

打个比方：你玩猜词游戏，你每猜一个词时内心有多少个"候选"。你每次只纠结 3-4 个候选时（PPL=3~4），说明你很懂语言；每次纠结几十个候选时（PPL=30~50），说明你不太行。

这是业界衡量语言模型质量的统一标准——PPL 越低越好。

---

## 6. 整个训练的终极目标一句话

> 大模型训练 = 最小化下一个 token 预测的交叉熵 = 最大化正确 token 的预测概率 = 降低困惑度

所有几百亿美元的算力投入，无数工程师的毕生心血，都指向这一个简洁的公式：

```python
loss = F.cross_entropy(model_output_logits, true_next_token)
loss.backward()        # 朝着让 loss 更小的方向更新所有参数
optimizer.step()
```

## 本章速查

| 概念 | 一句话解释 |
|------|----------|
| **信息量** | 消息的"意外程度"——概率越低 → 信息量越大 |
| **熵** | 系统的"混乱程度"——熵高 = 难预测 |
| **交叉熵** | 用预测分布描述真实分布的"编码成本" |
| **KL 散度** | "用 Q 代替 P 有多亏"——两个分布的差异 |
| **困惑度 PPL** | 把交叉熵翻译成"模型平均纠结几个词" |
| **为什么用交叉熵** | 交叉熵 + Softmax → 梯度 = 预测 - 真实（最简洁优美的梯度公式） |

**记住这个就够了**：大模型训练的本质是让模型在正确 token 上的预测概率尽量高。交叉熵就是衡量"预测和真实差多远"的尺子。
