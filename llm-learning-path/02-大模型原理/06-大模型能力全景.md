# 大模型能力全景

> 大模型的能力远不止"生成文本"。理解每项能力"如何产生"和"解决什么"，才能知道该在哪个环节投入资源。

---

## 1. In-Context Learning (ICL)：无需微调的任务执行

### 解决什么问题

传统 ML：每个新任务需要标注数据 + 微调模型。标注成本高，微调周期长，不可能实时适应新任务。

ICL 让模型**通过 prompt 中的几个示例，零参数更新地完成新任务**。

### 工作机制

模型在预训练期间见过海量的隐式"模式→答案"映射。ICL 本质是利用 Attention 机制的**模式匹配**能力：prompt 中的示例激活了模型内的相关模式，模型将模式应用到新的输入上。

```
"英语→法语:
 hello → bonjour
 world → monde
 goodbye → [模型预测: au revoir]"
```

### 为什么这是"涌现"的

小模型（<6B）的 ICL 准确率接近随机猜测。但参数超过 ~10B 时，ICL 能力突然跃升。这是因为 ICL 需要模型内部形成特定的计算回路（如"归纳头"——识别并复制模式），这些回路只在足够规模后才能稳定形成。

## 2. Chain-of-Thought (CoT)：逐步推理

### 解决什么问题

直接的"问题→答案"模式在多步推理任务（数学、逻辑、规划）上失败——模型需要中间的推理步骤来"思考"。

### 工作机制

在 prompt 中加入推理链作为示范，引导模型也输出中间步骤：

```
"Q: 小明有5个苹果，吃了2个，又买了3个，还剩几个？
A: 小明开始时有5个。
    他吃了2个，所以5-2=3个。
    他又买了3个，所以3+3=6个。
    答案是6个苹果。"

"Q: 一个班级有30人，男生比女生多6人，男生有多少人？
A: [模型开始逐步推理...]"
```

### CoT 的关键发现

- **规模阈值**：CoT 只在 50B+ 模型上有效（小模型加了 CoT 也推不出来）
- **正确性不一定需要正确推理**：有时模型给出正确推理链但答案错误，或推理错但答案对
- **Self-Consistency** 进一步提升：让模型生成多条推理链 → 投票选出最一致的答案

## 3. Tool Use (Function Calling)

### 解决什么问题

大模型有知识截止日期、无法进行精确计算、不能访问实时数据。Tool Use 让模型**调用外部工具来弥补这些缺陷**。

### 工作机制

模型学会输出特定格式的指令（通常是 JSON），外部系统解析并执行：

```
用户: "北京今天天气怎么样？"

模型输出:
{"tool": "get_weather", "args": {"city": "北京", "date": "today"}}

外部系统执行: 调用天气API → 返回结果
模型接收结果: "北京今天晴转多云，温度18-28°C"
```

### 为什么 Tool Use 需要训练

纯预训练模型不会输出结构化的工具调用指令。需要**特殊的微调数据**（对话+工具调用格式）来教会模型这个"约定"。

## 4. Agent 能力：规划和工具编排

### 解决什么问题

单一的工具调用不够——复杂任务需要**多步骤规划 + 多种工具的组合使用**。

### 工作机制

Agent = LLM + 规划 + 工具使用 + 记忆 + 反思

```
任务: "帮我分析这季度的销售数据并写份报告"

1. 规划: "我需要: ①拉取数据 ②统计分析 ③生成图表 ④撰写报告"
2. 执行: 依次调用 tool(sql_query) → tool(data_analysis) → tool(chart_gen) → LLM写作
3. 反思: "图表显示Q3下降, 我应该在报告中强调这点"
4. 输出: 综合所有步骤的最终报告
```

### Agent 的当前局限

- **规划不稳定**：多步规划中容易"跑偏"，中间步骤可能产生错误参数
- **工具调用幻觉**：可能调用不存在的工具或给错误的参数
- **长任务漂移**：超过~20步后，模型倾向于偏离原始目标

## 5. 指令跟随 (Instruction Following)

### 解决什么问题

预训练模型只会"补全文本"，不会"执行指令"。"写一首关于春天的诗"对预训练模型来说是"你正在看的文本恰巧以这句话开头"——它会继续写下去，但不会"响应"指令。

### SFT 的作用

监督微调 (SFT) 通过在「指令→理想回答」对上训练，教会模型"指令→执行"的映射：
- 格式对齐：输入是指令，输出应该是响应
- 风格转换：从"互联网文本"风格转为"助手"风格
- 安全约束：学会拒绝有害请求

### RLHF / DPO 的进一步对齐

SFT 让模型学会了"回答"但不一定"好用"。RLHF/DPO 进一步优化：
- 有用性：回答是否解决了用户的问题
- 真实性：是否编造事实（幻觉）
- 安全性：是否拒绝有害请求
