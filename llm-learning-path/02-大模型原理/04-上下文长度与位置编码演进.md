# 上下文长度与位置编码演进

上下文窗口从 512 token 扩展到 128K 甚至百万级别，这个技术路线代表了大模型领域最重要的进展之一。

---

## 1. 为什么需要长上下文

### 问题场景

| 上下文需求 | 场景 |
|-----------|------|
| 4K | 短对话、单篇文章翻译 |
| 8-16K | 标准对话、RAG 检索增强 |
| 32K-128K | 整本书摘要、完整代码库理解、长文档问答 |
| 128K+ | 超长多轮对话、学术文献综述、超长代码分析 |

### 核心矛盾

长上下文的需求 vs Attention 的 $O(n^2)$ 复杂度。序列长度翻倍，Attention 计算量翻 4 倍。这是为什么早年的模型都是 512-2048 的上下文窗口。

---

## 2. RoPE 的外推难题

### 问题

RoPE 在训练时只见过 [0, 4095] 的位置。训练好的模型学会了在这些位置上的旋转角度对应的注意力模式。但推理时要求 [0, 131071] 的位置——模型从未见过相距 50000 个位置的两个 token 应该如何交互。

### 为什么不能直接"往外用"

RoPE 每两个维度旋转的角度为 $\theta_i = base^{-2i/d} \times pos$。当 pos 远超训练范围时：
- 某些高频维度的旋转角度可能超过 $2\pi$（绕了一圈回到原处）
- 模型无法区分"距离 10 个位置"和"距离 10 + 周期长度 个位置"
- 这导致了长距离上的"混淆"——注意力模式退化为噪声

---

## 3. 外推技术：从粗暴到精细

### 位置插值 (Position Interpolation)：最直接

```python
# 把超出训练范围的位置"压缩"回训练范围内
pos_new = pos_old * (4096 / 131072)  # 128K → 压缩到 4K
```

**解决的问题**：让超出训练范围的位置也有"意义"。

**产生的新问题**：近距离区分度下降——原来相邻两个词的相对距离是 1，现在变成了 0.031。模型无法区分紧邻词和稍微远一点的词。局部信息受损严重。

### NTK-Aware Scaling：保留局部分辨率

**核心思想**：不改变位置索引，而是改变 RoPE 的 base 频率。

```python
# 高频维度保持"快转"（保留局部分辨率）
# 低频维度让它们"更慢"（覆盖更长的距离范围）
alpha = target_len / train_len
base_new = base_old * (alpha ** (d / (d - 2)))
```

- 高频维度：本身周期就短 → 不需要太多调整 → 局部分辨率保留
- 低频维度：周期调整 → 可以覆盖更长的距离
- 相当于让不同频率"分工"：高频负责近距离精细区分，低频负责远距离位置关系

### YaRN：NTK + 温度校准

NTK 解决了位置区分的问题，但引入了一个新问题：长序列上注意力分布变得过于"平坦"——token 不知道应该关注谁，注意力权重分散。

YaRN 在 NTK 缩放后，对 softmax 输入除以一个温度因子：

$$\text{Attention} = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k} \cdot \tau}\right)$$

- $\tau > 1$ → 注意力分布更尖锐 → 模型能聚焦到最相关的 token
- 相当于在说："序列很长时，你需要更果断地选择关注谁"

**YaRN 是目前公认效果最好的 RoPE 外推方法。**

### Dynamic NTK：运行时自适应

不在训练时固定 base，推理时根据实际序列长度动态调整：

```python
if cur_seq_len > train_len:
    scale = cur_seq_len / train_len
    base = base * scale ** (d / (d - 2))
```

**解决的问题**：不同推理请求的序列长度变化很大（有的是 200 token，有的是 100K token），固定一个 base 不够——短序列浪费了高分辨率的潜力，长序列又不够。

## 4. 方法论：训练时就考虑长上下文

与其训练 4K 然后用外推强行拉到 128K，更好的做法是**在训练后期引入长文本数据**：

```
阶段1: 用 4K 长度的数据完成大部分预训练（最便宜）
阶段2: 用少量 32K-128K 的数据继续训练（如 1B tokens）
阶段3: 配合 RoPE 大 base (500000-1000000) 或 YaRN
```

这样模型既学会了基础的语言能力（阶段 1），又有了长上下文处理能力（阶段 2），且不会因为全程长文本训练而浪费算力。

---

## 5. 未来方向：还需要位置编码吗？

NoPE (No Position Encoding) 实验发现：Decoder-Only 模型的因果掩码本身就包含了位置信息（token 只能看到左边 → 左边 token 的数量 = 位置）。去掉位置编码后长度外推更好，但需要更多训练数据来补偿。

这个方向在 2025 年仍处于探索阶段，但提示了位置编码可能不是永恒的必需组件。
