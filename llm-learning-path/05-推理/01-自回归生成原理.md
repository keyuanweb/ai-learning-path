# 自回归生成原理

推理就是将训练好的模型用于生成文本。这个过程看似简单，但采样策略的选择决定了生成质量。

---

## 1. 自回归生成的本质

### 问题

训练时模型是一次性看到完整序列，推理时序列是逐步构建的。每个新 token 的生成依赖之前所有已生成的 token。

```python
def autoregressive_generate(model, prompt, max_new_tokens):
    tokens = tokenizer.encode(prompt)
    for _ in range(max_new_tokens):
        logits = model(tokens)          # 完整的 forward pass
        next_logits = logits[-1, :]     # 只取最后一个位置
        next_token = select(next_logits) # 采样策略
        tokens.append(next_token)
        if next_token == eos_id:
            break
    return tokenizer.decode(tokens)
```

**关键**：每生成一个 token，需要重新做一次完整的 Attention 计算（所有历史 token 两两之间都要算）。这就是为什么推理是 $O(n^2)$ 的，也是 KV Cache（下一章）为什么如此重要。

---

## 2. 采样策略解决的问题

### Greedy（贪婪解码）

每次选概率最高的 token：

```python
next_token = torch.argmax(logits, dim=-1)
```

**问题**：确定性输出 + 没有"冒险"精神 → 容易陷入重复循环。对翻译等确定性任务尚可，对创意写作是灾难。

### Temperature（温度采样）

$$P(w_i) = \text{softmax}\!\left(\frac{\text{logits}}{T}\right)_i$$

| T | 效果 | 适用 |
|---|------|------|
| $T \to 0$ | 近乎 greedy | 翻译、事实问答 |
| $T = 0.7-0.8$ | 适度的随机性 | 通用对话 |
| $T = 1.0$ | 原始分布 | 创意写作 |
| $T > 1.0$ | 长尾 token 概率增加 | 需要高度多样性时 |

**作用机制**：温度降低分布的标准差，让高概率 token 更突出（低 T）或更平滑（高 T）。不是直接改变"谁更好"，而是改变"好多少"。

### Top-k Sampling

只保留概率最高的 k 个 token，其余概率置零后重新归一化：

```python
top_k_values, top_k_indices = torch.topk(logits, k)
logits_filtered = torch.full_like(logits, float('-inf'))
logits_filtered.scatter_(-1, top_k_indices, top_k_values)
probs = softmax(logits_filtered / T)
```

**解决的问题**：防止从长尾中采到完全不合语法的 token。

**问题**：k 是固定的。对某些位置，候选 pool 可能太大（100 个合理 token 但被截到 50），对另一些位置又太小（只剩 2 个候选但 k=50）。

### Top-p (Nucleus Sampling)

动态选择最小的 token 集合，使其累积概率 ≥ p：

```python
sorted_probs, _ = torch.sort(probs, descending=True)
cumulative = torch.cumsum(sorted_probs, dim=-1)
cutoff_idx = (cumulative > p).nonzero()[0]
logits[probs < sorted_probs[cutoff_idx]] = float('-inf')
```

**解决的问题**：Top-k 的僵硬。当分布很集中时（只有 3 个 token 总概率 0.95），top-p 就只保留 3 个；当分布平坦时（100 个 token 各 ~0.01），top-p 保留 ~100 个。

## 3. 组合策略

推荐组合：**Temperature + Top-p + Repetition Penalty**

```python
def sample_next_token(logits, temperature=0.8, top_p=0.95, repetition_penalty=1.1):
    # 1. 温度
    logits = logits / temperature

    # 2. 重复惩罚：对已出现的 token 降低概率
    for token_id in generated_ids:
        logits[token_id] /= repetition_penalty

    # 3. Top-p 过滤
    probs = softmax(logits)
    sorted_probs, sorted_indices = torch.sort(probs, descending=True)
    cumulative = torch.cumsum(sorted_probs, dim=-1)
    cutoff = sorted_probs[(cumulative > top_p).nonzero()[0]]
    logits[probs < cutoff] = float('-inf')

    # 4. 采样
    probs = softmax(logits)
    return torch.multinomial(probs, 1)
```

### 重复惩罚

```python
# 对已在上下文中的 token 施加惩罚
logits[token_id] /= repetition_penalty  # 通常 1.05-1.2
```

**解决的问题**：模型倾向于"陷入循环"——生成过的词在上下文中出现后，模型认为它们更"合理"（因为上下文包含这些词），于是在下一个位置继续生成它们，形成自我强化的循环。

---

## 4. Beam Search

### 解决的场景

需要"整体最优"的场合（翻译、OCR 纠正），而非按 token 贪心。

```
Greedy: 每次选最优 → 可能错过"前两步不是最优但整体最优"的路径
Beam Search: 同时维护 k 条候选路径 → 综合考虑全局得分
```

### 计算方式

```python
beam_size = 4
beams = [(0.0, [bos_token])]  # (score, tokens)

for step in range(max_len):
    new_beams = []
    for score, tokens in beams:
        logits = model(tokens)
        top_k_logprobs, top_k_ids = torch.topk(F.log_softmax(logits[-1]), beam_size)
        for lp, tid in zip(top_k_logprobs, top_k_ids):
            new_beams.append((score + lp, tokens + [tid]))
    beams = sorted(new_beams, reverse=True)[:beam_size]
```

**问题**：在大模型推理中不常用，因为需要维护多条序列的 KV Cache → 显存开销 × beam_size。对对话和创意生成，beam search 效果反而不如采样（因为重复问题更突出）。

---

## 5. 采样策略选择

| 任务 | 策略 | 参数 |
|------|------|------|
| 事实问答 | Greedy 或 T=0.1 | top_p=1.0 |
| 通用对话 | Temperature + Top-p | T=0.7, p=0.9 |
| 创意写作 | Temperature + Top-p | T=0.9, p=0.95 |
| 翻译 | Beam Search | beam=4, T=1.0 |
| 代码生成 | Greedy 或 T=0.2 | top_p=0.9 |
| 避免重复 | + Repetition Penalty | 1.05-1.2 |
