# DPO 偏好对齐

SFT 教会模型"回答问题"，DPO (Direct Preference Optimization) 教会模型"回答得更好"。这是从"能用"到"好用"的关键一步。

---

## 1. SFT 的局限：为什么需要偏好对齐

### SFT 能做的事

SFT 训练数据："法国的首都是什么？→ 巴黎"

模型学到：看到问首都，回答首都。这是**模仿**——模型学会了数据中"怎么做"。

### SFT 做不到的事

现实中同一个问题可能有多个回答，质量参差不齐：

```
Q: "帮我写一封辞职邮件"
A1: "好的，这是辞职邮件模板：尊敬的领导..." (好)
A2: "辞职？你确定要辞职吗？我建议你三思..." (不请自来的建议)
A3: "辞职邮件很简单，我写好了：我辞职，再见。" (过于敷衍)
```

SFT 把所有回答都当作"正确答案"来学习，无法区分 A1 > A2 > A3。

**偏好对齐要解决的就是这个问题：教会模型分辨"好回答"和"更好的回答"。**

---

## 2. DPO 的原理：直接优化偏好

### 传统 RLHF 的痛点

RLHF (Reinforcement Learning from Human Feedback) 的传统流程：
1. 训练一个奖励模型（需要大量人工标注打分）
2. 用 PPO 强化学习优化模型（训练不稳定、超参数敏感）
3. 反复迭代（工程复杂）

### DPO 的简化

DPO 将整个偏好对齐**直接转化为一个分类损失**，一步到位：

$$\mathcal{L}_{DPO} = -\log \sigma\!\left(\beta \log\frac{\pi_\theta(y_w|x)}{\pi_{ref}(y_w|x)} - \beta \log\frac{\pi_\theta(y_l|x)}{\pi_{ref}(y_l|x)}\right)$$

- $y_w$：更好的回答 (win)
- $y_l$：较差的回答 (lose)
- $\pi_\theta$：当前模型
- $\pi_{ref}$：参考模型（SFT 后的模型，被冻结）
- $\beta$：控制偏离参考模型的程度

### 直觉解释

这个损失函数在做一件事：**让"好回答"在当前模型下的概率相对参考模型上升，让"坏回答"的概率下降**。

$$\text{希望: } \frac{\pi_\theta(y_w)}{\pi_{ref}(y_w)} > \frac{\pi_\theta(y_l)}{\pi_{ref}(y_l)}$$

如果当前模型給好回答的概率比参考模型高，且坏回答的概率比参考模型低，损失就小。反之就惩罚。

### DPO 为什么不需要奖励模型

DPO 通过数学推导将奖励函数**消去了**——损失函数只依赖于当前模型和参考模型对好/坏回答的概率比。不需要单独训练一个奖励模型，不需要 PPO 强化学习，只需要偏好数据对 (win, lose)。

## 3. DPO 数据格式

```python
dpo_sample = {
    "prompt": "帮我写一封辞职邮件",
    "chosen": "好的，这是辞职邮件模板：[专业模板]",     # win
    "rejected": "辞职？你确定要辞职吗？建议你三思...",  # lose
}
```

### 数据来源

| 来源 | 方法 | 质量 |
|------|------|------|
| 人工标注 | 让人比较两个回答 | 最高，但贵 |
| GPT-4 打分 | 用最强模型评估质量 | 高，成本可控 |
| 规则 + 人工 | 自动发现问题（乱码、太短）+ 人工确认 | 中等 |
| 合成数据 | 生成 "好回答 → 故意破坏 → 坏回答" | 中等，但有分布偏差 |

## 4. DPO 训练配置

```python
from trl import DPOTrainer

dpo_trainer = DPOTrainer(
    model=model,                   # SFT后的模型
    ref_model=ref_model,           # SFT模型的冻结副本
    train_dataset=dpo_dataset,
    tokenizer=tokenizer,
    args=TrainingArguments(
        per_device_train_batch_size=4,
        learning_rate=5e-6,        # DPO的学习率很低！
        num_train_epochs=1,        # DPO通常在1个epoch内收敛
        bf16=True,
        optim="adamw_8bit",
    ),
    beta=0.1,                      # 控制偏离 ref_model 的程度
)
```

### β 的选择

| β 值 | 效果 |
|------|------|
| 0.01 | 激进优化偏好（可能大幅偏离 SFT 模型 → 遗忘或过度自信） |
| **0.1** | 常用默认值（平衡） |
| 0.5 | 保守（接近 ref_model，优化幅度有限） |

### DPO 的学习率为什么这么低

DPO 的目标是微调偏好，不是学习新能力。太高的学习率会导致模型"忘记"SFT 阶段学到的指令跟随能力。典型值 1e-6 ~ 5e-6（比 SFT 低 5-10 倍）。

## 5. DPO vs RLHF

| | DPO | RLHF (PPO) |
|---|---|---|
| **复杂度** | 简单（一个分类损失） | 复杂（4个模型 + PPO算法） |
| **训练稳定性** | 稳定 | 不稳定，需要大量调参 |
| **需要奖励模型** | 否 | 是 |
| **数据需求** | 偏好对 (win, lose) | 奖励标注 + 大量在线采样 |
| **效果** | 接近 RLHF | 理论上更灵活 |
| **工程实现** | 一行 trainer.train() | 多个组件需要协调 |

2024-2025 年 DPO 已经是多数开源模型的默认对齐方案。RLHF 在闭源前沿模型 (GPT-4, Claude) 中仍然使用，但开源的 DPO 效果已经足够好。
