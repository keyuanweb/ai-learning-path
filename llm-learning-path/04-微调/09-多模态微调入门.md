# 多模态微调入门

> 多模态 = 文本 + 图像 + 音频 + 视频。目前最成熟的是图文多模态。

---

## 1. 多模态模型要解决什么

### 问题

纯文本模型无法理解图片。用户发来一张表格截图问"这个表第三行的数据是多少？"，纯文本模型根本"看不见"图片。

### 核心思路：两个编码器 + 一个连接器

```
图片 → Vision Encoder (ViT/CLIP) → 图片特征
文字 → Text Tokenizer → Text Embedding → Transformer → 输出
                          ↑
                    图片特征投影后拼接
```

模型看到的序列：
```
[img_tokens × N] [text_token_1] [text_token_2] ...
```

图片被"翻译"成 N 个视觉 token，与文本 token 一起输入 Transformer。

---

## 2. LLaVA 架构：多模态的"Hello World"

### 组件

| 组件 | 作用 | 典型选择 |
|------|------|---------|
| **Vision Encoder** | 将图片编码为特征向量 | CLIP ViT-L (336×336) |
| **Projector** | 视觉特征 → 文本空间的投影 | 简单 MLP 或 Q-Former |
| **LLM** | 处理图文混合序列 | LLaMA/Qwen/DeepSeek |

### LLaVA 的训练两阶段

**阶段 1：特征对齐（只训练 Projector）**
```
输入: 图片 → [Vision Encoder] → [Projector] → [visual tokens] + [文本描述]
目标: 让 Projector 学会将视觉特征映射到文本 embedding 空间
冻结: Vision Encoder + LLM
```

**阶段 2：指令微调（训练 Projector + LLM）**
```
输入: [visual tokens] + "请描述这张图片"
输出: "图中有一只橘猫坐在窗台上，背景是阳光..."
目标: 端到端的多模态对话能力
冻结: Vision Encoder (通常)
```

## 3. 多模态微调的显存挑战

### 为什么更费显存

- **Vision Encoder** 额外占约 1-2 GB (ViT-L)
- **图片 tokens 多**：一张 336×336 图片生成约 576 个 visual tokens，等效于增加 576 个文本 token 的序列长度
- **多图片更夸张**：如果有 5 张图片 → 5 × 576 = 2880 visual tokens

### 多模态 LoRA

对 Vision Encoder 不微调（它只是提取视觉特征），只对 LLM 部分加 LoRA：

```python
lora_config = LoraConfig(
    r=16,  # 多模态建议略高的 rank
    target_modules=["q_proj", "v_proj", "o_proj"],  # +output projection
)

# Vision Encoder 保持冻结
for param in model.vision_encoder.parameters():
    param.requires_grad = False

# Projector 全参数微调（它比较小）
for param in model.projector.parameters():
    param.requires_grad = True
```

## 5. 多模态微调的应用场景

| 场景 | 数据需求 | 微调方法 |
|------|---------|---------|
| 图片描述 | (图片, 描述) 对 | LoRA |
| OCR/文档理解 | (文档截图, 结构化信息) | LoRA on Q+V |
| 图表分析 | (图表, 数据解读) | LoRA + Projector |
| 医学影像 | (X光/CT, 报告) | 全参数微调 (领域差异大) |
| 视觉问答 | (图片+问题, 答案) | LoRA (r=16-32) |

多模态微调是 2025 年增长最快的方向之一——随着视觉编码器和 Projector 技术的成熟，"看图说话"正在成为大模型的标配能力。
