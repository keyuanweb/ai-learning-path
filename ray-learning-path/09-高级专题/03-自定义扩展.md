# 自定义扩展

## 提出问题

Ray 的内置功能覆盖了大多数场景，但你可能需要：

- 自定义调度器（比如优先调度紧急任务）
- 自定义资源类型（比如管理"FPGA 设备"）
- 自定义容错逻辑（比如某个 Actor 挂了触发告警）
- 扩展 Ray Serve 的中间件

怎么在 Ray 上做这些自定义扩展？

## 自定义调度器

### 场景：带优先级的调度

```python
import ray
from ray.util.scheduling_strategies import NodeAffinitySchedulingStrategy

# 简单方式：自定义资源 + 节点亲和
@ray.remote(resources={"priority_high": 1})
def urgent_task():
    ...

@ray.remote  # 默认优先级
def normal_task():
    ...

# 集群启动时分配不同节点不同优先级
# ray start --resources='{"priority_high": 100}'
```

### 场景：自定义 Placement Strategy

```python
# 实现自定义的放置策略（需要修改 Ray 源码级别）
# 一般通过 Placement Group + 自定义逻辑来实现

from ray.util.placement_group import placement_group

def custom_schedule(task_specs, cluster_state):
    """自定义调度逻辑"""
    # task_specs: 待调度的 Task 列表
    # cluster_state: 集群当前状态（节点、资源）

    allocation = {}
    for task in task_specs:
        # 自定义逻辑：比如大模型优先放有大 GPU 显存的节点
        if task.gpu_memory_required > 40:  # 40GB
            candidate = find_node_with_large_gpu_memory(cluster_state)
        else:
            candidate = find_least_loaded_node(cluster_state)

        allocation[task.id] = candidate.node_id

    return allocation
```

## 自定义 Ray Serve 中间件

### 请求日志中间件

```python
from ray import serve
from starlette.middleware.base import BaseHTTPMiddleware
import time

class LoggingMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        start = time.time()
        response = await call_next(request)
        duration = time.time() - start
        print(f"{request.method} {request.url.path} - {duration:.3f}s")
        response.headers["X-Process-Time"] = str(duration)
        return response

app = FastAPI()
app.add_middleware(LoggingMiddleware)

@serve.deployment
@serve.ingress(app)
class MyService:
    @app.post("/predict")
    async def predict(self, request: Request):
        ...
```

### 认证中间件

```python
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.responses import JSONResponse

class AuthMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        token = request.headers.get("Authorization")

        if not token or not validate_token(token):
            return JSONResponse(
                {"error": "Unauthorized"},
                status_code=401
            )

        request.state.user = get_user_from_token(token)
        return await call_next(request)

app = FastAPI()
app.add_middleware(AuthMiddleware)
```

### 请求速率限制

```python
from ray import serve
import asyncio
import time

class RateLimiter:
    def __init__(self, max_requests_per_second: int):
        self.max_rate = max_requests_per_second
        self.tokens = max_requests_per_second
        self.last_refill = time.time()
        self.lock = asyncio.Lock()

    async def acquire(self):
        async with self.lock:
            now = time.time()
            elapsed = now - self.last_refill
            self.tokens = min(
                self.max_rate,
                self.tokens + elapsed * self.max_rate
            )
            self.last_refill = now

            if self.tokens >= 1:
                self.tokens -= 1
                return True
            return False

@serve.deployment
class RateLimitedModel:
    def __init__(self):
        self.limiter = RateLimiter(100)  # 100 QPS

    async def __call__(self, request):
        if not await self.limiter.acquire():
            return {"error": "Rate limit exceeded"}
        return self.model(await request.json())
```

## 自定义容错和告警

### Actor 崩溃告警

```python
import ray
import requests

@ray.remote(max_restarts=3)
class MonitoredActor:
    def __init__(self):
        self.setup_monitoring()

    def setup_monitoring(self):
        # 注册析构钩子（Actor 崩溃时触发）
        import atexit
        atexit.register(self.on_crash)

    def on_crash(self):
        # 发送告警到 Slack/PagerDuty
        requests.post(
            "https://hooks.slack.com/services/xxx",
            json={"text": "⚠️ Actor crashed!"}
        )

    def work(self):
        ...
```

### 自定义 Checkpoint 策略

```python
import ray.train
from ray.train import Checkpoint

class CustomCheckpointStrategy:
    def __init__(self, save_interval_minutes=30, keep_last_n=3):
        self.save_interval = save_interval_minutes * 60
        self.keep_last_n = keep_last_n
        self.last_save = time.time()
        self.checkpoints = []

    def maybe_save(self, model, optimizer, metrics):
        now = time.time()
        if now - self.last_save >= self.save_interval:
            self._save(model, optimizer, metrics)
            self.last_save = now

    def _save(self, model, optimizer, metrics):
        with tempfile.TemporaryDirectory() as tmpdir:
            torch.save({
                "model": model.state_dict(),
                "optimizer": optimizer.state_dict(),
                "metrics": metrics,
            }, f"{tmpdir}/checkpoint.pt")

            checkpoint = Checkpoint.from_directory(tmpdir)
            ray.train.report(metrics, checkpoint=checkpoint)

            # 保留最近 N 个
            self.checkpoints.append(checkpoint)
            if len(self.checkpoints) > self.keep_last_n:
                # 删除最旧的 checkpoint
                old = self.checkpoints.pop(0)
                # Ray 的 checkpoint 存储会自动管理删除
```

## 扩展 Ray Data

### 自定义数据源

```python
from ray.data import Datasource, ReadTask

class KafkaDatasource(Datasource):
    def __init__(self, bootstrap_servers, topic):
        self.bootstrap_servers = bootstrap_servers
        self.topic = topic

    def get_read_tasks(self, parallelism: int):
        # 将 Kafka partition 分配到 Ray ReadTask
        partitions = self._get_partitions()
        return [
            ReadTask(
                read_fn=lambda p=p: self._read_partition(p),
                metadata={}
            )
            for p in range(parallelism)
        ]

    def _read_partition(self, partition_id):
        from kafka import KafkaConsumer
        consumer = KafkaConsumer(
            self.topic,
            bootstrap_servers=self.bootstrap_servers,
            group_id=f"ray-datasource-{partition_id}"
        )
        for msg in consumer:
            yield msg.value

# 使用
ds = ray.data.read_datasource(
    KafkaDatasource("localhost:9092", "ml-events"),
    parallelism=8
)
```

## 扩展策略

| 需求 | 扩展方式 | 难度 |
|------|---------|------|
| 调度优化 | Placement Group + 自定义资源 | 低 |
| 新的资源类型 | `ray.init(resources={...})` | 低 |
| 请求中间件 | Starlette/FastAPI 中间件 | 低 |
| 自定义容错 | atexit + 外部告警 | 低 |
| 自定义数据源 | Datasource 接口 | 中 |
| 算法级调度变更 | 修改 Ray Core | 高 |
| 新的 AI 库 | 基于 Core API 构建 | 中-高 |

## 常见陷阱

### 1. 在 Task 内部修改全局状态

```python
# ❌ Ray Task 中修改模块级变量
COUNTER = 0

@ray.remote
def increment():
    global COUNTER
    COUNTER += 1  # 这个 COUNTER 和别的 Task 的 COUNTER 不是同一个！
    return COUNTER

# ✅ 用 Actor 管理全局状态
@ray.remote
class Counter:
    def __init__(self):
        self.count = 0
    def increment(self):
        self.count += 1
        return self.count
```

### 2. 自定义中间件引入性能问题

```python
# ❌ 在中间件中做同步阻塞操作
class SlowMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        # 同步 sleep → 阻塞整个 event loop
        time.sleep(0.1)
        return await call_next(request)

# ✅ 用异步操作
class FastMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        await asyncio.sleep(0.001)  # 异步
        return await call_next(request)
```

## 小结

- 自定义资源是最简单的扩展（`ray.init(resources={...})`）
- Placement Group 可以模拟复杂的调度需求
- FastAPI 中间件给 Ray Serve 加认证、限流、日志
- `atexit` 钩子实现 Actor 崩溃告警
- Ray Data 支持自定义数据源（`Datasource` 接口）
- 深层的 Core 修改一般不需要——Ray 的原语已经非常灵活
