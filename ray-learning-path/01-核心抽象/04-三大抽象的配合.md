# 三大抽象的配合

## 提出问题

我们已经分别了解了 Task、Actor、Object。但真实应用很少只用其中一个。一个典型的 ML 工作流是：

1. **加载数据** → 放对象存储
2. **预处理** → 用 Task 并行处理
3. **训练模型** → 用 Actor 持有模型
4. **分布式评估** → Task 并行推理
5. **聚合结果** → Actor 汇总

如何让这三者无缝协作？

## 核心模式

### 模式 1：Task → Object → Task（管道模式）

最常见的 ETL 管道：数据在不同 Task 之间流动。

```python
@ray.remote
def extract(source):
    return read_from_source(source)     # 返回数据

@ray.remote
def transform(data_ref):
    data = ray.get(data_ref)
    return clean(data)                  # 返回处理后数据

@ray.remote
def load(data_ref, destination):
    data = ray.get(data_ref)
    write_to_dest(data, destination)

# 构建管道
raw_ref = extract.remote("s3://bucket/raw")
clean_ref = transform.remote(raw_ref)
done_ref = load.remote(clean_ref, "s3://bucket/clean")

ray.get(done_ref)
```

> **类比**：这像工厂流水线——原料（Object）从上一道工序流出，进入下一道工序。每道工序（Task）不关心原料从哪来、要去哪，只负责自己的加工。传送带（Object Store）负责搬运。

### 模式 2：Task + Actor → 异步训练（客户-服务员模式）

```python
@ray.remote(num_gpus=1)
class Trainer:
    def __init__(self):
        self.model = create_model().cuda()
        self.optimizer = torch.optim.Adam(self.model.parameters())

    def train_step(self, batch_ref):
        batch = ray.get(batch_ref)
        loss = compute_loss(self.model, batch)
        self.optimizer.zero_grad()
        loss.backward()
        self.optimizer.step()
        return loss.item()

    def get_weights(self):
        return self.model.state_dict()

@ray.remote
def data_worker(storage_ref):
    # 从对象存储加载数据，预处理
    data = ray.get(storage_ref)
    return preprocess(data)

# 协作
trainer = Trainer.remote()
data_ref = ray.put(raw_dataset)

for epoch in range(10):
    # data_worker 并行准备下一批数据
    batch_ref = data_worker.remote(data_ref)
    # 同时 Trainer 用当前数据训练
    loss = ray.get(trainer.train_step.remote(batch_ref))
    print(f"Epoch {epoch}, Loss {loss}")

final_weights = ray.get(trainer.get_weights.remote())
```

> **类比**：Actor (Trainer) 像厨房主厨，不断接收食材 (Object)、加工、出菜。Task (data_worker) 像采购员，在厨房外并行采购和预加工食材送进来。

### 模式 3：多 Actor + Object 共享（黑板模式）

```python
@ray.remote
class ParameterServer:
    def __init__(self):
        self.params = initialize_params()

    def push_gradients(self, grads):
        self.params = update(self.params, grads)

    def pull_parameters(self):
        return self.params

@ray.remote(num_gpus=1)
class Learner:
    def __init__(self, ps_handle):
        self.ps = ps_handle
        self.local_model = create_model().cuda()

    def learn(self, batch_ref):
        batch = ray.get(batch_ref)
        params = ray.get(self.ps.pull_parameters.remote())
        self.local_model.load_state_dict(params)
        grads = compute_gradients(self.local_model, batch)
        self.ps.push_gradients.remote(grads)

# 创建 1 个参数服务器 + N 个学习者
ps = ParameterServer.remote()
learners = [Learner.remote(ps) for _ in range(8)]

# 并行训练
batch_ref = ray.put(training_data)
futures = [l.learn.remote(batch_ref) for l in learners]
ray.get(futures)
```

> **类比**：ParameterServer 像是办公室的**白板**——Learner 们各自看完白板去算出新想法（梯度），回来把新想法写在白板上。所有人看到的都是最新的白板内容。

### 模式 4：Actor → Actor 直接通信

```python
@ray.remote
class Producer:
    def produce(self, consumer_handle):
        for i in range(100):
            data = generate_data(i)
            consumer_handle.consume.remote(data)  # 直接发给 Consumer

@ray.remote
class Consumer:
    def __init__(self):
        self.results = []

    def consume(self, data):
        self.results.append(process(data))

    def get_results(self):
        return self.results

consumer = Consumer.remote()
producer = Producer.remote()
producer.produce.remote(consumer)
```

Actor 之间可以直接传递 Handle 进行通信——不需要经过中间对象存储。

## 协作时的工作原理

### 依赖自动解析

当你在一个 `.remote()` 调用中传入了 ObjectRef 或 Actor Handle，Ray 会自动分析依赖关系：

```
Task_C.remote(obj_ref_from_A, actor_ref_B)
                │                  │
                ▼                  ▼
         等 Task_A 完成      等 Actor_B 空闲
                │                  │
                └──────┬───────────┘
                       ▼
               Task_C 才开始执行
```

你不需要手动管理依赖，Ray 的**有向无环图 (DAG) 引擎**自动处理。

### 数据在节点间的流动

```
场景1：同节点 Task → Task
  Task_A (节点1) → Plasma(节点1) → Task_B (节点1)
  方式：零拷贝（共享内存指针）

场景2：跨节点 Task → Task
  Task_A (节点1) → Plasma(节点1) → 网络 → Plasma(节点2) → Task_B (节点2)
  方式：Ray 自动处理序列化+传输

场景3：Actor 接收 ObjectRef
  Actor (节点2).method.remote(obj_ref_on_node1)
  Ray 自动将 obj 从节点1传到节点2
```

### 引用计数与生命周期

Ray 使用**分布式引用计数**来管理对象的生命周期：

```python
@ray.remote
def creator():
    return [1, 2, 3]       # 引用计数 = 1 (返回给调用者)

@ray.remote
def consumer(ref):
    data = ray.get(ref)     # 引用计数 +1 (consumer 使用中)
    process(data)
    # consumer 完成，引用计数 -1

ref = creator.remote()      # 调用者持有 ref
consumer.remote(ref)        # consumer 也持有 ref
del ref                     # 调用者释放，引用计数 -1
# 引用计数归零 → GC 回收
```

## 设计决策指南

| 你的需求 | 推荐模式 | 理由 |
|----------|----------|------|
| 并行处理独立数据块 | Task | 无状态、自动分布、简单 |
| 模型常驻内存做推理 | Actor | 模型加载一次，持续服务 |
| 多个 Worker 共享参数 | Actor + Actor | 参数服务器模式，黑板更新 |
| ETL 管道 | Task → Task | 自然的数据流，自动依赖 |
| 在线服务 | Actor | 持续运行、状态持久 |
| 大批量数据共享 | `ray.put()` | 一次序列化，多方复用 |
| 流式处理 | Actor + Actor | 生产者-消费者直连 |

## 小结

- Task、Actor、Object 三者是互补的，真实应用都是混用
- Task 负责无状态计算，Actor 负责有状态服务，Object 是它们之间的"通用语言"
- Ray 的 DAG 引擎自动解析依赖，你只管传 ObjectRef
- 同节点数据零拷贝，跨节点自动传输
- 分布式引用计数保证对象不被过早回收
- 三种原语组合出的四种经典模式覆盖绝大多数 ML 场景
