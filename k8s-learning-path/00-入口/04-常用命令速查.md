# 常用命令速查

## kubectl 通用格式

```bash
kubectl [verb] [resource-type] [resource-name] [flags]

# verb:   get / describe / create / apply / delete / edit / logs / exec / rollout / scale / top / cordon / drain / taint / label / annotate
# resource-type:  pods / deployments / services / nodes / namespaces / configmaps / secrets / pv / pvc / ingress / events ...（支持缩写，见下文）
```

## 资源缩写对照

| 全称 | 缩写 | 全称 | 缩写 |
|---|---|---|---|
| pods | `po` | persistentvolumes | `pv` |
| deployments | `deploy` | persistentvolumeclaims | `pvc` |
| services | `svc` | configmaps | `cm` |
| namespaces | `ns` | secrets | —（无缩写） |
| nodes | `no` | ingresses | `ing` |
| replicasets | `rs` | serviceaccounts | `sa` |
| statefulsets | `sts` | horizontalpodautoscalers | `hpa` |
| daemonsets | `ds` | poddisruptionbudgets | `pdb` |
| jobs | — | networkpolicies | `netpol` |
| events | `ev` | customresourcedefinitions | `crd` |

## Pod 相关

```bash
# 查看
kubectl get po -n <ns>                      # 列出 Pod（缩写 po = pods）
kubectl get po -n <ns> -o wide              # 含节点 IP、容器镜像
kubectl get po -n <ns> -o yaml              # 完整 YAML 输出
kubectl get po -n <ns> -l app=nginx         # 按标签筛选
kubectl get po -n <ns> --sort-by=.status.startTime  # 按启动时间排序
kubectl get po -A                           # 所有 namespace
kubectl get po -A --field-selector spec.nodeName=worker01  # 指定节点上的 Pod

# 详情
kubectl describe po <name> -n <ns>          # Events 排障最关键来源
kubectl get events -n <ns> --sort-by=.lastTimestamp  # 汇总 Events

# 实时监控
kubectl get po -n <ns> -w                   # watch 实时变化
kubectl top po -n <ns>                      # CPU / 内存用量（需 metrics-server）

# 操作
kubectl delete po <name> -n <ns>            # 删除单个 Pod（Deployment 会重建）
kubectl delete po -n <ns> -l app=nginx      # 按标签批量删除
kubectl delete po <name> -n <ns> --force --grace-period=0  # 强制立即删除
```

## Deployment 相关

```bash
# 创建
kubectl create deploy nginx --image=nginx:alpine -n <ns> --replicas=3

# 查看
kubectl get deploy -n <ns>
kubectl describe deploy <name> -n <ns>      # 看滚动更新策略、Conditions
kubectl get rs -n <ns>                      # 查看关联的 ReplicaSet

# 更新
kubectl set image deploy/<name> <container>=<new-image> -n <ns>
kubectl edit deploy <name> -n <ns>          # 在线编辑 YAML

# 扩缩容
kubectl scale deploy/<name> --replicas=5 -n <ns>

# 滚动更新控制
kubectl rollout status deploy/<name> -n <ns>         # 等待更新完成
kubectl rollout history deploy/<name> -n <ns>        # 查看历史版本
kubectl rollout undo deploy/<name> -n <ns>           # 回滚到上一版本
kubectl rollout undo deploy/<name> --to-revision=3 -n <ns>  # 回滚到指定版本
kubectl rollout restart deploy/<name> -n <ns>        # 重启所有 Pod（滚动重建）

# 暂停/恢复（用于批量修改，减少滚动更新次数）
kubectl rollout pause deploy/<name> -n <ns>
kubectl set image deploy/<name> app1=v2 app2=v3 -n <ns>  # 批量改
kubectl rollout resume deploy/<name> -n <ns>
```

## 日志与调试

```bash
# 日志
kubectl logs <pod> -n <ns>                      # 单容器 Pod
kubectl logs <pod> -c <container> -n <ns>       # 多容器 Pod 指定容器
kubectl logs <pod> -n <ns> --previous           # 上一次容器日志（用于 CrashLoopBackOff）
kubectl logs <pod> -n <ns> --tail=100           # 最后 100 行
kubectl logs <pod> -n <ns> --since=5m           # 最近 5 分钟
kubectl logs -f <pod> -n <ns>                   # follow 实时输出
kubectl logs -l app=nginx -n <ns> --all-containers  # 按标签聚合日志
kubectl logs deploy/<name> -n <ns>              # Deployment 级别（自动选 Pod）

# 进入容器
kubectl exec -it <pod> -n <ns> -- /bin/sh
kubectl exec -it <pod> -c <container> -n <ns> -- /bin/bash

# 不进入容器执行单条命令
kubectl exec <pod> -n <ns> -- cat /etc/resolv.conf
kubectl exec <pod> -n <ns> -- nslookup kubernetes.default

# 端口转发
kubectl port-forward <pod> 8080:80 -n <ns>                   # Pod 级别
kubectl port-forward svc/<svc> 8080:80 -n <ns>               # Service 级别
kubectl port-forward deploy/<name> 9000:9090 -n <ns>         # Deployment 级别

# 文件复制
kubectl cp <pod>:/path/file ./local-file -n <ns>             # Pod → 本地
kubectl cp ./local-file <pod>:/path/file -n <ns>             # 本地 → Pod
kubectl cp <pod>:/path/dir ./local-dir -n <ns> --retries=3  # 目录递归复制

# 临时调试容器（1.23+）
kubectl debug <pod> -n <ns> --image=busybox --target=<container> -it -- sh
kubectl debug node/<node> -it --image=busybox -- sh          # 以特权 Pod 调试节点
```

## Service 与网络

```bash
# 查看
kubectl get svc -n <ns>
kubectl get svc -A                                     # 所有 namespace
kubectl describe svc <name> -n <ns>                    # 看 Endpoints 是否正常关联 Pod
kubectl get endpoints <name> -n <ns>                   # 查看后端 Pod IP 列表
kubectl get ep -n <ns>                                 # 简写

# 创建
kubectl expose deploy <name> --port=80 --target-port=8080 -n <ns>
kubectl expose deploy <name> --type=NodePort --port=80 -n <ns>
kubectl create svc clusterip <name> --tcp=80:8080 -n <ns>

# Ingress
kubectl get ing -A
kubectl describe ing <name> -n <ns>

# NetworkPolicy
kubectl get netpol -n <ns>
```

## 节点相关

```bash
kubectl get nodes                                      # 节点列表
kubectl get no -o wide                                 # 含 IP、OS、内核版本
kubectl describe node <name>                           # 资源容量、Conditions、Taints
kubectl top nodes                                      # 节点 CPU/内存用量

# 维护操作
kubectl cordon <node>                                  # 标记不可调度（已有 Pod 不驱逐）
kubectl drain <node> --ignore-daemonsets               # 安全驱逐所有 Pod 并标记不可调度
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data  # 含 emptyDir 数据
kubectl uncordon <node>                                # 恢复可调度

# 污点与标签
kubectl taint node <node> key=value:NoSchedule         # 添加污点，拒绝无容忍 Pod
kubectl taint node <node> key=value:NoSchedule-        # 删除污点（末尾加 -）
kubectl label node <node> workload=app                 # 添加标签
kubectl label node <node> workload-                    # 删除标签（末尾加 -）
```

## RBAC 与安全

```bash

kubectl get sa -n <ns>

```

## 批量与进阶

```bash
# YAML 批量操作
kubectl apply -f dir/                               # apply 整个目录
kubectl apply -f manifest.yaml -n <ns>
kubectl apply -k dir/                               # kustomize 方式
kubectl delete -f manifest.yaml -n <ns>

# dry-run 预览
kubectl apply -f manifest.yaml --dry-run=client     # 语法检查不实际执行
kubectl create deploy nginx --image=nginx --dry-run=client -o yaml  # 生成 YAML 模板

# JSONPath 提取
kubectl get no -o jsonpath='{.items[*].status.addresses[0].address}'
kubectl get po -n <ns> -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.podIP}{"\n"}{end}'
kubectl get po -n <ns> -o custom-columns='POD:.metadata.name,IP:.status.podIP,NODE:.spec.nodeName'

# 聚合操作
kubectl get po -A --sort-by=.metadata.creationTimestamp | tail -5  # 最新创建的 Pod

# 批量为节点打标签
for node in worker01 worker02 worker03; do
  kubectl label node $node workload=app
done

# 批量重启某 Deployment 下的所有 Pod
kubectl rollout restart deploy -n <ns>

# 导出所有 Pod YAML（备份）
kubectl get po -A -o yaml > all-pods.yaml
```

## 输出格式速查

| 格式 | 用途 |
|---|---|
| `-o wide` | 额外列（节点、IP、镜像） |
| `-o yaml` | 完整 YAML 定义 |
| `-o json` | JSON 输出，可管道给 jq |
| `-o name` | 仅输出资源路径（如 `pod/nginx-xxx`），便于管道 |
| `-o jsonpath='{...}'` | 自定义字段提取 |
| `-o custom-columns=...` | 自定义表格列 |
| `-o go-template='{{...}}'` | Go 模板，jsonpath 不满足时使用 |
| `--show-labels` | 所有 get 命令都能加，显示标签列 |

## 常见组合场景

```bash
# 场景 1：Pod 挂了快速排障
kubectl get po -n <ns>                         # 看状态
kubectl describe po <name> -n <ns>             # 看 Events（镜像拉取？资源不够？调度失败？）
kubectl logs <pod> -n <ns> --previous          # 看上一次崩溃日志

# 场景 2：确认滚动更新是否成功
kubectl rollout status deploy/<name> -n <ns>   # 阻塞等待
kubectl get rs -n <ns>                         # 新 RS 扩容到期望数，旧 RS 缩到 0

# 场景 3：排查 Service 不通
kubectl get svc <name> -n <ns>                 # 看 CLUSTER-IP / PORT
kubectl get ep <name> -n <ns>                  # 看后端 Pod IP 是否正确
kubectl describe svc <name> -n <ns>            # 看 selector 是否匹配 Pod labels

# 场景 4：节点维护
kubectl cordon worker01                        # 先标记不可调度
kubectl drain worker01 --ignore-daemonsets --delete-emptydir-data  # 安全驱逐
# ... 执行维护 ...
kubectl uncordon worker01                      # 恢复

# 场景 5：找哪个 Pod 消耗最多 CPU
kubectl top po -A --sort-by=cpu | head -10

# 场景 6：查看集群总资源
kubectl top nodes
kubectl describe nodes | grep -A5 "Allocated resources"
```

## 小结

- `describe` + `logs --previous` 是排障两个入口命令
- `-o wide` 和 `--show-labels` 可以加在几乎所有 get 命令上
- `rollout` 系列（status / history / undo）管理滚动更新的完整生命周期
- `cordon / drain / uncordon` 是节点维护的标准三步
- `kubectl explain <resource>` 可以直接在终端查资源字段定义，比查网页快
