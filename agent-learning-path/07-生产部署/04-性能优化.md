# 性能优化

## 优化全景

LangGraph Agent 的性能优化覆盖：Prompt 缓存、并行执行、模型分层、上下文压缩、Checkpoint 策略。

## 1. Prompt Caching

Anthropic 和 OpenAI 都支持 Prompt 缓存，对长 System Prompt 和工具定义可显著降低成本。

```python
from langchain_openai import ChatOpenAI
from langchain_anthropic import ChatAnthropic

# Anthropic Claude 自动缓存（需要超过 1024 token 的前缀）
llm = ChatAnthropic(
    model="claude-sonnet-4-6",
    max_tokens=4096,
    # System prompt 和 tools 定义会自动被缓存
)

# 缓存收益估算
# 场景：System Prompt (2000 tokens) + Tools 定义 (1500 tokens)
# 没缓存：每次都发送 3500 tokens 前缀
# 有缓存：第一次发送后，后续只发送新的 user message
# 节省：~90% 的前缀 token 成本
```

### 手动控制缓存断点

```python
from langchain_core.caches import InMemoryCache
from langchain_core.prompts import ChatPromptTemplate

# 使用 cache 断点标记（Anthropic）
system_prompt = (
    "你是一个助手。\n"
    "规则1：...\n"
    "规则2：...\n"
)

# System Prompt 放在 Messages 的最前面，会被自动缓存
messages = [
    ("system", system_prompt),
    ("user", "{input}")  # 变化的用户输入在缓存断点之后
]
```

## 2. 并行节点优化

LangGraph 自动并行执行没有依赖关系的节点（Fan-out）：

```python
# 这些节点会并行执行，不需要额外配置
builder.add_edge("A", "B")
builder.add_edge("A", "C")
builder.add_edge("A", "D")
# B、C、D 会同时开始执行

# 等待所有完成后才到 E
builder.add_edge("B", "E")
builder.add_edge("C", "E")
builder.add_edge("D", "E")
```

## 3. 模型分层策略

```python
# 不同任务使用不同成本的模型
model_config = {
    "routing": ChatOpenAI(model="gpt-4o-mini"),     # 简单分类
    "planning": ChatOpenAI(model="gpt-4o"),          # 复杂规划
    "execution": ChatOpenAI(model="gpt-4o-mini"),    # 工具调用
    "synthesis": ChatOpenAI(model="gpt-4o"),         # 最终输出
}

# 场景和推荐模型
"""
意图分类    → gpt-4o-mini / claude-haiku-4-5 (~$0.15/1M tokens)
工具调用    → gpt-4o-mini / claude-haiku-4-5
推理/规划   → gpt-4o / claude-sonnet-4-6 (~$3/1M tokens)
最终输出    → gpt-4o / claude-sonnet-4-6
"""

# 成本对比（单次 Agent 调用）
# 全用 gpt-4o：~$0.05
# 混合策略：~$0.01
# 节省 80%
```

## 4. 上下文压缩

当对话历史过长时，需要压缩上下文。

### SummarizationMiddleware

```python
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model=llm,
    tools=tools,
    middleware=[
        SummarizationMiddleware(
            max_tokens=4000,  # 超过此阈值触发摘要
            summary_prompt="将以下对话历史压缩为关键信息："
        )
    ]
)
```

### 手动上下文压缩

```python
def compress_context(messages: list, max_tokens: int = 4000) -> list:
    """压缩对话历史"""
    # 估算当前 token 数（简单估算：1 token ≈ 4 字符）
    total_chars = sum(len(str(m.content)) for m in messages)
    estimated_tokens = total_chars / 4

    if estimated_tokens <= max_tokens:
        return messages

    # 保留最近的 N 条消息 + 摘要
    summary_llm = ChatOpenAI(model="gpt-4o-mini")

    old_messages = messages[:-6]  # 除了最近 6 条
    recent_messages = messages[-6:]

    summary_prompt = f"将以下对话历史压缩为 200 字以内的摘要：\n{old_messages}"
    summary = summary_llm.invoke(summary_prompt).content

    return [
        {"role": "system", "content": f"[对话历史摘要] {summary}"},
        *recent_messages
    ]
```

## 5. Checkpoint 策略

```python
# MemorySaver：开发用，重启丢失
from langgraph.checkpoint.memory import MemorySaver
graph = builder.compile(checkpointer=MemorySaver())

# SqliteSaver：单机生产，持久化
from langgraph.checkpoint.sqlite import SqliteSaver
with SqliteSaver.from_conn_string("checkpoints.db") as cp:
    graph = builder.compile(checkpointer=cp)

# PostgresSaver：分布式生产
from langgraph.checkpoint.postgres import PostgresSaver
with PostgresSaver.from_conn_string(os.environ["DATABASE_URL"]) as cp:
    graph = builder.compile(checkpointer=cp)

# 性能对比
# MemorySaver: 最快，但不持久 ~0.1ms
# SqliteSaver: ~1-5ms，适合单机
# PostgresSaver: ~5-20ms，适合分布式
```

## 6. LLM 调用优化

```python
# 降低 Temperature 减少随机性（不直接提升性能但减少重试）
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0.0)

# 限制 max_tokens（防止过长的响应）
llm = ChatOpenAI(model="gpt-4o-mini", max_tokens=1024)

# 减少不必要的 LLM 调用
def router(state):
    # 先用简单规则判断
    if "退款" in state["query"]:
        return "billing"         # 无 LLM 调用
    if "登录" in state["query"]:
        return "account"         # 无 LLM 调用
    # 复杂情况才用 LLM
    return llm_router(state)    # LLM 调用
```
