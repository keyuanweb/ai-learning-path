# 渐进式披露与层级覆盖

## 渐进式披露（Progressive Disclosure）

这是 Skills 系统最核心的设计模式。它解决了"工具/Skill 太多导致上下文爆炸"的问题。

### 工作原理

```
第一次加载：只读 YAML frontmatter 元数据
┌──────────────────────────────┐
│ name: arxiv-search           │
│ description: 搜索学术论文... │  ← ~50-100 tokens
│ allowed-tools: [web_search]  │
└──────────────────────────────┘
         │
         │ Agent 决定使用 → 加载完整内容
         ▼
┌──────────────────────────────┐
│ # ArXiv 论文研究 Skill        │
│ ## 执行流程                   │
│ ### 步骤 1：搜索论文          │
│ ...                          │  ← ~2000 tokens
│ ## 输出格式                   │
│ ...                          │
└──────────────────────────────┘
```

### 性能对比

假设一个 Agent 有 20 个 Skill，每个平均 5KB：

| 模式 | 首次 Prompt Token | 说明 |
|------|------------------|------|
| 全量加载 | ~25,000 | 上下文直接爆掉 |
| 渐进式披露 | ~2,000 | 只有元数据，按需加载正文 |

### SkillsMiddleware 核心逻辑

```python
class SkillsMiddleware(AgentMiddleware):
    """渐进式披露的实现核心"""

    def __init__(self, backend, sources: list[str]):
        self._backend = backend
        # 启动时只加载元数据（YAML frontmatter）
        self._skills_metadata = self._load_all_metadata(sources)
        # 缓存：skill_name → full_content（懒加载）
        self._skill_content_cache: dict[str, str] = {}

    def _load_all_metadata(self, sources: list[str]) -> list[dict]:
        """扫描所有 SKILL.md，只解析 YAML frontmatter"""
        metadata_list = []
        for source in sources:
            for skill_dir in self._backend.list_dirs(source):
                skill_md = self._backend.read_file(f"{skill_dir}/SKILL.md")
                frontmatter = self._parse_frontmatter(skill_md)
                metadata_list.append({
                    "name": frontmatter["name"],
                    "description": frontmatter["description"],
                    "path": skill_dir
                })
        return metadata_list

    def modify_request(self, request):
        """第一次只注入元数据列表"""
        skills_intro = self._format_skills_intro()
        # skills_intro ≈ "可用 Skill: arxiv-search(搜索论文), paper-analyzer(分析论文)..."
        request.system_prompt += f"\n\n{skills_intro}"
        return request

    def _get_skill_full_content(self, skill_name: str) -> str:
        """Agent 真正决定使用时才加载完整 SKILL.md"""
        if skill_name not in self._skill_content_cache:
            path = self._skill_paths[skill_name]
            full = self._backend.read_file(f"{path}/SKILL.md")
            self._skill_content_cache[skill_name] = full
        return self._skill_content_cache[skill_name]
```

## 层级覆盖（Layered Skills）

支持从多个来源加载 Skill，后加载的同名 Skill 覆盖前面的。

### 基础用法

```python
agent = create_deep_agent(
    model=model,
    backend=LocalShellBackend(root_dir="."),
    skills=[
        "./skills/base/",        # 第一层：公司基础规范
        "./skills/team/",        # 第二层：团队特定规则
        "./skills/project/",     # 第三层：项目定制流程（优先级最高）
    ],
)
```

### 企业级 Skill 分层体系

```
组织级 Skill 层级：

┌──────────────────────────────┐
│ Layer 1: 公司基础（company/） │
│ - 合规检查 Skill              │  ← 所有项目共享
│ - 审计日志 Skill              │
│ - 数据脱敏 Skill              │
└──────────┬───────────────────┘
           │ 可被覆盖
┌──────────▼───────────────────┐
│ Layer 2: 团队约定（team/）    │
│ - SQL 查询 Skill              │  ← 数据团队特定
│ - 报表生成 Skill              │
│ - ETL 流程 Skill              │
└──────────┬───────────────────┘
           │ 可被覆盖
┌──────────▼───────────────────┐
│ Layer 3: 项目定制（project/） │
│ - 特定客户模板 Skill          │  ← 仅本项目
│ - 自定义数据源 Skill          │
└──────────────────────────────┘
```

### 覆盖行为示例

```python
# base/ 中定义
# skills/base/sql-query/SKILL.md
# name: sql-query
# allowed-tools: [query_db]
# 默认 LIMIT 100

# project/ 中覆盖
# skills/project/sql-query/SKILL.md
# name: sql-query          ← 同名，覆盖
# allowed-tools: [query_db, validate_sql]  ← 增加了校验工具
# 默认 LIMIT 500           ← 项目特定限制

agent = create_deep_agent(
    skills=["./skills/base/", "./skills/project/"],
    # project/ 中的 sql-query 覆盖 base/ 中的定义
)
```

## 与 LangSmith 集成追踪

```python
import os
os.environ["LANGCHAIN_TRACING_V2"] = "true"
os.environ["LANGCHAIN_API_KEY"] = "ls_..."

agent = create_deep_agent(
    model=model,
    backend=LocalShellBackend(root_dir="."),
    skills=["./skills"],
    checkpointer=InMemorySaver(),
)

# 每次 Skill 加载和使用在 LangSmith 中都有完整 Trace：
# ├── Agent.plan → 读取 Skills 元数据列表
# ├── Agent.decide → 选择 "arxiv-search" Skill
# ├── Skill.load → 读取完整 SKILL.md (仅此时)
# ├── Tool.use → web_search("site:arxiv.org ...")
# └── Agent.response → 返回结果
```

## 自定义 load_skill 工具模式

如果不想用 `create_deep_agent`，也可以手动实现渐进式披露：

```python
from typing import Annotated
import operator
from langgraph.types import Command

class SkillState(MessagesState):
    skills_loaded: Annotated[list[str], operator.add]

SKILLS_LIBRARY = {
    "arxiv-search": {
        "name": "arxiv-search",
        "description": "搜索 ArXiv 学术论文",
        "allowed_tools": ["web_search", "fetch_url"],
        "content": """# ArXiv 搜索 Skill
## 步骤
1. 使用 web_search 在 site:arxiv.org 搜索
2. 使用 fetch_url 获取详情
...""",
    },
    # ... 更多 Skills
}

# 始终对 Agent 可见的 Loader Tool
@tool
def load_skill(skill_name: str) -> str:
    """加载一个 Skill 的完整内容。可加载的 Skill: arxiv-search, paper-analyzer, citation-formatter"""
    skill = SKILLS_LIBRARY.get(skill_name)
    if not skill:
        return f"未找到 Skill: {skill_name}"
    return f"已加载 Skill [{skill_name}]:\n\n{skill['content']}"

# Agent 开始时只看到 load_skill 工具
# 加载后 Skill 内容进入上下文，Agent 开始使用 Skill 中描述的工具
```

## 最佳实践

| 实践 | 说明 |
|------|------|
| **名称为描述性** | `arxiv-search` 而非 `skill1` |
| **description 要精确** | 模糊描述导致 Agent 频繁错选 Skill |
| **分层组织** | 按功能分文件夹：`search/`、`analysis/`、`output/` |
| **层级覆盖用同名** | 同文件夹 + 同名 Skill = 覆盖机制 |
| **小写命名** | 文件夹名必须全小写（Deep Agent 限制） |
| **单 Skill 保持简洁** | 一个 Skill 做好一件事，复杂任务拆分为多个 Skill |

3. 实现一个手动 `load_skill` 模式（参考上面的自定义实现）
