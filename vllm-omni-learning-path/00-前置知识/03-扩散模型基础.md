# 03 · 扩散模型基础：DiT 与去噪过程

## 扩散模型做什么

扩散模型（Diffusion Model）是一种**通过"逐步去噪"来生成数据**的模型。它的核心思想很简单：

1. **训练时**：拿一张清晰的图片，一步步往上面加噪声，直到变成纯噪声。模型学习如何在每一步"逆转"这个过程。
2. **推理时**：从纯噪声开始，模型一步步去掉噪声，最终得到一张清晰的图片。

可以类比为雕刻：你不是直接刻出雕像，而是从一块"噪声石头"开始，一刀刀去掉多余的部分，最终露出成品。

## 为什么 vLLM-Omni 需要支持扩散模型

传统的 vLLM 只支持自回归（AR）模型——一种每次生成一个 token 的模式。但在图像、视频、音频生成领域，扩散模型（尤其是 DiT, Diffusion Transformer）已经占据了主导地位：

- **文生图**：Flux、SD3、Qwen-Image、Z-Image —— 都是 DiT 架构
- **文生视频**：Wan、LTX2、HunyuanVideo —— DiT 处理时空数据
- **音频/语音**：Stable Audio、AudioX、DreamID —— 扩散模型生成声音

这些模型都不是"逐 token 生成"的模式，vLLM 原生不支持。vLLM-Omni 的 Diffusion Engine 就是为此而生的。

## DiT（Diffusion Transformer）是什么

DiT 就是把扩散模型中的 U-Net（传统去噪网络）替换为 Transformer。这样做的好处是：

- Transformer 的扩展性更好（scaling law）
- 可以复用 vLLM 中为 Transformer 优化的各种技术
- 更容易做分布式（序列并行、张量并行等）

DiT 模型的一次前向过程：

```
噪声输入(z_t) + 条件(文本/图片)
        │
        ▼
  DiT Transformer（多层 Attention + FFN）
        │
        ▼
    预测的噪声(ε)
```

条件（condition）是什么？就是你输入的 prompt。比如文生图时，条件就是"一只坐在沙发上的猫"这个文本描述被编码器编码后的向量。

## 扩散推理的关键参数

| 参数 | 含义 | vLLM-Omni 中的位置 |
|------|------|-------------------|
| **steps** | 去噪步数，越多质量越好但越慢 | `num_inference_steps` |
| **guidance_scale** | 引导强度，控制模型"听 prompt 话"的程度 | `guidance_scale` |
| **CFG** | Classifier-Free Guidance，同时算条件和无条件两个路径 | `cfg_kv_request_ids` |
| **width/height** | 输出图像/视频尺寸 | `OmniDiffusionSamplingParams` |
| **seed** | 随机种子，控制生成的可复现性 | `seed` |
| **scheduler** | 去噪调度算法（DDIM、Euler、Flow Match 等） | `schedulers/` 目录 |

## 扩散模型的调度器（Scheduler）

注意不要和 vLLM 的请求调度器（Request Scheduler）混淆。这里的 Scheduler 指的是**去噪算法调度器**——它决定每一步去噪时的噪声强度（sigma/alpha）和计算方式。

vLLM-Omni 支持多种去噪调度器，位于 [`diffusion/models/schedulers/`](../../code/vllm-omni/vllm_omni/diffusion/models/schedulers/)，包括：

- **Flow Match Euler**：用于 Flux、Wan 等
- **Flow UniPC Multistep**：更快的多步求解器
- **DMD2 Euler**：用于蒸馏模型加速
- **Helios Scheduler**：Helios 模型专用

## CFG（Classifier-Free Guidance）在 vLLM-Omni 中的实现

CFG 需要同时计算两个路径：
1. 带文本条件的去噪（会生成和 prompt 相关的内容）
2. 不带条件的去噪（模型自由发挥）

然后将两个结果按 guidance_scale 混合。在 vLLM-Omni 中，条件路径和无条件路径可以**并行计算**——它们作为两个"companion request"分别提交给扩散引擎，完成后再合并。这个过程由 Orchestrator 的 `CfgCompanionTracker` 协调。

```
                    ┌─→ 条件路径 (with text prompt) ─┐
Orchestrator 提交   │                                ├→ 合并 → 下一步去噪
                    └─→ 无条件路径 (empty prompt) ───┘
```

## 扩散模型的 VAE（变分自编码器）

DiT 不在像素空间工作，而是在一个压缩的"潜空间"（latent space）工作：

- **Encoder（编码）**：图像 → 潜变量（尺寸缩小 8x，如 1024×1024 → 128×128）
- **DiT（去噪）**：在潜空间中一步步去噪
- **Decoder（解码）**：潜变量 → 图像（放大回原尺寸）

VAE 是 vLLM-Omni 扩散管线中不可或缺的一部分，支持分布式 VAE（`DistributedVaeMixin`）来并行编码/解码大尺寸图像。
