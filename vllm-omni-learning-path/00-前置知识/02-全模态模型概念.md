# 02 · 全模态模型概念：Thinker / Talker / Code2Wav

## 什么是全模态（Omni-Modality）模型

传统的 AI 模型各管一摊：LLM 处理文字，Stable Diffusion 生成图片，Whisper 做语音识别。全模态模型则是**一个模型搞定多种输入输出**——听你说话、看懂图片、用语音回答、甚至生成一段视频。

打个比方：传统模型是分工明确的流水线工人（一个只切菜，一个只炒菜），全模态模型是一个全能厨师，从切菜到出锅一人包办。

## 全模态模型的"三件套"架构

大多数全模态模型（以 Qwen-Omni 为代表）将模型拆成三个子模块：

```
用户的语音输入 →  [Thinker（思考者）]  →  理解内容，生成回复的文字
                              │
                              ├→ 生成"该怎么说"的控制信号（音频 Token）
                              │
                              ▼
                  [Talker（说话者）]  →  把控制信号转为声学特征
                              │
                              ▼
                  [Code2Wav（合成器）] →  把声学特征转为音频波形
                              │
                              ▼
                        用户听到语音回答
```

### Thinker（思考者）—— 模型的"大脑"

- **做什么**：理解输入（文字、图片、声音），推理后决定如何回复
- **用什么技术**：自回归（AR）Transformer，和普通 LLM 一样逐 token 生成
- **输出什么**：文本 token（回复的文字内容）+ 音频控制 code（告诉 Talker 该怎么说话）

Thinker 本质上就是一个"升级版 LLM"——不仅能理解文字，还能理解图片（通过视觉编码器）和声音（通过音频编码器）。它的输出除了文字 token，还有"说话指令"。

### Talker（说话者）—— 模型的"嘴巴"

- **做什么**：接收 Thinker 的控制信号，生成"声学特征"（抽象的声音表示）
- **用什么技术**：自回归模型或流匹配模型
- **输入是什么**：文本 token + 音频控制 code
- **输出是什么**：声学特征（mel-spectrogram 或音频 code）

Talker 的核心工作是"把文字变成声音的蓝图"——它不直接生成声音波形，而是生成一种中间表示，交给 Code2Wav。

### Code2Wav（合成器）—— 模型的"声带"

- **做什么**：将声学特征（抽象编码）转为可播放的音频波形
- **用什么技术**：神经声码器（如 HiFi-GAN）、扩散模型（DiT）、或流匹配模型
- **输入是什么**：Talker 输出的声学特征 / 音频 code
- **输出是什么**：PCM 音频波形（raw audio）

Code2Wav 是从"蓝图"到"实物"的最后一步。

## Stage 的抽象：不止三种

在 vLLM-Omni 的代码中，Stage 是一个**通用概念**，不限于 Thinker/Talker/Code2Wav。不同的模型有不同的 Stage 拆分方式：

| 模型 | Stage 拆分 | 各 Stage 功能 |
|------|-----------|-------------|
| Qwen2.5-Omni | Thinker → Talker → Token2Wav | 思考→说话→合成 |
| Qwen3-Omni | Thinker(MoE) → Talker(MoE) → Code2Wav | 同上，但用了 MoE |
| CosyVoice3 | AR → DiT | AR 生成音素→DiT 合成波形 |
| Fish Speech | SlowAR → FastAR → DAC Decoder | 慢 AR→快 AR→解码 |
| GLM-Image | AR → Diffusion | AR 生成 token→扩散生成图像 |
| HunyuanImage3 | AR → Diffusion | 同上模式 |

**关键理解**：vLLM-Omni 的多 Stage 设计不是硬编码的，而是通过"Pipeline"来声明模型的 Stage 关系。每个模型的 `pipeline.py` 文件定义了该模型有几个 Stage、每个 Stage 做什么、Stage 之间如何转换数据。

## Stage 类型：ar vs generation vs diffusion

每个 Stage 有一个 `worker_type` 属性，决定它在 GPU 上的执行方式：

- **ar**：自回归生成，逐 token 输出。用 vLLM 的 AR Worker + AR Scheduler
- **generation**：非自回归生成，一次输出一批 token/特征。用 Generation Worker
- **diffusion**：扩散模型，多次迭代去噪。用独立的 Diffusion Engine

约 20 分钟。理解 Thinker/Talker/Code2Wav 三元组是读懂 vLLM-Omni 代码的关键。
