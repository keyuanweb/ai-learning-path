# 上线检查清单

## 概述

上线前逐项确认，降低事故风险，保证**可控、可观测、可回滚**。

## 15 项检查表

| # | 检查项 | 达标标准 |
|---|--------|----------|
| 1 | 任务边界与目标 | 支持/不支持范围明确；成功标准、留痕要求清晰 |
| 2 | 上下文来源与质量 | 来源可追溯、可刷新；命中率可接受 |
| 3 | 工具权限最小化 | 仅暴露必要工具；敏感操作二次确认或 HITL |
| 4 | MCP 工具接入校验 | 服务稳定；超时重试；入参出参 Schema 校验 |
| 5 | Sandbox 执行环境 | 代码/命令在沙箱；CPU/内存/网络/耗时限制 |
| 6 | 文件操作与回滚 | 路径受限；关键操作前快照 |
| 7 | Human Review | 高风险清单；人工介入留痕 |
| 8 | 失败重试与退避 | 重试条件、次数、退避明确；幂等保障 |
| 9 | 回滚与补救 | 回滚触发条件与步骤；数据可恢复 |
| 10 | 日志与观测 | 结构化日志、Trace ID；成功率/延迟/错误率/成本 |
| 11 | 安全与合规 | 脱敏；权限审计；操作留痕 |
| 12 | 评测与质量门禁 | 核心+边界用例评测集；通过才放行 |
| 13 | 上线频率与灰度 | 灰度比例、观察周期明确 |
| 14 | 成本与配额 | 模型/工具成本可控；限流熔断 |
| 15 | 文档与交接 | 用户文档、运维手册、应急预案齐全 |

## 上线流程

```mermaid
flowchart LR
  s1[本地自测] --> s2[预发布验证]
  s2 --> s3[联合评审]
  s3 --> s4[灰度发布]
  s4 --> s5[全量发布]
```

## 风险分级

| 级别 | 后果 | 典型问题 |
|------|------|----------|
| 高 | 数据泄露、资金损失、服务中断 | 越权、无审核、无回滚 |
| 中 | 体验降级、成本飙升 | 幂等缺失、监控不全 |
| 低 | 局部效率影响 | 输出波动、日志不全 |

## TOP 事故模式（务必警惕）

- 权限过大、上下文污染、工具不稳定
- 沙箱失效、无人工审核、无回滚
- 无观测告警、成本失控

## 动手练习

1. 用 15 项清单评估一个你熟悉的 Agent 产品，标红未达标项
2. 写出灰度发布第 1 天应观察的 5 个指标
3. 选 3 项「必须项」，说明不达标不得上线的理由

## 常见坑

- **检查表走过场**：无 owner 签字
- **只测 Happy Path**：边界与对抗未覆盖
- **灰度跳过**：直接全量

## 小结

- **边界清晰 + 权限最小 + 可观测可回滚 + 人在回路 + 灰度先行** 是五大护栏
- 15 项清单是生产准入标准
- 评测通过 + 灰度观察通过才全量
