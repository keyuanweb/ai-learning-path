### 核心观点
- **标题**：没有 Harness 的 Agent 为什么不稳定？
- **副标题**：稳定的 Agent 不是靠模型能力，而是靠工程系统 (Harness) 兜底。

### 问题与解决方案对比表
表格列出了 10 个常见问题，对比了“裸 Agent”的表现与“Harness”的解决机制：

| # | 问题 | 裸 Agent 会怎样翻车 | Harness 如何兜底 (稳定来自工程) |
| :--- | :--- | :--- | :--- |
| 1 | **上下文错乱** | 聊天无信息上下文，忘记关键信息，输出跑题或前后矛盾 | 上下文管理器：清洗、压缩、分层、检索，只给有效且精简的摘要 |
| 2 | **工具参数错误** | 参数格式乱填、必填项漏、类型不匹配导致调用失败或报错 | 工具注册+参数校验：Schema 校验、必填校验、默认值、示例约束 |
| 3 | **权限过大** | 可执行高危操作，越权访问敏感数据或修改生产数据 | 权限控制：最小权限、审批流授权、敏感操作二次确认/降级/旁路 |
| 4 | **没有 Sandbox** | 直接操作真实环境，误删/覆盖/破坏系统，难以隔离影响 | 沙箱执行：隔离运行、只读/受限写入、模拟验证后再落地 |
| 5 | **任务状态丢失** | 中途断网、超时重启后，丢失上下文和进度，需要从头开始 | 状态管理：步骤持久化、进度记录、可恢复执行、断点续跑 |
| 6 | **无人审查** | 关键决策/高风险操作无人把关，错误结果直接对外造成损失 | 人工审查：关键节点触发、人工确认、可撤销流程（退回/问/停） |
| 7 | **无日志观测** | 出问题不知道原因，无法定位责任也无法持续优化 | 日志观测：结构化日志、链路追踪、指标监控、告警通知 |
| 8 | **无法重试** | 临时失败就放弃，成功率低，浪费人工尝试次数 | 重试机制：策略化重试（退避/抖动）、幂等保护、失败分类重试 |
| 9 | **无法回滚** | 操作一旦执行成功无法撤销，造成不可逆损害 | 回滚机制：前置快照、补偿事务、版本管理、回滚预案 |
| 10 | **目标难以保障** | 无约束、无评估，结果不符合预期，质量不一性 | 目标与评估：明确目标、输出校验、评测/模型评分对齐、质量门禁 |

### 执行流程对比图
图片中间部分展示了两种执行流程的对比：

#### 裸 Agent 执行流程 (容易翻车)
- **流程**：用户输入 → LLM 决策 → 直接调用工具/接口 → 执行结果 → 直接输出给用户
- **典型风险点**：
    - 信息混乱、理解偏差
    - 参数错误、调用失败
    - 权限过大、误删库
    - 中断丢失、从头开始
    - 无人审核、直接发布
    - 无日志、无法排查
    - 失败即止、无重试
    - 无法回滚、后果严重
- **结果**：**不确定、不可控、难排查、难恢复**

#### 有 Harness 执行流程 (稳定可控)
- **流程**：用户输入 → 意图理解 → 上下文管理 → 工具选择 & 参数校验 → 沙箱执行 & 权限控制 → 结果校验 & 多轮迭代 → 人工审查 (必要时) → 输出给用户
- **Harness 关键能力贯穿全程**：
    - √ 上下文管理
    - √ 工具注册与校验
    - √ 权限控制与审批
    - √ 人工审查
    - √ 日志监控与告警
    - √ 重试与补偿
    - √ 回滚与快照
- **结果**：**可预测、可观测、可追溯、可恢复**

### 什么时候必须上 Harness？——判断准则
底部列出了 5 个判断准则：
1. **涉及外部系统调用或敏感操作**
    - 读写数据库/文件
    - 调用外部 API
    - 发送消息/邮件
    - 发交易/支付/操作
2. **上下文依赖复杂或多轮交互**
    - 可能出错/遗漏
    - 需维护对话历史
    - 断网/中断场景
    - 需从中间恢复
3. **多步骤复杂任务链**
    - 需要按顺序分步执行
    - 某步可能失败
    - 需自动重试
    - 需要记录各步状态
4. **有人协作/对外交付**
    - 需要审核才能生效
    - 结果需可追溯
    - 责任需可界定
5. **追求自动化与规模化**
    - 需批量处理任务
    - 需监控告警
    - 性能/稳定性优化
    - 持续自动化改进

### 一句话总结
- **模型负责“想什么”，Harness 负责“怎么做、做得对、可控、可恢复”。**
- 没有 Harness 的 Agent = 盲走；有 Harness 的 Agent = 有仪表盘、刹车和安全气囊的自动驾驶。
