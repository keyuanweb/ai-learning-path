# 生产级 Agent 上线检查表

**上线前逐项确认，降低事故风险，保证可控、可观测、可回滚**

## 📋 检查项列表

| # | 检查项 | 检查要点（达标标准） | □ |
| :--- | :--- | :--- | :--- |
| 1 | **任务边界与目标** | • 明确支持的任务范围和不支持范围• 输入/输出格式、成功标准、是否需留痕 | □ |
| 2 | **上下文来源与质量** | • 上下文来源清晰、可追溯、实时刷新• 语言、切分粒度、命中率与相关性可接受 | □ |
| 3 | **工具权限最小化** | • 工具清单明确，仅暴露必要调用• 敏感操作需二次确认或进入人工审核 | □ |
| 4 | **MCP 工具接入校验** | • MCP 服务稳定可用，超时与重试策略• 入参/出参校验、类型与 Schema 校验 | □ |
| 5 | **Sandbox 执行环境** | • 代码/命令在沙箱中执行，隔离资源• CPU/内存/磁盘/网络配额与耗时限制 | □ |
| 6 | **文件操作与回滚** | • 读写路径受限，禁止越权访问• 关键文件操作前自动快照/备份 | □ |
| 7 | **Human Review 人工审核** | • 高风险操作需人工确认并留痕• 明确需要人工介入的决策清单 | □ |
| 8 | **失败重试与回退** | • 重试条件、次数、退避策略明确• 部分失败可重试，幂等性已保障 | □ |
| 9 | **回滚与补救策略** | • 明确回滚触发条件与操作步骤• 业务影响最小化，数据可恢复 | □ |
| 10 | **日志与观测可追溯** | • 结构化日志，全链路可追踪 (Trace ID)• 关键指标：成功率/延迟/错误率/成本 | □ |
| 11 | **安全与合规** | • 敏感数据脱敏与最小暴露• 权限审计、访问控制、操作留痕 | □ |
| 12 | **评测与样例质量门禁** | • 覆盖核心场景与边界用例的评测集• 评测通过才放行，回归自动化 | □ |
| 13 | **上线频率与灰度** | • 灰度比例、放量策略与观察周期明确 | □ |
| 14 | **成本与配额预算控制** | • 模型/工具/存储成本可控• 配额、限流、异常熔断已配置 | □ |
| 15 | **文档与交接信息备案** | • 用户文档、运维手册、应急预案齐全• 配置项、联系人、升级路径明确 | □ |

> **注：** 🔴 必须项（不达标不得上线）

## 🚀 上线流程（建议流程）

1.  **本地自测**：开发自测，覆盖核心场景与边界用例
2.  **预发布验证**：在预发布环境验证集成、权限、观测、回滚能力
3.  **评审与验收**：产品/安全/运维联合评审通过上线检查清单
4.  **灰度发布**：小流量灰度，密切观察指标与告警
5.  **全量发布**：确认稳定后逐步放量持续观测与优化

## ⚠️ 风险分级与示例

-   **高风险（红）🔴**
    -   **后果**：导致数据泄露、资金损失、服务中断。
    -   **典型示例**：越权访问/敏感数据外泄/未审核执行/无回滚方案/故障扩散。
-   **中风险（橙）🟠**
    -   **后果**：可能导致体验降级、业绩下降、成本飙升。
    -   **典型示例**：逻辑注入/工具误用未做幂等/灰度失败/成本失控/监控不全。
-   **低风险（黄）🟡**
    -   **后果**：影响局部性能效率，暂不影响核心业务。
    -   **典型示例**：输出不稳定/日志不完整/提示不清晰。

## 💥 导致生产事故的 TOP 问题（务必警惕）

| 图标 | 核心问题 | 描述 |
| :--- | :--- | :--- |
| 🔓 | **权限过大** | 越权操作 |
| 📂 | **上下文污染** | 错误信息影响决策 |
| 🛠️ | **工具不稳定** | 超时重试不当 |
| 🧪 | **沙箱失效** | 代码/命令越界 |
| 👤 | **无人工审核** | 高风险直接执行 |
| 🔄 | **无回滚方案** | 问题无法补救 |
| 📉 | **无观测告警** | 故障发现太晚 |
| 💰 | **成本失控** | 超预算消耗 |

## 💡 一句话记住

**边界清晰 + 权限最小 + 可观测可回滚 + 人在回路 + 灰度先行，是 Agent 安全稳定上线的五大护栏。**
