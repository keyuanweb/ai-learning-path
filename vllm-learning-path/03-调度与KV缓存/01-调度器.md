## V1 统一调度的核心思想

V0 有显式的 prefill 阶段和 decode 阶段。V1 消除了这个区别。

每个 Request 有 `num_computed_tokens`（已计算）和 `num_tokens_with_spec`（总 token 数，含投机 token）。调度器的唯一任务是**让前者追上后者**。

这统一地处理了：
- **纯 prefill**：追差值为 1000（一次追完或分 chunk）
- **chunked prefill**：追差值为 800（本步追一部分，下步再追）
- **decode**：追差值为 1（每次生成一个）
- **speculative decoding**：追差值为 5（一次验证 5 个 draft token）

## 抢占（Preemption）

当 KV 缓存满时，调度器会**抢占**（preempt）一个低优先级的 running 请求：释放它的 KV 块，把它移回等待队列。下次被调度时，它需要重新计算被释放的 token。
