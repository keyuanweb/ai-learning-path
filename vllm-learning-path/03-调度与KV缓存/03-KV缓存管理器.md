# 03 · KV 缓存管理器

**源码**：[`code/vllm/vllm/v1/core/kv_cache_manager.py`](../../code/vllm/vllm/v1/core/kv_cache_manager.py)

## 职责

`KVCacheManager` 是对调度器暴露的 KV 缓存接口。它把底层 KV 块的分配/释放/查找封装为简洁的方法。

## 对调度器暴露的接口

| 方法 | 说明 |
|------|------|
| `allocate_slots(request, num_new_tokens)` | 给请求的 N 个新 token 分配 KV 块。返回 `KVCacheBlocks` 或 None（分配失败） |
| `get_computed_blocks(request)` | 检查 prefix cache 命中。命中时返回已存在的 `KVCacheBlocks` |
| `free(request)` | 释放请求的全部 KV 块 |
| `get_blocks(request)` | 获取请求当前的块列表 |
| `evict(request)` | 驱逐请求的 KV 块（抢占时使用） |

## Prefix Cache 的工作原理

1. 当请求 A 计算了一段 prompt，它的每个 KV 块产生一个哈希值
2. 哈希 → KV 块的映射存入 `BlockHashToBlockMap`
3. 请求 B 的 prompt prefix 如果和请求 A 相同，哈希匹配 → `get_computed_blocks()` 返回请求 A 的 KV 块
4. 请求 B 直接引用这些块，跳过这部分计算

这就是为什么 prefix cache 在「多请求共享相同系统提示」的场景下特别有效。

## 内部委托

`KVCacheManager` 实际委托给 `KVCacheCoordinator`（见下一章）处理细节。
