# 02 · 调度输出结构

**源码**：[`code/vllm/vllm/v1/core/sched/output.py`](../../code/vllm/vllm/v1/core/sched/output.py)

## `SchedulerOutput`

一个 dataclass，包含一步调度的完整结果。Executor 根据它构建 GPU 输入。

| 字段 | 说明 |
|------|------|
| `scheduled_new_reqs` | 全新请求的列表（`list[NewRequestData]`） |
| `scheduled_cached_reqs` | 已在运行的请求的增量（`CachedRequestData`） |
| `num_scheduled_tokens` | 本步每个请求各算几个 token |
| `scheduled_spec_decode_tokens` | 投机解码的 draft token IDs |
| `scheduled_encoder_inputs` | 多模态 encoder 输入的 token IDs |
| `num_common_prefix_blocks` | 公共前缀的 KV 块数（cascade attention 优化用） |
| `preempted_req_ids` | 本步被抢占的请求 |
| `finished_req_ids` | 本步完成的请求 |

## `NewRequestData` — 新请求的完整信息

```python
class NewRequestData:
    req_id: str
    prompt_token_ids: list[int]      # 全量 prompt
    mm_features: list[...]            # 多模态特征
    sampling_params: SamplingParams
    pooling_params: PoolingParams | None
    block_ids: list[int]              # 分配的 KV 块
    num_computed_tokens: int          # 已计算（可能是 prefix cache 命中）
    lora_request: LoRARequest | None
    ecc_type: EncoderCacheType | None
```

## `CachedRequestData` — 旧请求的增量

```python
class CachedRequestData:
    req_ids: list[str]
    resumed_req_ids: list[str]        # 被抢占比后恢复的请求
    new_token_ids: list[list[int]]    # 每请求新增的 token IDs（decode 时通常 1 个）
    new_block_ids: list[list[int]]    # 每请求新增的 KV 块
    num_computed_tokens: list[int]    # 每请求当前 computed 位置
    num_output_tokens: list[int]      # 每请求已生成的 token 数
```

## 阅读重点

- 理解「新请求」和「旧请求」（cached）的数据差异
- 新请求需要全量 prompt token ids，旧请求只需要增量 new_token_ids
- `block_ids` 和 `new_block_ids` 是 KV 缓存的逻辑块号，后面 worker 用它们寻址
