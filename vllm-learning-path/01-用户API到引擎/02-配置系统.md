# 02 · 配置系统：`EngineArgs` 与 `VllmConfig`

## EngineArgs

**源码**：[`code/vllm/vllm/engine/arg_utils.py`](../../code/vllm/vllm/engine/arg_utils.py)

约 2600 行的大 dataclass。**不要全读。** 只需知道：

- `EngineArgs` 聚合了所有可配置参数（模型路径、并行度、精度、KV 缓存、调度策略、量化、投机解码、结构化输出等）
- 关键方法 `create_engine_config()` 把离散参数组装成统一的 `VllmConfig` 对象
- 参数大致分这几组：

| 组 | 典型字段 |
|----|---------|
| 模型 | `model`, `tokenizer`, `dtype`, `max_model_len`, `quantization`, `hf_overrides` |
| 并行 | `tensor_parallel_size`, `pipeline_parallel_size`, `data_parallel_size`, `distributed_executor_backend` |
| 调度 | `max_num_batched_tokens`, `max_num_seqs`, `max_num_partial_prefills` |
| KV 缓存 | `block_size`, `gpu_memory_utilization`, `swap_space`, `enable_prefix_caching` |
| 编译 | `compilation_config` (O0/O1/O2), `cudagraph_mode` (NONE/PIECEWISE/FULL/FULL_AND_PIECEWISE) |
| 投机解码 | `speculative_model`, `num_speculative_tokens`, `speculative_draft_model_quantization` |
| 多模态 | `limit_mm_per_prompt`, `mm_processor_kwargs` |
| LoRA | `enable_lora`, `max_lora_rank`, `max_loras`, `lora_dtype` |
| 结构化输出 | `structured_outputs_config` |
| 可观测性 | `otlp_traces_endpoint`, `enable_otel`, `distributed_tracing` |

`EngineArgs` 还包含 CLI 入口函数：`add_cli_args(parser)` 把所有参数注册到 argparser，以及 `from_cli_args(args)` 从命令行还原对象。

## VllmConfig — Pydantic 配置聚合器

**源码**：[`code/vllm/vllm/config/vllm.py`](../../code/vllm/vllm/config/vllm.py)

vLLM 的配置系统已全面迁移到 **Pydantic** 模型，共 30+ 个独立配置文件，统一由 `VllmConfig` 聚合：

| 子配置 | 类 | 文件 | 管辖领域 |
|--------|----|------|---------|
| `model_config` | `ModelConfig` | `config/model.py` | 模型路径、dtype、max_model_len、HF override |
| `cache_config` | `CacheConfig` | `config/cache.py` | KV 缓存：block_size、gpu_memory_utilization、prefix caching |
| `parallel_config` | `ParallelConfig` | `config/parallel.py` | TP/PP/DP/CP/EP 大小、分布式后端 |
| `scheduler_config` | `SchedulerConfig` | `config/scheduler.py` | 调度策略、最大 batch token 数、max_seqs |
| `device_config` | `DeviceConfig` | `config/device.py` | 设备类型（cuda/rocm/tpu/cpu） |
| `compilation_config` | `CompilationConfig` | `config/compilation.py` | torch.compile 模式、CUDA Graph 模式、优化级别、Fusion Pass 开关(~1555行) |
| `lora_config` | `LoRAConfig` | `config/lora.py` | LoRA 适配器配置 |
| `speculative_config` | `SpeculativeConfig` | `config/speculative.py` | 投机解码方法和参数 |
| `observability_config` | `ObservabilityConfig` | `config/observability.py` | OTLP tracing、metrics |
| `structured_outputs_config` | `StructuredOutputsConfig` | `config/structured_outputs.py` | 结构化输出后端选择 |
| `multimodal_config` | `MultiModalConfig` | `config/multimodal.py` | 多模态输入限制和 processor 参数 |
| `quant_config` | `QuantizationConfig` | `model_executor/layers/quantization/base_config.py` | 量化方法选择和参数 |
| `attention_config` | `AttentionConfig` | `config/attention.py` | Attention backend 配置 |
| `kernel_config` | `KernelConfig` | `config/kernel.py` | Kernel 选择和参数 |
| `reasoning_config` | `ReasoningConfig` | `config/reasoning.py` | 推理 parser 配置 |
| `pooler_config` | `PoolerConfig` | `config/pooler.py` | Pooling/Embedding 配置 |

### Pydantic 优势

相比传统 dataclass，Pydantic 模型提供：

- **类型校验**：启动时检查所有参数合法性，避免运行时才发现配置错误
- **Hash-based 缓存失效**：编译缓存 key 由 config 的 hash 值构成，config 变化时自动重新编译
- **JSON Schema 导出**：便于生成配置文档和 API schema
- **嵌套验证**：`VllmConfig` 的 `@model_validator` 自动执行交叉字段校验（如 TP 大小 vs 模型兼容性）

### VllmConfig 交叉验证

```python
@model_validator(mode='after')
def verify_config(self) -> 'VllmConfig':
    # max_model_len 不能超过模型支持的上限
    # TP 大小必须能整除 num_attention_heads
    # PP 大小必须能整除 num_hidden_layers
    # DP>1 时 forward context 必须配置正确
    ...
```

### Hash-based 编译缓存

config 对象的 hash 构成编译缓存 key 的一部分：
```
cache_key = hash(model_code + model_config_hash + compilation_config_hash + ...)
```

任何配置变更（包括 `CompilationConfig` 中的 fusion pass 开关）都会自动触发重新编译。可通过 `VLLM_DISABLE_COMPILE_CACHE=1` 禁用缓存。

## 与 SamplingParams 的区别

这是新手最容易混淆的：

- **`EngineArgs`**：引擎级别，「模型怎么跑、用几块 GPU、KV 缓存多大」—— 创建引擎时设定，整个生命周期不变
- **`SamplingParams`**：请求级别，「这个 prompt 用多高的 temperature、生成多少 token」—— 每次 `generate()` 时指定，每个请求可以不同

## 阅读重点

- 扫一遍 `EngineArgs` 的字段分组（知道什么参数存在即可）
- 看 `create_engine_config()` 方法：理解离散参数如何变成结构化配置
- 看 `VllmConfig` 的字段列表：知道每个子配置管什么领域
- 理解 hash-based 编译缓存机制——这是调试「改了配置但没重新编译」问题的关键
- 子配置文件按需深入：做量化时看 `quantization.py`，调调度参数时看 `scheduler.py`，调试编译问题时看 `compilation.py`
