# 03 · 输入输出类型

## 输入类型

**源码**：[`code/vllm/vllm/inputs/`](../../code/vllm/vllm/inputs/)

看 `__init__.py` 了解导出清单。输入类型层级：

```
PromptType (联合类型)
├── SingletonPrompt
│   ├── str                    # 纯文本
│   ├── TextPrompt             # { prompt: str, multi_modal_data: dict }
│   ├── TokensPrompt           # { prompt_token_ids, multi_modal_data? }
│   └── EmbedsPrompt           # { embedding: torch.Tensor }
├── ExplicitEncoderDecoderPrompt  # encoder-decoder 模型专用
│   { encoder_prompt, decoder_prompt }
├── DataPrompt                 # 评分/embedding 模型
└── list[SingletonPrompt]      # 多个 prompt 组成列表
```

最常用的：
- `str` — 纯文本，「你好，请帮我写一首诗」
- `TextPrompt(text="描述这张图", multi_modal_data={"image": img})` — 多模态
- `TokensPrompt(prompt_token_ids=[1, 2, 3])` — 已经 tokenize 好的输入

### 内部类型（Engine 侧）

在 `LLMEngine.add_request()` 内部，用户输入被 `InputProcessor` 处理为：

```python
class EngineCoreRequest(msgspec.Struct):
    request_id: str
    client_index: int
    prompt_token_ids: list[int]     # prompt 的 token IDs
    mm_features: list[MultiModalFeatureSpec]  # 多模态特征
    sampling_params: SamplingParams | None
    pooling_params: PoolingParams | None
    arrival_time: float
    lora_request: LoRARequest | None
    priority: int
    trace_headers: dict | None
```

## 输出类型

**源码**：[`code/vllm/vllm/outputs.py`](../../code/vllm/vllm/outputs.py)

| 类 | 说明 |
|----|------|
| `RequestOutput` | 一次请求的完整结果：`request_id`, `prompt`, `outputs: list[CompletionOutput]`, `finished: bool`, `metrics` |
| `CompletionOutput` | 单个 completion：`index`, `text`, `token_ids`, `cumulative_logprob`, `finish_reason`, `stop_reason` |
| `PoolingRequestOutput` | pooling/embedding 请求结果：含 `embeddings`, `finished` |
| `EmbeddingRequestOutput` | embedding 结果包装 |
| `ScoringRequestOutput` | 评分结果 |
| `ClassificationRequestOutput` | 分类结果 |

注意：`RequestOutput.outputs` 是 `list[CompletionOutput]`（因为 `n > 1` 时一个 prompt 可能生成多个 completion）。在流式模式下，`RequestOutput` 是增量更新的——`prompt_token_ids` 逐步增加，`outputs[i].token_ids` 逐 token 增长。

## 采样参数

**源码**：[`code/vllm/vllm/sampling_params.py`](../../code/vllm/vllm/sampling_params.py)

`SamplingParams` 是每次 `generate()` 调用时传入的请求级参数。关键字段：

| 参数 | 类型 | 说明 |
|------|------|------|
| `temperature` | `float` | 温度（0 = 贪婪解码） |
| `top_k` | `int` | top-k 采样 |
| `top_p` | `float` | top-p (nucleus) 采样 |
| `max_tokens` | `int` | 最大生成 token 数 |
| `stop` | `str \| list[str]` | 停用字符串 |
| `stop_token_ids` | `list[int]` | 停用 token IDs |
| `n` | `int` | 每个 prompt 生成几个 completion |
| `logprobs` | `int \| None` | 返回的 top logprobs 数量 |
| `min_p` | `float` | min-p 采样 |
| `frequency_penalty` | `float` | 频率惩罚（惩罚已在输出中出现过的 token） |
| `repetition_penalty` | `float` | 重复惩罚（惩罚连续出现的 token） |
| `presence_penalty` | `float` | 出现惩罚（惩罚任何已出现的 token） |
| `seed` | `int \| None` | 随机种子 |
| `bad_words` | `list[str]` | 禁止生成的词列表 |
| `include_stop_str_in_output` | `bool` | 输出中是否包含 stop string |
| `structured_outputs` | `StructuredOutputsParams \| None` | 结构化输出约束（JSON schema / regex / grammar） |
| `repetition_detection` | `RepetitionDetectionParams \| None` | 重复检测参数（触发时自动停止） |
| `skip_special_tokens` | `bool` | 是否跳过特殊 token |

`SamplingParams` 还包含 `clone()` 方法（用于 `n > 1` 时给每个 completion 独立副本）和 `update_from_generation_config()` 方法（从 HF 的 GenerationConfig 覆盖未设定的参数）。

## 阅读重点

- 知道输入类型的层级关系
- 记得 `RequestOutput.outputs` 是 `list[CompletionOutput]`（因为 n>1 时会生成多个）
- 理解 `EngineArgs` vs `SamplingParams` 的分工
- 流式模式中 `RequestOutput` 是增量更新的
