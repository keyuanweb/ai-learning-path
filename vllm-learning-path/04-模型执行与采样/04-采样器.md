## `Sampler(nn.Module)` — 采样流程

```python
class Sampler(nn.Module):
    def forward(self, logits, sampling_params, ...):
        # 步骤 1：计算 logprobs（如果 sampling_params 要求）
        logprobs = compute_logprobs(logits)

        # 步骤 2：应用 bad words exclusion
        # 将 bad_words 对应的 token ID 的 logit 置为 -inf
        logits = apply_bad_words(logits, bad_words)

        # 步骤 3：应用 logit processors
        logits = apply_min_p(logits, min_p)
        logits = apply_logit_bias(logits, logit_bias)

        # 步骤 4：应用 penalties
        # 基于请求已生成的 token_ids 来惩罚重复
        logits = apply_repetition_penalty(logits, output_token_ids, penalty)
        logits = apply_frequency_penalty(logits, output_token_ids, penalty)
        logits = apply_presence_penalty(logits, output_token_ids, penalty)

        # 步骤 5：采样（两种分支）
        if temperature == 0:
            # 贪婪解码：直接 argmax
            token_ids = greedy_sample(logits)
        else:
            # 随机采样：先缩放，再 top-k/top-p 过滤，最后随机抽取
            logits = logits / temperature
            token_ids = top_k_top_p_sample(logits, top_k, top_p)

        # 步骤 6：应用结构化的输出过滤（如果有 grammar bitmask）
        # 被 grammar 禁止的 token 已经在前面的步骤中被置为 -inf

        # 步骤 7：返回
        return SamplerOutput(sampled_token_ids, logprobs_tensors)
```

## 辅助采样内核

都在 [`code/vllm/vllm/v1/sample/ops/`](../../code/vllm/vllm/v1/sample/ops/) 下：

| 文件 | 说明 |
|------|------|
| `topk_topp_sampler.py` | top-k + top-p 采样内核 — 先按 logits 排序取 top-k，再 cumulative probability 截断 top-p |
| `penalties.py` | repetition/frequency/presence penalties — 基于已生成 token 的出现次数惩罚 logits |
| `logprobs.py` | logprob 计算 — softmax + log，返回 top-k 个 logprob |
| `bad_words.py` | 禁用词排除 — 将 bad_words 对应的所有 token ID 序列的 logit 置为 -inf |

## 可插拔 LogitsProcessor

在 [`code/vllm/vllm/v1/sample/logits_processor/`](../../code/vllm/vllm/v1/sample/logits_processor/) 下：

| 处理器 | 文件 | 说明 |
|--------|------|------|
| `min_p` | `builtin.py` | 低于 `max_prob * min_p` 的 token 概率置零（有效隔离尾部噪声） |
| `logit_bias` | `builtin.py` | 给特定 token ID 加减分数（用于引导模型倾向某些词） |

接口定义在 `interface.py` 中的 `LogitsProcessor` ABC。自定义处理器只需实现 `apply(logits: torch.Tensor) -> torch.Tensor`。

## 贪婪 vs 随机采样的实现差异

| 方面 | Greedy (temperature=0) | Stochastic (temperature>0) |
|------|------------------------|---------------------------|
| 实现 | `torch.argmax(logits, dim=-1)` | 先 `/temperature`，再 `top_k + top_p` 过滤，最后从剩余 token 中按概率采样 |
| 确定性 | 确定（相同输入 → 相同输出） | 随机（受 seed 控制） |
| 性能 | 极快（单次 argmax） | 稍慢（需要排序 + cumulative sum） |
| 使用 | 离线任务、必须确定性的场景 | 创意生成、对话 |

## 阅读重点

- 采样流程的 7 个步骤（logprobs → bad_words → processors → penalties → greedy/stochastic → grammar → output）
- 区分 greedy（temperature=0，直接 argmax）和 stochastic（temperature>0，top-k/top-p）
- LogitsProcessor 是可插拔的——了解接口即可
- Penalties 需要访问「已生成的 token」——所以采样器持有请求的 output_token_ids
