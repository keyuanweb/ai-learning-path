# 05 · 后端引擎：`EngineCore`（核心！）

**源码**：[`code/vllm/vllm/v1/engine/core.py`](../../code/vllm/vllm/v1/engine/core.py)

## 这是整个 vLLM 的心脏

约 600 行。`EngineCore` 拥有调度器和执行器，运行推理的紧循环。

## `__init__()` — 初始化做了什么

1. **创建 Executor**：加载模型到 GPU
2. **GPU 内存 Profiling**：调 `executor.determine_available_memory()` 计算可用显存 → 确定 KV 缓存能分几个 block → 调 `executor.initialize_from_config()` 分配 KV 缓存
3. **创建 Scheduler**：调度器决定每步算什么
4. **设置结构化输出管理器**：如果有 JSON schema / regex 约束
5. **冻结 Python GC**：减少 GC 暂停对延迟的影响

## `step()` — 推理紧循环（五个步骤！）

```python
def step(self):
    # 步骤 1：调度
    scheduler_output = self.scheduler.schedule()
    # → SchedulerOutput：本步要算哪些请求、各算几个 token

    # 步骤 2：执行模型前向
    model_output = self.executor.execute_model(scheduler_output)
    # → ModelRunnerOutput：前向结果（可能含采样结果）

    # 步骤 3：获取语法约束（结构化输出）
    grammar_output = self.scheduler.get_grammar_bitmask(scheduler_output)

    # 步骤 4：采样（如果步骤 2 没做采样）
    if model_output is None:
        model_output = self.executor.sample_tokens(grammar_output)

    # 步骤 5：更新请求状态
    outputs = self.scheduler.update_from_output(scheduler_output, model_output)
    # → dict[int, EngineCoreOutputs]：本步的 token 级别输出

    return outputs
```

## `step_with_batch_queue()` — 流水线版本

当启用 Pipeline Parallelism（PP>1）时，使用这个版本。原理是同时维护多个 in-flight batch，让调度（CPU 工作）和执行（GPU 工作）重叠。

## `EngineCoreProc` — 多进程版

同文件中的 `EngineCoreProc` 把 `EngineCore` 包装在独立进程中，通过 ZMQ socket 与前端通信。它的主循环是 `run_busy_loop()`：不断从前端收请求、执行 `step()`、向后端发输出。
