# 03 · 前端引擎：`LLMEngine`

**源码**：[`code/vllm/vllm/v1/engine/llm_engine.py`](../../code/vllm/vllm/v1/engine/llm_engine.py)

## 职责

`LLMEngine` 是引擎的**前端**。它不管调度，不管 GPU 计算。它只做三件事：
1. 把用户输入转成内部格式（通过 `InputProcessor`）
2. 把内部输出转回用户可读的格式（通过 `OutputProcessor`）
3. 驱动前后端之间的数据流通

## 三个核心成员

| 成员 | 类型 | 职责 |
|------|------|------|
| `self.input_processor` | `InputProcessor` | tokenize / 规范化 / 多模态特征提取 |
| `self.output_processor` | `OutputProcessor` | detokenize / logprobs 处理 / stop 检查 |
| `self.engine_core` | `EngineCoreClient` | 与后端通信的 IPC 句柄 |

## 核心方法

### `add_request(request_id, prompt, sampling_params)`

1. 调 `InputProcessor.process_inputs()` → 得到 `EngineCoreRequest`
2. `OutputProcessor.add_request()` 创建对应的输出跟踪
3. `EngineCoreClient.add_request()` 发给后端

### `step()` — 主循环方法

```python
def step(self):
    # 1. 从后端拿 outputs
    outputs = self.engine_core.get_output()
    # 2. 转换成用户可读的 RequestOutput
    processed = self.output_processor.process_outputs(outputs)
    # 3. 中止已完成的请求
    # 4. 返回
    return list(processed.values())
```

注意 `step()` 不是引擎的紧循环——它只是从前端视角的一次推进。真正的紧循环在 `EngineCore.step()`。

## `from_engine_args()` 工厂方法

```python
@classmethod
def from_engine_args(cls, engine_args: EngineArgs):
    vllm_config = engine_args.create_engine_config()
    return cls(vllm_config)
```

## 阅读重点

- 理解 `LLMEngine` 是「前端」，不包含调度逻辑
- `add_request()` 的输入处理链
- `step()` 只是一个取结果的动作，不是计算循环
