# 06 · InputProcessor / OutputProcessor / 序列化

## InputProcessor

**源码**：[`code/vllm/vllm/v1/engine/input_processor.py`](../../code/vllm/vllm/v1/engine/input_processor.py)

把用户 prompt 转成 `EngineCoreRequest`。核心流程：

1. **输入规范化**：把 `str | TextPrompt | TokensPrompt | EmbedsPrompt` 统一为内部表单
2. **Tokenization**：如果用户传的是文本，调用 tokenizer 转成 token IDs
3. **多模态特征提取**：对多模态请求，调用 `MultiModalRegistry` 找到对应的 encoder（如 CLIP），编码图像/音频为 embedding；记录 mm_features（占位信息）
4. **验证**：检查 prompt 长度是否超过 `max_model_len`，检查多模态限制
5. **构建 EngineCoreRequest**：填充所有字段，准备发送给后端

## OutputProcessor

**源码**：[`code/vllm/vllm/v1/engine/output_processor.py`](../../code/vllm/vllm/v1/engine/output_processor.py)

把 `EngineCoreOutput` 转回 `RequestOutput`。核心流程：

1. **维护输出状态**：每个活跃请求维护一个 `RequestState` 对象，追踪 token_ids、text、logprobs 的累积状态
2. **增量 Detokenization**：每次收到新 token IDs，调用 detokenizer 增量解码为文本（不每次重新解码全序列）
3. **Logprobs 处理**：管理每个请求的 logprobs 累积和 top-k 记录
4. **Stop 检查**：检查 stop strings、stop token IDs（在 detokenized 文本上检查）
5. **构建 RequestOutput**：为每个请求创建 `RequestOutput` 对象（含增量的 `CompletionOutput`）

## 序列化：MsgpackEncoder / MsgpackDecoder

**源码**：[`code/vllm/vllm/v1/serial_utils.py`](../../code/vllm/vllm/v1/serial_utils.py)

前后端跨进程通信时使用的自定义序列化层。核心设计：

- **基于 msgpack**：比 pickle 快 3-10x，且不会执行任意代码（安全）
- **自定义扩展类型**：注册了 `torch.Tensor`、`msgspec.Struct`、`enum` 等自定义编码器
- **Tensor 零拷贝**：大 tensor（> 某个阈值）通过共享内存（`multiprocessing.shared_memory`）传递，序列化消息中只包含共享内存的索引和元数据（shape/dtype/offset）。小 tensor 直接内联到 msgpack 消息中
- **前向兼容**：字段添加/删除不会破坏反序列化（msgspec 原生支持）

序列化流程：
```
发送方: Python对象 → MsgpackEncoder.encode() → (msgpack bytes, shared_memory_blocks)
接收方: (msgpack bytes, shared_memory_blocks) → MsgpackDecoder.decode() → Python对象
```

## AsyncLLM

**源码**：[`code/vllm/vllm/v1/engine/async_llm.py`](../../code/vllm/vllm/v1/engine/async_llm.py)

异步引擎门面，用于 OpenAI 兼容服务。提供：
- `generate()` → async generator，逐 token yield `RequestOutput`
- `encode()` → async generator，用于 embedding
- `start_profile()` / `stop_profile()` → 异步 profiling

内部持有 `InputProcessor`、`OutputProcessor` 和异步 MP 客户端（`self.engine_core`）。在线服务通过 `AsyncLLM` 访问 vLLM，离线推理直接通过 `LLM` 类访问。

## 阅读重点

- `InputProcessor` 和 `OutputProcessor` 作为数据转换层理解即可，第一遍不需要深读实现
- 知道序列化使用 msgpack + 共享内存零拷贝——这是多进程 IPC 的性能关键
- `AsyncLLM` 是给 API 服务器用的，离线推理不需要
