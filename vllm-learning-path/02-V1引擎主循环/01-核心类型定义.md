# 01 · 核心类型定义

**源码**：[`code/vllm/vllm/v1/engine/__init__.py`](../../code/vllm/vllm/v1/engine/__init__.py)

## 为什么先读这些类型

这个文件定义了前后端之间传递的所有核心数据结构。理解了这些类型，后面读 `LLMEngine` 和 `EngineCore` 时就不会疑惑「这个对象里有什么字段」。

## 关键类型

### EngineCoreRequest — 内部请求

```python
class EngineCoreRequest(msgspec.Struct):
    request_id: str
    client_index: int           # 客户端索引（DP 场景）
    prompt_token_ids: list[int]  # prompt 的 token IDs
    mm_features: list[MultiModalFeatureSpec]  # 多模态特征
    sampling_params: SamplingParams | None
    pooling_params: PoolingParams | None
    arrival_time: float
    lora_request: LoRARequest | None
    priority: int               # 优先级
    trace_headers: dict | None
```

### EngineCoreOutput — 单步输出

```python
class EngineCoreOutput(msgspec.Struct):
    request_id: str
    new_token_ids: list[int]     # 本步新生成的 token IDs
    new_logprobs: LogprobsTensors | None
    finish_reason: FinishReason | None
    stop_reason: int | str | None
    num_cached_tokens: int       # prefix cache 命中的 token 数
```

### FinishReason — 结束原因

| 值 | 含义 |
|----|------|
| STOP = 0 | 正常结束（遇到 EOS） |
| LENGTH = 1 | 达到 max_tokens 限制 |
| ABORT = 2 | 用户主动取消 |
| ERROR = 3 | 出错 |
| REPETITION = 4 | 重复检测触发 |

### EngineCoreEventType — 事件类型

| 值 | 含义 |
|----|------|
| QUEUED = 1 | 请求已入队 |
| SCHEDULED = 2 | 请求已被调度 |
| PREEMPTED = 3 | 请求被抢占（KV 缓存不足时） |

## msgspec.Struct 是什么

比 dataclass 更轻量的序列化结构。支持 msgpack 序列化，用于前后端进程间通信。比 pickle 快且安全。

## 阅读重点

- 记住 `EngineCoreRequest` 和 `EngineCoreOutput` 的字段
- 理解 `FinishReason` 的几种情况
- 知道 `PREEMPTED` 事件的存在（后面读调度器时会用到）
