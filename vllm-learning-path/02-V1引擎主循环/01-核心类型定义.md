# 01 · 核心类型定义

**源码**：[`code/vllm/vllm/v1/engine/__init__.py`](../../code/vllm/vllm/v1/engine/__init__.py)

## 为什么先读这些类型

这个文件定义了前后端之间传递的所有核心数据结构。理解了这些类型，后面读 `LLMEngine` 和 `EngineCore` 时就不会疑惑「这个对象里有什么字段」。

## 关键类型

### EngineCoreRequest — 内部请求

```python
class EngineCoreRequest(msgspec.Struct):
    request_id: str
    client_index: int               # 客户端索引（DP 场景下标识来自哪个前端）
    prompt_token_ids: list[int]     # prompt 的 token IDs
    mm_features: list[MultiModalFeatureSpec]  # 多模态特征（图像/音频的 embedding 占位信息）
    sampling_params: SamplingParams | None   # 采样参数（generation 请求）
    pooling_params: PoolingParams | None     # pooling 参数（embedding 请求）
    arrival_time: float
    lora_request: LoRARequest | None
    priority: int                   # 优先级（0=最高，值越小越高）
    trace_headers: dict | None      # 可观测性 trace 头
```

### EngineCoreOutput — 单步输出

```python
class EngineCoreOutput(msgspec.Struct):
    request_id: str
    new_token_ids: list[int]        # 本步新生成的 token IDs（decode 阶段通常是 1 个）
    new_logprobs: LogprobsTensors | None  # 新增 token 的 logprobs
    finish_reason: FinishReason | None    # 请求是否结束
    stop_reason: int | str | None         # 触发了哪个 stop 条件
    num_cached_tokens: int                # prefix cache 命中的 token 数
```

### EngineCoreOutputs — 一步的完整输出集合

```python
class EngineCoreOutputs(msgspec.Struct):
    outputs: dict[str, EngineCoreOutput]  # request_id → 输出
    scheduler_stats: SchedulerStats       # 调度统计信息
    timestamp: float
```

### FinishReason — 结束原因

| 值 | 含义 |
|----|------|
| `STOP = 0` | 正常结束（遇到 EOS token） |
| `LENGTH = 1` | 达到 `max_tokens` 限制 |
| `ABORT = 2` | 用户主动取消 |
| `ERROR = 3` | 出错 |
| `REPETITION = 4` | 重复检测触发 |

### EngineCoreEventType — 事件类型

| 值 | 含义 |
|----|------|
| `QUEUED = 1` | 请求已入队 |
| `SCHEDULED = 2` | 请求已被调度 |
| `PREEMPTED = 3` | 请求被抢占（KV 缓存不足时） |

## msgspec.Struct — 为什么用它而不用 dataclass

1. **零开销序列化**：基于 msgpack，比 pickle 快 3-10 倍
2. **安全**：不会执行任意代码（pickle 的核心风险）
3. **零拷贝 tensor 传递**：大 tensor 通过共享内存索引传递，不经过序列化
4. **类型安全**：编译时检查字段类型
5. **前向兼容**：支持字段默认值，新增字段不破坏旧代码
