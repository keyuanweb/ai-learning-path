# 02 · 废弃目录：`vllm/engine/`

**源码**：[`code/vllm/vllm/engine/`](../../code/vllm/vllm/engine/)

## 重要发现

打开 `vllm/engine/llm_engine.py`，你会发现里面只有一行 re-export：

```python
from vllm.v1.engine.llm_engine import LLMEngine
```

`vllm/engine/async_llm_engine.py` 同理：

```python
from vllm.v1.engine.async_llm import AsyncLLM as AsyncLLMEngine
```

**全部真实逻辑在 `vllm/v1/` 下。** `vllm/engine/` 仅保留 `arg_utils.py`（EngineArgs 定义，约 2600 行）有实质内容。

## 为什么保留 shim

1. **向后兼容**：已有代码 `from vllm.engine.llm_engine import LLMEngine` 仍然有效
2. **公开 API 不变**：`__init__.py` 的 `MODULE_ATTRS` 仍指向 `vllm.engine.llm_engine`
3. **渐进迁移**：`arg_utils.py` 尚未完成 V1 标准化

## 这意味着什么

- 所有源码阅读从 `vllm/v1/` 开始
- 看到 `from vllm.engine import ...` 直接跳转到 `vllm/v1/` 对应文件
- 唯一例外：`EngineArgs` 的定义仍在 `vllm/engine/arg_utils.py`

## 阅读时间

5 分钟。理解「vllm/engine/ 是空壳」即可。
