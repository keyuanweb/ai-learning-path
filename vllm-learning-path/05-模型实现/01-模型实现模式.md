# 01 · 模型实现模式（以 Llama 为例）

**源码**：[`code/vllm/vllm/model_executor/models/llama.py`](../../code/vllm/vllm/model_executor/models/llama.py)

## vLLM 中每个模型都是五层嵌套结构

```
LlamaForCausalLM        ← 顶层（对外暴露的模型类）
  │  继承: nn.Module, SupportsLoRA, SupportsPP, SupportsEagle, SupportsEagle3
  └─ LlamaModel         ← Transformer 堆叠
       │  继承: nn.Module, EagleModelMixin
       └─ LlamaDecoderLayer  ← 单层 Transformer
            ├─ LlamaAttention   ← 注意力
            │    qkv_proj (QKVParallelLinear)
            │    o_proj (RowParallelLinear)
            │    rotary_emb (RoPE)
            │    attn (Attention / EncoderOnlyAttention)
            └─ LlamaMLP         ← 前馈网络
                 gate_up_proj (MergedColumnParallelLinear)
                 down_proj (RowParallelLinear)
                 act_fn (SiluAndMul)
```

## 标准化的 forward 签名

所有 200+ 模型必须使用同一个 `forward` 签名：

```python
def forward(self, input_ids, positions,
            intermediate_tensors=None, inputs_embeds=None):
```

| 参数 | 说明 |
|------|------|
| `input_ids` | `[batch, seq_len]` — 本步要计算的 token IDs |
| `positions` | `[batch, seq_len]` — 每个 token 在序列中的位置（用于 RoPE 等位置编码） |
| `intermediate_tensors` | PP 模式下前一个 rank 传来的中间结果 |
| `inputs_embeds` | 多模态场景下的预计算 embedding（替代 input_ids） |

**为什么所有模型必须统一签名？** 因为 `GPUModelRunner` 不关心你是什么模型——它只调 `self.model(input_ids=..., positions=..., ...)`。统一签名让 engine 和 model 完全解耦。

## 顶层模型必须实现的接口

```python
class LlamaForCausalLM(nn.Module, SupportsLoRA, SupportsPP, ...):
    # 1. 融合参数的映射
    packed_modules_mapping = {
        "qkv_proj": ["q_proj", "k_proj", "v_proj"],     # QKV 三合一
        "gate_up_proj": ["gate_proj", "up_proj"],       # gate+up 二合一
    }

    def forward(self, input_ids, positions, ...): ...
    def compute_logits(self, hidden_states): ...  # hidden → logits
    def load_weights(self, weights): ...          # 自定义权重加载
    def make_empty_intermediate_tensors(batch_size, dtype, device): ...  # PP 用
```

## 关键设计点

1. **融合投影**：HF 模型中 `q_proj`、`k_proj`、`v_proj` 是三个独立 weight，vLLM 把它们物理合并成 `qkv_proj`，减少 kernel launch
2. **`load_weights()` 的 `stacked_params_mapping`**：告诉加载器「HF 的 `q_proj.weight` 应该填充到 `qkv_proj.weight` 的前 1/3 位置」
3. **`compute_logits()` 返回 None**：当 TP>1 且当前 rank 不是最后一个 TP rank 时，不需要计算完整的 logits
