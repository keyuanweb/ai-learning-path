# 03 · 关键层实现

## 并行感知的 Linear 层

**源码**：[`code/vllm/vllm/model_executor/layers/linear.py`](../../code/vllm/vllm/model_executor/layers/linear.py)

vLLM 的线性层不是普通的 `nn.Linear`，而是感知 Tensor Parallelism 的变体。这四种 Linear 是理解 vLLM 模型实现的关键。

### ColumnParallelLinear — 列并行

在 output 维度上分片。TP=4 时，每个 GPU 只计算 1/4 的输出通道。

```
输入: [batch, in_features] (每个 GPU 都有完整输入，通过 broadcast 获得)
权重: [in_features, out_features // 4] (每个 GPU 持有 1/4 列)
输出: [batch, out_features // 4] (每个 GPU 只有部分输出)
      → gather → [batch, out_features] (需要拼接才是完整输出)
```

使用场景：`qkv_proj`, `gate_up_proj`（列并行的典型应用）

### RowParallelLinear — 行并行

在 input 维度上分片。TP=4 时，每个 GPU 只接收 1/4 的输入通道。

```
输入: [batch, in_features // 4] (每个 GPU 拿 1/4 输入)
权重: [in_features // 4, out_features] (每个 GPU 持有 1/4 行)
输出: [batch, out_features] (all-reduce 后每个 GPU 都有完整输出)
```

使用场景：`o_proj`, `down_proj`（紧跟在 ColumnParallel 后的线性层）

### ColumnParallel + RowParallel 的高效组合

```
[ColumnParallelLinear]              [RowParallelLinear]
  输入: full input                   输入: 1/4 局部
  权重: 1/4 列                      权重: 1/4 行
  输出: 1/4 局部 (no gather!)  →   输出: all-reduce → 完整输出
```

相邻的 Column → Row 形成了高效的「分片-计算-规约」模式——不需要在中间做 all-gather，直接传入分片数据，最后才 all-reduce 结果。这节省了一次全对全通信。

### QKVParallelLinear — Q/K/V 三合一

```python
class QKVParallelLinear(ColumnParallelLinear):
    # 在 ColumnParallelLinear 基础上增加 head 感知的分片逻辑
    
    # 当 num_heads 不能被 TP 整除时，Q/K/V 各自独立分片
    # 例如：32 heads, TP=4, num_kv_heads=8
    #   Q: 32/4=8 heads per GPU
    #   K: 8/4=2 heads per GPU  
    #   V: 8/4=2 heads per GPU
```

HF 的 Q/K/V 是三个独立 weight → 三次 kernel launch。vLLM 的 QKVParallelLinear 合并为一个 weight → 一次 kernel launch。

### MergedColumnParallelLinear — gate/up 二合一

```python
class MergedColumnParallelLinear(ColumnParallelLinear):
    # SwiGLU MLP: gate_proj 和 up_proj 拼接在一起
    # HF: gate(x), up(x) → gate * up → down(gate*up)  两次 matmul
    # vLLM: merged(x) → split → gate * up → down(...)  一次 matmul
```

## 其他关键层

### VocabParallelEmbedding

**源码**：[`code/vllm/vllm/model_executor/layers/vocab_parallel_embedding.py`](../../code/vllm/vllm/model_executor/layers/vocab_parallel_embedding.py)

在 vocab 维度上分片的 embedding 层。TP=4 时：
- 每个 GPU 存 1/4 的 embedding 表（`[vocab_size//4, hidden_dim]`）
- 如果 input token ID 落在本 GPU 范围内 → 正常查表
- 如果不在 → 返回 0（后续 all-reduce 由持有该 token 的 GPU 补齐非零值）

## 阅读重点

- 理解 `ColumnParallelLinear` vs `RowParallelLinear` 的分片方向差异
- 理解融合投影的意义：减少 kernel launch 次数
- `VocabParallelEmbedding` 的分片方式——通过 all-reduce 补齐缺失 token
- Column → Row 的「不做中间 gather」优化——这是 TP 高效的秘诀
