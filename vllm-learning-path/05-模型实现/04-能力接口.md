# 04 · 模型能力接口（Capability Mixins）

**源码**：[`code/vllm/vllm/model_executor/models/interfaces.py`](../../code/vllm/vllm/model_executor/models/interfaces.py)

## 为什么用 Mixin 模式

vLLM 支持 200+ 种模型，它们有不同的能力（LoRA、投机解码、多模态、MoE 等）。使用 Mixin 模式（多继承）让每个模型声明自己支持什么能力，引擎代码通过 `isinstance()` 检查模型能力并采取对应行为。

## 能力接口全景

| Mixin | 能力 | 引擎侧行为 |
|-------|------|-----------|
| `SupportsLoRA` | LoRA 适配器 | 权重加载时插入 LoRA adapter；forward 时合并 LoRA weights |
| `SupportsPP` | Pipeline Parallelism | PP > 1 时调用 `make_empty_intermediate_tensors()` 创建缓冲区 |
| `SupportsEagle` | EAGLE 投机解码 | 插入 aux hidden states 层；用特定层的 hidden states 预测 draft token |
| `SupportsEagle3` | EAGLE3 投机解码 | 同 EAGLE，但预测方式不同（支持更复杂的 draft token 候选） |
| `SupportsMultiModal` | 多模态输入 | InputProcessor 调用对应的 encoder；`get_mm_mapping()` 返回多模态配置 |
| `MixtureOfExperts` | MoE 模型 | 支持 expert parallelism (EP)；EPLB 负载均衡（经 `set_eplb_state` 接口） |
| `HasInnerState` | 有内部状态 | Mamba/Jamba 的 SSM 状态；调度器避免抢占此类请求（状态无法重建） |
| `IsAttentionFree` | 无注意力机制 | 不使用 PagedAttention；KV cache 管理不同（如 Mamba 的 SSM 状态） |
| `IsHybrid` | 混合注意力 + Mamba | 部分层用 attention，部分层用 SSM；需要兼容两者的调度逻辑 |
| `SupportsMRoPE` | 多维 RoPE | Qwen2-VL 等需要 3D MRoPE；位置编码计算不同 |
| `SupportsTranscription` | 语音识别 | FireRedASR、Kimi-Audio 等；有特殊的分词器 + encoder-decoder 结构 |
| `SupportsEncoderCudaGraph` | Vision encoder CUDA graph | 多模态模型的 vision encoder 支持 CUDA graph |

## 基础协议

**源码**：[`code/vllm/vllm/model_executor/models/interfaces_base.py`](../../code/vllm/vllm/model_executor/models/interfaces_base.py)

```python
class VllmModel(Protocol):
    def embed_input_ids(self, input_ids: torch.Tensor) -> torch.Tensor: ...
    def forward(
        self, input_ids, positions,
        intermediate_tensors=None, inputs_embeds=None
    ) -> torch.Tensor | IntermediateTensors: ...

class VllmModelForTextGeneration(VllmModel, Protocol):
    def compute_logits(self, hidden_states: torch.Tensor) -> torch.Tensor | None: ...

class VllmModelForPooling(VllmModel, Protocol):
    pooler: nn.Module
    attn_type: str
    score_type: str | None
```

`VllmModel` 协议定义了两个必须实现的方法，所有模型都隐式满足这个协议。

## 引擎如何使用 Mixin 检查能力

```python
# 在模型加载时
if isinstance(model, SupportsLoRA):
    model = LoRAModel.wrap(model, lora_config)

# 在 PP 初始化时
if isinstance(model, SupportsPP):
    buffers = model.make_empty_intermediate_tensors(batch_size, dtype, device)

# 在调度时
if isinstance(model, HasInnerState):
    # 不抢占有内部状态的请求（SSM 状态无法重建）
    skip_preemption_for_this_request = True
```

这种设计让引擎代码不需要知道具体的模型类名，只通过 Mixin 接口就能判断能力。

## 实际使用示例

以 Llama 为例：

```python
class LlamaForCausalLM(nn.Module, SupportsLoRA, SupportsPP,
                        SupportsEagle, SupportsEagle3):
    # 继承了 4 个 Mixin：
    # SupportsLoRA → 自动获得 LoRA 加载/合并能力
    # SupportsPP → 自动获得 Pipeline Parallelism 支持
    # SupportsEagle/Eagle3 → 自动获得投机解码支持
    ...
```

以 Qwen2-VL 为例：

```python
class Qwen2VLForConditionalGeneration(nn.Module, SupportsMultiModal,
                                       SupportsPP, SupportsMRoPE):
    # SupportsMultiModal → 支持图像/视频输入
    # SupportsMRoPE → 3D RoPE 编码
    ...
```

## 阅读重点

- 了解这些接口的存在——添加新模型时回来查阅应该继承哪些 Mixin
- 理解 `isinstance()` 检查是引擎发现模型能力的主要方式
- `HasInnerState` 是最特殊的——直接影响调度器的抢占决策
