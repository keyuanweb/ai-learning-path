## `get_attn_backend()` — 如何选择后端

```python
def get_attn_backend(
    head_size, dtype, kv_cache_dtype,
    use_mla, has_sink, use_sparse,
    attn_type, ...
) -> type[AttentionBackend]:
```

遍历所有注册的后端（按优先级），对每个后端调用 `validate_configuration()`。第一个通过所有检查的胜出。

## 验证检查项

| 检查 | 说明 |
|------|------|
| head_size 支持 | MLA 后端通常只支持 head_size=576 等特定值 |
| dtype 支持 | 某些后端只支持 fp16/bf16 |
| KV cache dtype 支持 | FP8 KV 缓存只有部分后端支持 |
| block_size 兼容 | 某些后端对 block_size 有要求 |
| MLA vs 非 MLA | MLA 后端只用于 MLA 层 |
| sink token 支持 | 静态 sink token 只有部分后端支持 |
| attention type | DECODER / ENCODER / ENCODER_ONLY / ENCODER_DECODER |
| GPU compute capability | 某些后端需要 SM 80+ 等 |
| batch invariance | 某些后端需要 batch size 不变（CUDA graph 兼容） |

## 每层的后端在 `__init__` 时确定

```python
class Attention(nn.Module):
    def __init__(self, head_size, dtype, ...):
        self.attn_backend = get_attn_backend(
            head_size, dtype, kv_cache_dtype,
            use_mla=False, ...
        )
```

这意味着**同一个模型的不同层可以使用不同的 attention 后端**。比如 DeepSeek V3：
- 部分层使用 `FLASH_ATTN`
- 部分层使用 `FLASHINFER_MLA`
- 两种层的 KV 缓存结构完全不同

## GPU 特定选择

不同的 GPU 型号有不同的最优后端：
- NVIDIA H100/H800 → FlashInfer 或 FlashAttention-3
- NVIDIA A100/V100 → FlashAttention-2
- AMD MI300X → ROCm AITER FA

## 阅读重点

- 理解选择逻辑是「逐个验证，第一个通过即用」
- 理解「不同层可以用不同后端」的设计
- 不需要记每个后端的约束条件
