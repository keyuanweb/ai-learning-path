# 02 · Attention 后端选择

**源码**：[`code/vllm/vllm/v1/attention/selector.py`](../../code/vllm/vllm/v1/attention/selector.py)

## `get_attn_backend()` — 选择逻辑

```python
def get_attn_backend(
    head_size: int,
    dtype: torch.dtype,
    kv_cache_dtype: str,
    use_mla: bool,
    has_sink: bool,
    use_sparse: bool,
    attn_type: AttentionType,
    ...
) -> type[AttentionBackend]:
```

算法：**按优先级遍历所有注册的后端，逐个调用 `validate_configuration()`，第一个通过所有检查的胜出。**

## 验证检查项（10+ 项）

| 检查 | 说明 |
|------|------|
| **head_size 支持** | MLA 后端通常只支持 head_size=192/576 等特定值；标准后端不限 |
| **dtype 支持** | 某些后端只支持 fp16/bf16，不支持 fp32 |
| **KV cache dtype 支持** | FP8 KV 缓存只有 FlashInfer/FlashAttention-3 等部分后端支持 |
| **block_size 兼容** | 某些后端对 block_size 有整除要求（如必须被 16 整除） |
| **MLA vs 非 MLA** | `use_mla=True` 时跳过所有非 MLA 后端 |
| **sparse 支持** | `use_sparse=True` 时只匹配稀疏 MLA 后端 |
| **sink token 支持** | 静态 sink token 只有部分后端支持 |
| **attention type** | DECODER / ENCODER / ENCODER_ONLY / ENCODER_DECODER — 不是所有后端都支持所有类型 |
| **GPU compute capability** | FlashAttention-3 需要 SM 80+（H100/H800）；CK backend 需要 AMD |
| **batch invariance** | 某些后端需要 batch size 在录制和运行时一致（CUDA graph 兼容性） |
| **环境可用性** | 检查 CUDA kernel 是否编译成功 / Triton 库是否安装 / FlashInfer 版本是否兼容 |

## 每层的后端在 `__init__` 时确定

```python
class Attention(nn.Module):
    def __init__(self, head_size, dtype, kv_cache_dtype, use_mla=False, ...):
        # 在模型实例化时就选好了——不是运行时选择
        self.selected_backend = get_attn_backend(
            head_size, dtype, kv_cache_dtype,
            use_mla=use_mla, ...
        )
```

这意味着**同一个模型的不同层可以使用不同的 attention 后端**。

### 实例：DeepSeek V3 的混合后端

```
Layer 0-2:   FLASH_ATTN (标准 FullAttention)
Layer 3-60:  FLASHINFER_MLA (MLA attention)
```

两种层的 KV 缓存结构完全不同，因此被分配到不同的 `KVCacheGroup`，由不同的 `SingleTypeKVCacheManager` 管理。

## GPU 特定的后端选择

不同 GPU 的「最优后端」不同：

| GPU | 推荐后端 | 原因 |
|-----|---------|------|
| H100/H800 | FlashInfer 或 FlashAttention-3 | SM 90+, FP8 支持 |
| A100 | FlashAttention-2 | SM 80, 最成熟 |
| V100 | FlashAttention-2 | SM 70, 功能受限 |
| MI300X | ROCm AITER FA | AMD CDNA3 |
| CPU | CPU_ATTN | PyTorch SDPA 后端 |

## 后端优先级

`validate_configuration()` 的顺序就是优先级。通用后端（`FLASH_ATTN`）排在前，专用后端排在后：

```
FLASH_ATTN → FLASHINFER → TRITON_ATTN → FLEX_ATTENTION → ...
  (优先用最成熟的，回退到最通用的)
```

## 阅读重点

- 理解选择逻辑是「逐个验证，第一个通过即用」——不是「找最优」，是「找第一个能用的」
- 理解「同一模型不同层可以用不同后端」——这是支持 DeepSeek V3 等混合模型的基础
- 验证检查涵盖：数值参数（head_size, dtype）+ 硬件（compute capability）+ 环境（库是否安装）+ 约束（block_size 整除等）
