## 为什么需要多个 Attention 后端

不同的 GPU 硬件、不同的模型结构、不同的 KV 缓存格式和不同的 batch 规模，需要的 attention kernel 完全不同。vLLM 使用**可插拔后端**设计——每个模型层可以独立选择最适合自己的后端。

## 后端全景（约 25 个已注册）

### 标准 Attention 后端

| 后端枚举 | 适用场景 |
|----------|---------|
| `FLASH_ATTN` | NVIDIA GPU 默认（FlashAttention-2/3，Hopper 上用 FA3） |
| `FLASH_ATTN_DIFFKV` | 带差分 KV 的 FlashAttention（投机解码验证阶段用） |
| `FLASHINFER` | FlashInfer 高效 decode kernel（对 decode 极端优化） |
| `TRITON_ATTN` | Triton 实现的 PagedAttention（不需要编译 CUDA 扩展） |
| `FLEX_ATTENTION` | PyTorch 2.0 FlexAttention（纯 Python API，可自定义 attention pattern） |
| `TREE_ATTN` | 树形注意力（投机解码多路径验证） |
| `ROCM_ATTN` | AMD GPU ROCm（使用 CK/Composable Kernel） |
| `ROCM_AITER_FA` | AMD GPU AITER FlashAttention |
| `CPU_ATTN` | CPU 后端（torch.nn.functional.scaled_dot_product_attention） |
| `NO_ATTENTION` | 无需 attention 的模型（纯 Mamba/Jamba） |

### MLA（Multi-head Latent Attention）后端

MLA 是 DeepSeek V2/V3/V4 的低秩 KV 缓存格式，有独立的实现族：

| 后端枚举 | 说明 |
|----------|------|
| `FLASHINFER_MLA` | FlashInfer 的 MLA 实现（NVIDIA 推荐） |
| `TRITON_MLA` | Triton 实现 |
| `CUTLASS_MLA` | CUTLASS 实现 |
| `FLASHMLA` | FlashMLA（DeepSeek 开源的 MLA kernel） |
| `FLASH_ATTN_MLA` | FlashAttention 适配 MLA |
| `FLASHINFER_MLA_SPARSE` | 稀疏 MLA（仅 decode 使用，节省 KV 缓存带宽） |
| `FLASHMLA_SPARSE` | 稀疏 FlashMLA |
| `ROCM_AITER_MLA` | AMD GPU MLA |

### Mamba / SSM 后端

| 后端枚举 | 说明 |
|----------|------|
| `MAMBA1_ATTN` | Mamba-1（选择性 SSM） |
| `MAMBA2_ATTN` | Mamba-2（基于 SSD 的 SSM） |
| `SHORT_CONV_ATTN` | 短卷积注意力（Hybrid 模型的卷积层） |

### 其他后端

| 后端枚举 | 说明 |
|----------|------|
| `PALIGEMMA_ATTN` | Paligemma 模型的特殊 attention |
| `CASCADE_ATTN` | Cascade Attention（公共前缀优化） |
| `IPEX_ATTN` | Intel XPU attention |
| `TORCH_SDPA` | torch.nn.functional.scaled_dot_product_attention 通用后端 |

## 后端基类

```python
class AttentionBackend(ABC):
    # 静态信息
    @staticmethod
    def get_name() -> str: ...
    @staticmethod
    def get_impl_cls() -> type[AttentionImpl]: ...
    @staticmethod
    def get_builder_cls() -> type[AttentionMetadataBuilder]: ...

    # KV 缓存规格
    @staticmethod
    def get_kv_cache_shape(num_blocks, block_size, num_kv_heads, head_size) -> tuple: ...
    @staticmethod
    def get_kv_cache_stride_order(...) -> tuple[int, ...]: ...

    # 验证
    @staticmethod
    def validate_configuration(head_size, dtype, kv_cache_dtype, block_size,
                                compute_capability, ...) -> bool: ...

    # 能力标记
    @staticmethod
    def is_mla() -> bool: ...
    @staticmethod
    def is_sparse() -> bool: ...
    @staticmethod
    def supports_sink() -> bool: ...
    @staticmethod
    def cudagraph_support() -> CUDAGraphSupport: ...
```

## 阅读重点

- 知道 ~25 个后端分三大类：标准 attention / MLA / Mamba
- 理解标准后端 vs MLA 后端 vs Mamba 后端的适用场景差异
- 每个后端都需要实现四大组件：Backend + Impl + MetadataBuilder + KV cache 规格
- 不需要记住所有后端——用到了再查
