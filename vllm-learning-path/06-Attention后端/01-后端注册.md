# 01 · Attention 后端注册

**源码**：[`code/vllm/vllm/v1/attention/backends/registry.py`](../../code/vllm/vllm/v1/attention/backends/registry.py)

## 为什么需要多个 Attention 后端

不同的 GPU、不同的模型结构、不同的 KV 缓存格式，最合适的 attention kernel 不同。vLLM 使用**可插拔后端**设计，让每个模型层可以选择最优的后端。

## 已注册的后端

### 标准 Attention 后端

| 后端 | 适合场景 |
|------|---------|
| `FLASH_ATTN` | NVIDIA GPU 默认（FlashAttention-2/3） |
| `FLASH_ATTN_DIFFKV` | 带差分 KV 的 FlashAttention（投机解码用） |
| `FLASHINFER` | 高效的 decode 阶段 kernel |
| `TRITON_ATTN` | Triton 实现的 PagedAttention |
| `FLEX_ATTENTION` | PyTorch 2.0 FlexAttention |
| `TREE_ATTN` | 树形注意力（投机解码用） |
| `ROCM_ATTN` | AMD GPU（ROCm/CK） |
| `ROCM_AITER_FA` | AMD GPU AITER FlashAttention |
| `CPU_ATTN` | CPU 后端 |
| `NO_ATTENTION` | 无需 attention 的模型（如纯 Mamba） |

### MLA（Multi-head Latent Attention）后端

DeepSeek V2/V3/V4 使用的 MLA 有独立的实现：

| 后端 | 说明 |
|------|------|
| `FLASHINFER_MLA` | FlashInfer 的 MLA 实现 |
| `TRITON_MLA` | Triton 实现 |
| `CUTLASS_MLA` | CUTLASS 实现 |
| `FLASHMLA` | FlashMLA |
| `FLASH_ATTN_MLA` | FlashAttention MLA |
| `FLASHINFER_MLA_SPARSE` | 稀疏 MLA（仅 decode） |
| `FLASHMLA_SPARSE` | 稀疏 FlashMLA |
| `ROCM_AITER_MLA` | AMD GPU MLA |

### Mamba 后端

| 后端 | 说明 |
|------|------|
| `MAMBA1_ATTN` | Mamba-1 |
| `MAMBA2_ATTN` | Mamba-2 |
| `SHORT_CONV_ATTN` | 短卷积注意力 |

## 后端基类

```python
class AttentionBackend(ABC):
    # 静态方法
    get_name() -> str
    get_impl_cls() -> type[AttentionImpl]
    get_builder_cls() -> type[AttentionMetadataBuilder]
    get_kv_cache_shape(...) -> tuple[int, ...]
    get_kv_cache_stride_order(...) -> tuple[int, ...]

    # 验证
    validate_configuration(head_size, dtype, kv_cache_dtype, ...)

    # 能力标记
    is_mla() -> bool
    is_sparse() -> bool
    supports_sink() -> bool
    cudagraph_support() -> CUDAGraphSupport
```
