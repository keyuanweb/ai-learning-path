# 05 · 量化与 KV 缓存卸载

## 量化

**入口**：[`code/vllm/vllm/model_executor/layers/quantization/`](../../code/vllm/vllm/model_executor/layers/quantization/)

vLLM 支持多种模型权重量化方法，在保持推理质量的同时减少显存占用和内存带宽。

### 支持的量化方法

| 方法 | 比特数 | 特点 |
|------|--------|------|
| **GPTQ** | 4-bit | Group-wise 量化，成熟稳定，生态好 |
| **AWQ** | 4-bit | Activation-aware，保护重要通道，质量优于 GPTQ |
| **FP8** | 8-bit | H100/H800 原生支持（Transformer Engine），速度接近 fp16 |
| **Marlin** | 4-bit | 专为 GPU 优化的 int4 kernel，速度最快 |
| **BitsAndBytes** | 8/4-bit | HuggingFace 集成，使用方便但速度一般 |
| **Compressed-Tensors** | 混合 | 稀疏 + 量化混合，灵活度高 |
| **GGUF** | 多种 | llama.cpp 格式，CPU/GPU 混合推理 |
| **HQQ/MXFP4** | 4-bit | 新兴量化方案 |
| **TPU_INT8** | 8-bit | TPU 专用 |

### 集成方式

量化通过 `QuantizeMethodBase` 接口集成：

```python
class QuantizeMethodBase(ABC):
    def create_weights(self, layer, input_size_per_partition, ...) -> None: ...
    def apply(self, layer, x, bias=None) -> torch.Tensor: ...
    def process_weights_after_loading(self, layer) -> None: ...
```

每个 `ColumnParallelLinear` / `RowParallelLinear` 等层的构造过程中，量化方法被注入：

```python
# linear.py 中的 ColumnParallelLinear.__init__()
if self.quant_method is not None:
    self.quant_method.create_weights(self, ...)
# forward 时
output = self.quant_method.apply(self, input_)  # 可能走量化 kernel
```

## KV 缓存卸载 — 分层存储

**入口**：[`code/vllm/vllm/v1/kv_offload/`](../../code/vllm/vllm/v1/kv_offload/)

当 GPU 显存不够存全部 KV 缓存时，把不常用的 KV 块换出到更慢但更大的存储。vLLM 现已支持**分层存储**架构：

### 三层 Backend

| Backend | 目录 | 存储介质 | 延迟 | 容量 |
|---------|------|---------|------|------|
| **CPU** | `tiering/cpu/manager.py` | CPU 内存 | 低（PCIe） | 中等（~TB） |
| **P2P** | `tiering/p2p/manager.py` | 远程 GPU 显存（NVLink/RDMA） | 极低 | 中等 |
| **Filesystem** | `tiering/fs/manager.py` | 本地 SSD/NVMe | 高 | 极大 |

### 淘汰策略

| 策略 | 文件 | 原理 |
|------|------|------|
| **LRU** | `cpu/policies/` | Least Recently Used — 优先淘汰最久未访问的块，简单高效 |
| **ARC** | `cpu/policies/` | Adaptive Replacement Cache — 自适应平衡 recency 和 frequency，维护 LRU + LFU 两个队列 |

### 架构分层

```mermaid
flowchart TD
  kvMgr["KVCacheManager：需要腾出空间?"]
  offloadMgr["KvOffloadManager：选择淘汰策略"]
  policy["Policy: LRU or ARC → 选择淘汰块"]
  backend["Backend: CPU / P2P / Filesystem"]
  io["IO Layer: swap_blocks / file_mapper / thread_pool"]
  
  kvMgr --> offloadMgr --> policy --> backend --> io
  
  backend -->|"swap_out(block_ids)"| io
  backend -->|"on cache miss: swap_in(block_ids)"| io
```

### 卸载流程

```mermaid
flowchart LR
  subgraph gpuMem["GPU显存较小"]
    hot["Block0-3 热"]
    warm["Block4-5 温"]
    cold["Block6 冷"]
  end
  subgraph tiered["分层存储"]
    cpuMem["CPU内存 (PCIe)"]
    p2pMem["P2P远程显存 (NVLink)"]
    fsStorage["NVMe SSD"]
  end
  cold -->|"swap_out → 策略选择目标"| cpuMem
  cold -.->|"或"| p2pMem
  cold -.->|"或"| fsStorage
```

示意：冷块按策略换出到合适的存储层；policy 决定哪些块被淘汰；backend 决定换到哪层。当 Block6 再次被访问时从存储层 swap_in（延迟取决于 backend 类型）。

### File Mapper

**源码**：[`code/vllm/vllm/v1/kv_offload/file_mapper.py`](../../code/vllm/vllm/v1/kv_offload/file_mapper.py)

### EngineCore sleep/wake_up — 弹性调度

`EngineCore.sleep(level)` / `wake_up(tags)` 支持弹性 GPU 资源调度：

```python

        """休眠引擎，释放 GPU 资源"""
```

这支持了生产环境的弹性 GPU 调度：引擎可被休眠后恢复到其他 GPU，支持 spot/preemptible instance 的优雅处理。
