# 01 · 投机解码

## 核心原理

先让一个小/快的「draft 模型」预测 K 个 draft token，再用大模型一次性验证这 K 个 token。验证通过则接受（赚了 K-1 步），不通过则拒绝（至少不亏）。

vLLM 的投机解码集成在调度器和 Worker 中：`num_tokens_with_spec` 包含了 draft token，调度器一次分配 K+1 个 token 的 KV 块。

## 三种 Draft Proposer

**目录**：[`code/vllm/vllm/v1/spec_decode/`](../../code/vllm/vllm/v1/spec_decode/)

| 文件 | 方法 | 说明 |
|------|------|------|
| `eagle.py` | EAGLE/EAGLE3 | 用主模型最后一层的 hidden states 预测 draft token。需要额外训练 aux 层 |
| `medusa.py` | Medusa | 在模型上加多个预测头，独立预测 draft token |
| `ngram_proposer.py` | N-gram | 基于历史 n-gram 模式：如果最近出现了「机器」，下一个 token 很可能是「学习」 |

## Worker 侧

**目录**：[`code/vllm/vllm/v1/worker/gpu/spec_decode/`](../../code/vllm/vllm/v1/worker/gpu/spec_decode/)

## 与普通推理的关键差异

在调度器中，投机解码的请求 `num_tokens_with_spec` 可能比 `num_computed_tokens` 大很多（多出 K 个 draft token）。调度器为这 K 个额外的 token 分配 KV 块。验证通过后自由释放未使用的块。
